# アラート、通知、メール

アラートルール、ユーザーへの通知、チームチャンネル、メールプロバイダーの設定について説明します。

## アラートルール

**設定 → アラート**には、共有ルールがあります。各ルールは、1 つの条件を監視します。

- **カメラが報告していない**: カメラがヘルスレポートの送信を停止した。
- **ノードがオフライン**: ノードがチェックインを停止した。
- **ストレージ残量が低下**: 空き容量が、ある割合を下回った。
- **ノードのフェイルオーバー**: ノードのカメラがバックアップノードに移った。
- **モーションを検出**: カメラ、またはそのモーションゾーンの 1 つでのモーション。
- **オブジェクトを検出**: AI 検出が、一致するオブジェクトを検出した。
- **制限を超える速度**: オブジェクトが[速度測定](/Help/ai-detection#speed-traps)を、設定した速度以上で通過した。
- **証拠ロックの期限が近づいています**と**証拠ロックが解除されました**: [証拠ロック](/Help/live-and-playback#evidence-locks)をご覧ください。

ヘルスルールは 1 分に 1 回チェックされます。**クールダウン**は、アラートを繰り返す最短の間隔で、条件が真のままでも、毎分アラートが出ることはありません。

### 検出アラート

**オブジェクトを検出**と**制限を超える速度**は、検出から数秒以内に発動します。フィルターはすべて任意で、設定したものがすべて一致する必要があります。

- **カメラ**: 1 台のカメラ、1 つのノードのカメラ、またはすべてのカメラ。
- **カテゴリ**と**ラベル**: たとえば「車両」、または「トラック」のみ。
- **色**: オブジェクトの色、または人のシャツやズボンの色。[オブジェクトの色](/Help/ai-detection#object-colors)をご覧ください。
- **ゾーン**: カメラのゾーンの 1 つの中に立っているオブジェクトのみ（ボックスの下端で判定）。
- **有効**: 曜日と時間帯。ルールを保存した人のタイムゾーンで判定されます。22:00 から 06:00 のような時間帯は、夜間をまたいで実行されます。

1 つの検出につき、アラートは 1 回です。複数のカメラを監視するルールでは、クールダウンがカメラごとに別々にカウントされるため、忙しいカメラがほかのカメラを妨げることはありません。

### モーションアラート

**モーションを検出**は、サーバーのモーション検出、またはカメラ自身のモーションイベントによるモーションから数秒以内に発動します。1 台のカメラ、1 つのノードのカメラ、またはすべてのカメラを選択します。1 台のカメラを選択した場合、**ゾーン**で、そのカメラの**サーバーのモーション**ゾーンの 1 つに限定できます。どこでのモーションでも対象にする場合は、**（カメラ全体）** のままにします。**有効**な曜日と時間は、検出アラートと同じように機能します。ひと続きのモーションは 1 回アラートを出し、クールダウンが次のアラートを抑えます。

### チームチャンネル

各ルールは、メールリスト、Webhook、ntfy、Pushover、Slack、Teams にも送信できます。チャンネルをオンにして、その項目を入力します。

## 通知

通知は、チームチャンネルではなく、個人宛てに、ブラウザーまたはメールで届きます。各自が、サイドバーの**通知**（名前の横の 🔔 でも開けます）で、受け取りたいものを選びます。通知が届くのは、その人が表示できるカメラの分だけです。

- **共有通知**: アラートルールで**ユーザーによる購読を許可**にすると、**マイ通知 → 利用可能**に表示され、誰でもオンにできます。管理者は、ルールの**購読者**で、ユーザーやロール内の全員を追加することもできます。
- **自分用の通知**: **マイ通知 → 自分用 → 新しい通知**では、アラートルールと同じ選択肢で、自分だけの通知を作成できます。たとえば、午後 10 時から午前 6 時の間の、裏庭カメラの動物などです。表示されるのはあなただけです。
- 通知は、購読を解除せずに、1 時間、8 時間、1 日、または再びオンにするまで**ミュート**できます。

**設定 → 通知**では、通知の種類ごとに、ユーザーに対するオン/オフを切り替えます。種類をオフにしても、アラートルールのチームチャンネルは止まりません。

購読には**共有通知を購読**権限が、自分用の通知の作成には**個人用通知を作成**権限が必要です。既定では、すべてのロールが両方を持っています。

### ブラウザー通知

各ブラウザーで、**マイ通知 → このブラウザーとデバイス**からオンにし、**テストを送信**を使います。**設定 → 通知**で、配信方法を選択します。

| 配信 | 機能する条件 | 必要なもの |
|---|---|---|
| **LarisVMS を開いている間** | LarisVMS のタブ、またはインストール済みアプリが開いている | 不要。ネットワーク内にとどまります。 |
| **Web プッシュ** | LarisVMS のページが開いていない（Chrome、Edge、Firefox、Safari）。コンピューターでは、ブラウザー自体が実行中である必要があります（下記参照） | **Web プッシュキーを生成**（1 回）と、サーバーからブラウザーベンダーのプッシュサービスへのインターネットの外向きアクセス。アカウントは不要。 |
| **Firebase Cloud Messaging** | LarisVMS のページが開いていない（コンピューターでは同じ制限あり） | ご自身の Firebase プロジェクト（ウェブアプリの設定、ウェブプッシュ証明書、サービスアカウントキー）。Web プッシュがオフのときのみ使用されます。 |

通知を表示する許可がない場合は、代わりに、開いている LarisVMS ページ内に表示されます。スマートフォンでは、先に LarisVMS をアプリとしてインストールしてください（[概要](/Help/overview)をご覧ください）。

スマートフォンでは、ブラウザーが閉じていてもプッシュ通知が届きます。コンピューターでは、ブラウザーが実行されている間のみ受信し、最後のウィンドウを閉じると、通常は終了します。その間に送信されたものは、再び起動したときに表示されます。バックグラウンドで実行し続けるには、**Google Chrome の終了後もバックグラウンド アプリの処理を続行する**（Chrome: 設定 → システム）または **Microsoft Edge の終了後もバックグラウンドの拡張機能とアプリの実行を続行する**（Edge: 設定 → システムとパフォーマンス）をオンにしてください。ブラウザーを実行していなくてもアラートが必要な人には、メールを使用してください。

### メール通知

通知にメールを選択することもできます。メールは、アカウントのアドレスに、下で設定したメールを通じて届きます。**設定 → 通知**で、メール通知をオフにできます。

## メール

メールによるアラートと通知は、**設定 → メール**で設定したプロバイダーを通じて送信されます。**保存してテストを送信**で、保存した設定を確認します。

- **SMTP**: ホスト、ポート、SSL/TLS、認証情報。
- **Microsoft Graph**: Entra ID にアプリを登録し、管理者の同意とともに `Mail.Send` **アプリケーション**権限（委任ではなく）を付与して、そのテナント ID、クライアント ID、シークレットを入力します。ユーザーごとのサインインはありません。
- **Gmail**: Google Cloud で、種類が*ウェブアプリケーション*の OAuth クライアントを作成します。承認済みのリダイレクト URI として `https://<your-host>/Admin/OAuthCallback` を追加し、`https://mail.google.com/` スコープを有効にします。そのあと、**保存して Google に接続**を一度使用して、同意を付与します。

保存されたシークレットは暗号化されます。サーバーのデータ保護キーが失われた場合は、再入力し、Gmail を再接続してください。
