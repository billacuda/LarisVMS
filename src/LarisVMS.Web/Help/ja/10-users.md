# ユーザーとアクセス

アカウント、ロール、権限、カメラアクセス、Active Directory、Microsoft サインインについて説明します。

## ユーザー

自己登録はオフです。アカウントは**設定 → ユーザー**で作成し、そこでロールの割り当て、アカウントの無効化、パスワードのリセットも行えます。ローカルアカウントは、メールアドレスでサインインします。アカウントを無効にすると、すべての場所からただちにサインアウトされ、ライブ映像も閉じられます。

## パスワード

パスワードは 12 文字以上にする必要があります。一般的なもの、`123456789012` のようなもの、本人の名前やメールアドレスを含むものは拒否されます。さらに拒否するものがある場合は、ウェブサーバーの `%ProgramData%\LarisVMS\password-blocklist.txt` に 1 行に 1 つずつ入力してください（公開されている漏洩パスワードのリストも使用できます）。再起動なしで反映されます。

ローカルアカウントを持つ人は、ページ上部の名前を選択して、ご自身のパスワードを変更します。現在のパスワードが必要で、その人のほかのセッションはすべてサインアウトされます。管理者も、**設定 → ユーザー**ではなく、同じ方法で自分のパスワードを変更します。Active Directory アカウントは、Windows でパスワードを変更します。

**設定 → ユーザー**でアカウントを作成するとき、またはパスワードをリセットするときに、**次回のサインイン時に変更が必要**にチェックを入れられます。その場合、その人は、ほかの操作を行う前に、自分のパスワードを選ぶ必要があります。**設定 → セキュリティ → 管理者が設定する一時パスワード**がオンのときは、最初からチェックが入っています。

1 つのアカウントに対して、1 つのアドレスから 15 分以内に 5 回パスワードを間違えると、そのアドレスは 15 分待つ必要があります。本人はほかの場所からならサインインできます。アカウントがロックされるのは、あらゆる場所からの合計で 20 回間違えた場合のみで、15 分間ロックされます。Super Admin は、サインイン時のパスワードの誤りでロックされることはありません。Super Admin には、繰り返される失敗とロックアウト、および多数のネットワークにまたがる推測が通知されます。15 分以内に、1 つのアカウントが 3 つ以上のネットワークから 10 回失敗した場合、またはサーバー全体で 10 以上のネットワークから 50 回失敗した場合です。

## 2 要素サインイン

パスワードでサインインする人（ローカルまたは Active Directory）は、スマートフォンの認証アプリ（Microsoft Authenticator、Google Authenticator、1Password など）の 6 桁のコードも必須にできます。各コードは 1 回だけ有効なため、入力されるのを見られても、再利用されることはありません。設定するには、ページ上部の名前を選択し、**2 要素サインイン**を選択して、QR コードをスキャンし、アプリに表示されるコードを入力します。10 個のリカバリーコードが発行されます。スマートフォンを紛失した場合に、各コードで 1 回ずつサインインできるため、安全な場所に保管してください。あとから新しいリカバリーコードの作成やオフなどの変更を行うには、現在のコードが必要です。

サインイン時に、**このブラウザーでは 14 日間、再度確認しない**を選ぶと、パスワードまたは 2 要素の設定が変更されるまで、そのブラウザーではコードが省略されます。

スマートフォンとリカバリーコードの両方を紛失した場合は、**設定 → ユーザー**でその人の横にある **2 要素認証をオフにする**を使うと、パスワードのみでサインインして、設定し直すことができます。

**設定 → セキュリティ → 2 要素サインインを必須にする**をオンにすると、パスワードでサインインするすべての人が、ほかの操作を行う前に設定する必要があり、オフにすることもできなくなります。Microsoft サインインは、Entra 自身のチェックに任されます。

## セッション

ページ上部の名前を選択し、**セッション**を選択すると、サインインしているすべてのブラウザーが、アドレスと最終使用日時とともに表示されます。見覚えのないもの、または使用中のもの以外のすべてをサインアウトしてから、パスワードを変更してください。パスワードを変更するか、2 要素サインインをオンにすると、ほかのセッションはただちにサインアウトされます。

**設定 → セキュリティ → 管理ページでパスワードを確認**がオンの場合、直近 15 分以内にサインインまたは確認していない限り、管理ページはパスワードを再度求めます（2 要素サインインがオンの場合はコードも）。管理ページを使っている間は、その期間が延長されます。サインインしたままのブラウザーを見つけた人は、システムを使えても、設定、ユーザー、キーを変更することはできません。Microsoft サインインの場合は、代わりに再度サインインします。既定ではオフです。

**設定 → ユーザー**で、人の横にある**サインアウト**を選ぶと、すべてのブラウザーでその人がサインアウトされます。再度サインインできます。サインインさせないようにするには、アカウントを無効にしてください。

## ロール

ロールは、名前付きの権限の集合で、**設定 → ロール**で管理します。各ロールには、次の項目もあります。

- **スコープ階層**。
- 時間制限付きアクセス向けの**有効期限**（たとえば、8 時間のシフトなら 480 分）。
- **セッション有効期間**: サインインしてから、操作の有無にかかわらず、ユーザーが再度サインインする必要が生じるまでの時間数（最大 30 日、または 0 で期限切れなし）。
- **アイドルタイムアウト**: ページを開かないままユーザーがサインアウトされるまでの分数（0 でオフ）。ライブ映像を表示したままの画面は、アイドル状態として扱われるため、ビデオウォールを見るロールではオフのままにしてください。
- **PTZ 優先度**: 2 人のユーザーが同じカメラを動かすときに、どちらが優先されるかを決めます。

## 権限

**設定 → 権限マトリクス**では、各ロールに許可する操作（カメラの表示、再生、エクスポート、設定の編集など）を設定します。組み込みの **Super Admin** ロールは、常にすべての権限を持ちます。

**手動録画の開始と停止**は、ライブタイルの録画ボタンを制御します。下記の**録画**カメラアクセスも必要です。

## カメラアクセス

**設定 → カメラアクセス**では、各ロールが使用できるカメラを、すべてのカメラ、グループ、または個別のカメラで、表示、再生、エクスポート、PTZ、通話（双方向音声）、設定、録画（手動録画）ごとに決めます。**権限付与のないロールは、カメラを使用できません。** Super Admin は常にすべてのカメラを使用できます。エクスポートの範囲は、再生より広がることはありません。権限付与のないロールがすべてのカメラを使用できたバージョンからアップグレードすると、各ロールとユーザーのアクセスを同じに保つため、「すべてのカメラ」の権限付与が追加されます。

## API キー

**管理 → API キー**では、[API](/Help/api) 用のキーを発行します。各キーは、紐付けられたロールとして動作し、そのロールの権限の一部に制限できるため、複数のキーでそれぞれ異なる操作を許可できます。キーが使用できるカメラは、ロールのカメラアクセスで決まります。

## Entra

**設定 → セキュリティ → Entra ID サインイン**で、「Microsoft でサインイン」ボタンが追加されます。アカウントが作成されることはなく、メールアドレスでアカウントが照合されることもありません。**設定 → ユーザー**で、その人の行の **Microsoft サインイン**を使って、Entra の**オブジェクト ID**（Microsoft Entra 管理センターのユーザーページから取得）を入力します。最初の Microsoft サインインでリンクが完了します。空欄にするとリンクが削除されます。セキュリティページに表示されるリダイレクト URI を使って Entra にアプリを登録し、そのテナント ID（ディレクトリの GUID またはドメイン。`common` は不可）、クライアント ID、シークレットを入力します。変更はすぐに反映されます。すでにリンクされているアカウントは、引き続き機能します。

## Active Directory

**設定 → Active Directory**では、ドメインユーザーが AD のユーザー名とパスワードでサインインでき、AD グループに基づいてロールが付与されます。ドメイン、LarisVMS の接続方法、ローカルサインインは、誰が誰としてサインインできるかを左右するため、変更できるのは Super Admin のみです。ほかの管理者は、同期間隔とグループのリンクを変更できます。

- **ドメイン:** `corp.example.com` のような、ドメイン名のみ。
- **暗号化:** 既定はポート 636 の LDAPS で、このサーバーが信頼する証明書がドメインコントローラーに必要です。ポート 389 のプレーン LDAP は証明書なしで動作しますが、安全ではなく、推奨されません。
- **検索用アカウント:** 統合セキュリティ（既定）は、LarisVMS Web サービス自身のアカウントを使用します。サービスがドメインに参加したサーバー上で LocalSystem として動作している場合、それはコンピューターアカウントです。または、サービスアカウントを `DOMAIN\username` とそのパスワードで入力します。
- **サインイン:** `@` を含む名前はローカルアカウントです。それ以外は AD のユーザー名で、ドメインを付けずに入力します。

**グループとロールのリンク:** グループ名の入力を開始し、一覧から選択します（Tab で最初の候補を選択）。グループのメンバーにロールが付与され、入れ子のグループのメンバーも含まれます。アカウントは、必要になった最初の時点（グループがリンクされた直後、またはユーザーが初めてサインインしたとき）に作成されます。グループとユーザーは SID で追跡されるため、AD で名前を変更しても、次回の同期で引き継がれます。AD アカウントのロールは、グループのリンクからのみ付与され、ユーザーページでは編集できません。

**同期**は、既定では 30 分ごと（5 分から 24 時間）に実行されます。**今すぐ同期**を使えば、すぐに実行されます。AD で無効化または期限切れになった AD アカウントや、リンクされたどのグループにも属さなくなった AD アカウントは、ここでも無効になり、サインアウトされます。AD に接続できない場合、同期は何も変更せず、5 分後に再試行します。同期によって無効になったアカウントは、再び条件を満たすと有効に戻ります。ユーザーページで手動で無効にしたアカウントは、無効のままです。

**ローカルサインイン**は、AD サインインがオンで、少なくとも 1 つの AD アカウントが Super Admin である場合に、オフにできます。セットアップ中に作成した Super Admin アカウントとそのパスワードは、安全な場所に保管してください。AD が利用できなくなった場合は、LarisVMS データベースに対して次を実行し、そのアカウントでサインインします。SQL Server の場合:

```sql
UPDATE ActiveDirectorySettings SET LocalLoginsEnabled = 1
```

MariaDB の場合:

```sql
UPDATE `ActiveDirectorySettings` SET `LocalLoginsEnabled` = 1;
```

## 監査ログ

ユーザーが行うことはすべて、**ログ → 監査ログ**に記録されます。変更（古い値と新しい値。シークレットは「変更された」としてのみ記録）、カメラの表示、再生の開始、エクスポートです。

**改ざん検知。** 各エントリは、直前のエントリとともに、データベース単独では保持していないキーで封印されます。6 時間ごと（および監査ログページで**今すぐ確認**を選択したとき）に、ログ全体が確認されます。エントリがデータベース内で直接変更、削除、または追加された場合は、ページにどのエントリかが表示され、Super Admin に通知されます。保持期間によって削除されたエントリは想定内であり、対象になりません。また、各削除自体も記録されます（**AuditLog.Pruned**）。この更新より前のエントリは、対象外です。

サーバーはまた、`%ProgramData%\LarisVMS\audit-chain.dat` に、封印キーとログの開始位置の小さな記録を、データベースの外に保持しています。これにより、別のキーでログを封印し直したり、消去してやり直したりすると、それが判明します。同じサーバーで、新しい空のデータベースで意図的にやり直す場合は、そのファイルを一度削除してください。次のエントリで新しいファイルが作成されます。

**syslog への転送。** 監査ログのコピーをサーバーの外に保管するには、**設定 → ログ**で syslog サーバーを入力します。新しいエントリは、書き込まれるたびに送信されます（RFC 5424、ファシリティは *log audit*、エントリは JSON）。UDP、TCP、TLS から選択します。TLS では、syslog サーバーの証明書がウェブサーバーに信頼されている必要があります。syslog サーバーに接続できない場合、エントリは保持され、復旧後に送信されます。転送は、既存の履歴ではなく、次のエントリから開始されます。ログの転送先を変更したり、転送をオフにしたりできるのは、Super Admin のみです。その変更自体は、まず古い転送先に送信されます。
