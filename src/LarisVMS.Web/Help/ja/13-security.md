# セキュリティ

IP 許可リスト、ライブ/再生用の別ポート、厳格なスクリプトポリシー、証明書、ホスト名、更新、暗号化されたシークレット、企業向けの追加の保護について説明します。

## 許可リスト

**設定 → セキュリティ**には、2 つの IP 許可リストがあります。1 行につき IP または CIDR ブロックを 1 つ入力します（例: `10.0.0.5` や `10.0.0.0/24`）。`#` で始まる行はコメントです。空のリストは、全員を許可します。

- **管理 / API**: 管理ページと REST API。保存元のアドレスをブロックしてしまうリストは拒否されるため、自分自身を締め出すことはできません。
- **ライブビュー / 再生**: ライブ映像、再生、サムネイル、エクスポートのダウンロード、カメラのスナップショット。

## 別ポート

**設定 → ライブビュー → カスタムポート**は、ライブと再生のトラフィックを、同じ証明書を使う専用の HTTPS ポートに移します。これにより、ファイアウォールを別に設定したり、そのポートだけを LAN の外に公開したりできます。`Restart-Service LarisVMSWeb` のあとに反映されます。その後、映像は新しいポートでのみ応答し、それ以外はすべてメインポートでのみ応答します。フィールドを空にすると、1 つのポートに戻ります。

## HTTP/3

サーバーは HTTP/2 を使用し、Windows 11、Windows Server 2022 以降では HTTP/3 も追加されます。ブラウザーは HTTP/2 で開始し、HTTP/3 に到達できる場合は自動的に切り替わります。HTTP/3 は、HTTPS ポート（設定されている場合はカスタムポートも）で UDP を使用します。インストーラーは TCP と UDP の両方を開きます。古いインストールでは、そのポートに UDP のルールを追加するか、最新のインストーラーをもう一度実行してください。それまでは、すべてが HTTP/2 で引き続き機能します。HTTP/3 をオフにするには、**設定 → セキュリティ → HTTP/3** のチェックを外し、`Restart-Service LarisVMSWeb` を実行します。

## 厳格なスクリプトポリシー

**設定 → セキュリティ → 厳格なスクリプトポリシー**をオンにすると、ブラウザーはこのサーバーが送信するスクリプトのみを実行するため、ページに挿入されたスクリプトは実行できません。既定でオンで、アップグレードするとオンになります。何かが動作しなくなった場合は、オフにしてください。ブラウザーが、厳格なポリシーがブロックしていたはずのものを報告し、最新のレポートがスイッチの下に表示されます。使用しているページを一通り使って、レポートが表示されなくなったら、再びオンにしてください。変更は、次のページ読み込みから有効になります。

## 証明書

サーバーの証明書は、`appsettings.Production.json` で設定する `.pfx` ファイルです。更新されたファイルは、再起動なしで 1 分以内に反映されます。ダイレクトストリーミングを使うノードには、ノードのページに独自の証明書設定があります。

## カメラの証明書

HTTPS で接続するカメラには、何とも照合できない自己署名証明書があるため、既定ではどの証明書も受け入れられます。**設定 → セキュリティ → カメラの証明書を固定**をオンにすると、サーバーが各カメラアドレスの証明書を最初に接続したときに記憶し、それ以降は、サーバーとノードで、異なる証明書を拒否します。そうすれば、ネットワーク上でカメラになりすました何かが、パスワードを収集したり、偽のイベントを送信したりすることはできません。

記憶された証明書は、設定の下に一覧表示されます。カメラの証明書が実際に変更された場合（ファームウェアの更新、リセット、新しい証明書など）は、そのアドレスの横の**忘れる**を選択してください。次に提示される証明書が記憶されます。それまでは、サーバーまたはノードで拒否された接続ごとに、監査ログに記録され、Super Admin に通知されます（カメラアドレスごとに最大 1 時間に 1 回）。ネットワーク上の何かがカメラになりすましている可能性があるためです。カメラアドレスは、サーバーが最初に到達したとき（通常はカメラの追加時）に記憶されます。ノードは、サーバーがまだ到達していないアドレスも受け入れます。

## ホスト名

既定では、サーバーはブラウザーが使用するどのホスト名にも応答するため、IP アドレス、短い名前、完全な名前のいずれでも動作します。使用している名前にのみ応答させるには、`appsettings.Production.json` の `AllowedHosts` に、それらをセミコロンで区切って設定し（例: `"AllowedHosts": "vms.example.com;vms;localhost"`）、`Restart-Service LarisVMSWeb` を実行します。ノード、プロキシ、人が接続に使用するすべての名前を含めてください。それ以外はエラーになります。

リバースプロキシ（IIS ARR、nginx など）の背後では、そのアドレスを `appsettings.Production.json` に `"ReverseProxy": { "KnownProxies": [ "10.0.0.2" ] }` として記載し、再起動します。サーバーは、そのプロキシの `X-Forwarded-For` と `X-Forwarded-Proto` ヘッダーから、クライアントの実際のアドレスとスキームを取得するため、許可リストと監査ログには、プロキシではなく本人が表示されます。これらのヘッダーは、リストにないものからは無視され、リストが空の間は完全に無視されます。

## 更新

これらのチェックは、ダウンロードと実行中のインストールの間にあります。

- **リリースのダウンロード**には、`SHA256SUMS.txt` が付属します。インストーラーを実行する前に、`Get-FileHash <file> -Algorithm SHA256` で確認し、そのファイルの行と比較するか、`sha256sum -c SHA256SUMS.txt` を実行してください。インストーラーがコード署名されている場合は、Windows が発行元も表示します。
- **ノードとプロキシの更新**は、このサーバーの署名キーで署名されます。ノードまたはプロキシは、登録時にそのキーを保存し、サーバーとの接続が改ざんされたとしても、そのキーで署名されていないものはインストールしません。また、実行中のものより新しくないビルドも拒否します。[インストール](/Help/installation#updates)をご覧ください。
- **発行元の署名**（任意）: 発行元のキー（`-PublisherKeyPath`）でビルドされたノードまたはプロキシは、すべての更新に発行元の署名も必要とします。それ以外のビルドでは、このチェックをスキップします。そのキーはオフラインで保管され、サーバー上には置かれないため、侵入されたサーバーでさえ、独自のコードをノードに送り込むことはできません。
- サーバーへの**接続**は、**ノード → 更新と登録 → サーバー証明書の確認**の設定に従って検証されます（[ノード](/Help/nodes#server-certificate)をご覧ください）。

## 暗号化されたシークレット

カメラの認証情報、SMB の認証情報、ノードのキー、メールのシークレット、Entra のクライアントシークレット、Active Directory のサービスアカウントのパスワードは、`%ProgramData%\LarisVMS\keys` のデータ保護キーを使って、データベース内で暗号化されます。`%ProgramData%\LarisVMS` を開けるのは、SYSTEM、Administrators、LarisVMS サービスのアカウントのみです。LarisVMS のインストール前にローカルユーザーが作成したフォルダーなど、そこで見つかったそれ以外のアクセスは、サービスの起動時に削除されます。そのフォルダーはバックアップし、デプロイ中に削除しないでください。

## 企業向けの追加の保護

初期状態では、LarisVMS は家庭への導入がそのまま動作するよう設定されています。以下はすべて任意で、既定ではオフです。企業や、インターネットから到達できるサーバーに適したものをオンにしてください。

- **2 要素サインインを必須にする**: 設定 → セキュリティ（[2 要素サインイン](/Help/users#two-factor-sign-in)をご覧ください）。
- **管理ページでパスワードを確認**: 設定 → セキュリティ（[セッション](/Help/users#sessions)をご覧ください）。
- **管理者が設定する一時パスワード**: 設定 → セキュリティ（[パスワード](/Help/users#passwords)をご覧ください）。
- **より短いセッションとアイドルタイムアウト**: 設定 → ロールの各ロール（[ロール](/Help/users#roles)をご覧ください）。
- **カメラの証明書を固定**: 設定 → セキュリティ（[カメラの証明書](#camera-certificates)をご覧ください）。
- **許可リスト**: 設定 → セキュリティ（[許可リスト](#allow-lists)をご覧ください）。
- **ほかのすべてのコンピューターからのセットアップトークン**: セットアップウィザードを実行する前に、`appsettings.Production.json` に `"Setup": { "AlwaysRequireToken": true }` を設定します（[インストール](/Help/installation#web-server)をご覧ください）。
- **ノードまたはプロキシのインストール時にサーバー証明書を固定**: `-ServerCertThumbprint`（[サーバー証明書](/Help/nodes#server-certificate)をご覧ください）。
- **共有キーをオフにした、1 回限りの登録コード**: ノード → 更新と登録（[1 回限りの登録コード](/Help/nodes#one-time-registration-codes)をご覧ください）。
- **サーバーからノードへの暗号化接続**: 各ノードのページ（[サーバーからの暗号化接続](/Help/nodes#encrypted-connections-from-the-server)をご覧ください）。
- **監査ログを syslog に転送**: 設定 → ログ（[監査ログ](/Help/users#audit-log)をご覧ください）。
- **発行元が署名した更新**（ご自身でビルドする場合）（[更新](#updates)をご覧ください）。
- **より権限の低いサービスアカウント。** LarisVMS のサービスは、LocalSystem として動作します。別のアカウント（`services.msc` または `sc.exe config`）で実行することもできますが、その場合、サービスが必要とするもの（インストールフォルダー、すべてのストレージおよびアーカイブのフォルダーまたは共有、証明書ファイル）をそのアカウントに付与するのは、ご自身の責任となります。`%ProgramData%\LarisVMS` は自動的に処理されます。各 LarisVMS サービスは、起動時に、これを SYSTEM、Administrators、LarisVMS サービスが実行されるアカウントに限定し、それ以外のアクセスを削除します。変更後は、サービスのログを確認してください。
