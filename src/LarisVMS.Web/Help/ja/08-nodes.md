# ノード

録画ノードの状態、ストリーミング経路、メディアプロキシ、フェイルオーバー、メンテナンス、更新について説明します。

サイドバーの**ノード**には、すべてのノードが、状態、アドレス、バージョン、カメラ数、ディスク使用量とともに一覧表示されます。ノードをクリックすると、設定を編集できます。**⋯** メニューには、次の操作があります。

- **サービスを再起動**: ノードの Windows サービスを再起動します。マシンは再起動しません。録画は数秒間一時停止します。
- **認証をリセット**: ノードのチェックイントークンをクリアします。ハートビートを逃したあと、認証に失敗し続けるノード向けです。正常なノードには影響しません。
- **メンテナンス**: メンテナンスをオフにするまで、ノードのカメラをバックアップノードに移します。
- **削除**: ノードを削除します。そのカメラは割り当てが解除されます。録画は削除されません。

ノードは、過去 2 分以内にチェックインしていれば**オンライン**です。⚠️ **時計**の警告は、ノードの時計がサーバーの時計と 1 分以上ずれていることを意味するため、時刻同期を確認してください。

## ダイレクトストリーミング

既定では、すべてのライブ映像と再生映像は、ウェブサーバー経由で中継されます（**プロキシ**）。**ダイレクト**にすると、ブラウザーが各ノード自身の HTTPS エンドポイントに直接接続し、サーバーの負荷が軽くなります。モードは**設定 → ライブビュー**で設定し、ノードごとに上書きできます。

ダイレクトモードには、ブラウザーが到達できる**クライアントエンドポイントのホスト**と、証明書（ノードのページの `.pfx` パス）が必要です。**自己署名を許可**はテスト専用です。閲覧者にブラウザーの警告が表示されるためです。ノードに正常なエンドポイントがないカメラは、自動的にプロキシにフォールバックします。

## サーバーからの暗号化接続

サーバーとメディアプロキシは、各ノードの映像・制御ルートに、ライブポート（8554）のプレーン HTTP で接続します。信頼できるネットワークでは、これで問題ありません。そのトラフィックを暗号化するには、ノードのページで**サーバーからの接続を暗号化**をオンにし、ノードを 1 回再起動します（**再起動**）。ノードは HTTPS エンドポイントを開始し（`.pfx` がない場合は独自の自己署名証明書を使用）、その証明書を報告します。サーバーはその証明書を固定します。サーバーとプロキシは、ノードからその証明書のみを受け入れ、メディアトークンはアドレスの一部ではなくなります。暗号化されると、ノードのプレーンポートは `/health` にのみ応答します。

ノードページの**暗号化済み**列には、暗号化されたノードに 🔒、オンにしたものの再起動が必要なノードに ⏳ が表示されます。スイッチの下のステータスには、使用中の証明書、またはサーバーがまだ証明書を待っていることが表示されます（それまでは、サーバーはプレーン HTTP を使い続けるため、機能が止まることはありません）。既定ではオフです。このために使用される自己署名証明書がブラウザーに提供されることはありません。ダイレクトストリーミングには、引き続き正規の証明書が必要です。

## プロキシ

**メディアプロキシ**は、ブラウザーとノードの間にある別の中継（`LarisVMS.Proxy`）で、リモート拠点や低帯域幅の回線向けです。プロキシは**設定 → メディアプロキシ**で登録し、各ノードのページでプライマリとバックアップのプロキシを選択します。ブラウザーは、最初に正常なものを使用します。

## フェイルオーバー

ノードに**バックアップ録画ノード**を設定すると、そのノードがダウンしたとき、復帰するまで、バックアップがそのカメラを録画します。「ダウン」かどうかは、ノードのパートナー、サーバー、そのプロキシの間の投票で決まります。**メンテナンス**は、意図的にカメラを移し、そのまま保持します。

バックアップに異なる AI ハードウェアがある場合や、録画専用の場合は、ノードのページに警告が表示されます。その場合、フェイルオーバー中は、検出が遅くなったり、一時停止したりすることがあります。

## 更新

ノードとプロキシは、承認されたビルドから自動更新されます（[インストール](/Help/installation#updates)をご覧ください）。**ノード → 更新と登録 → 自動更新**で、すべてのノードに対してオン/オフを切り替えます。

ノードページの**ビルド**セクションには、各種類のノードが目指しているビルドと、承認待ちのビルドが、**承認**と**却下**とともに表示されます。**ビルド履歴**には、承認済み、置き換え済み、却下済みを含む、すべてのビルドが一覧表示されます。

## サーバー証明書

**ノード → 更新と登録 → サーバー証明書の確認**で、ノードとプロキシがこのサーバーの HTTPS 証明書を検証する方法を決めます。

- **初回使用時に信頼**（既定）: 信頼された CA の証明書は、更新後や置き換え後のものを含め、常に使用できます。自己署名証明書は、ノードが初めて接続したときに記憶され、同じである限り、有効期限を過ぎても使用され続けます。変更された場合、ノードとプロキシは、再登録されるまでそれを拒否します。
- **信頼された証明書のみ**: サーバーの名前と一致する、信頼された CA の証明書のみ。これを選択する前に、インストールしてください。
- **確認しない**: どの証明書でも受け入れます。安全ではありません。ネットワーク経路上の誰もが、サーバーになりすませます。

初回使用時に信頼では、ノードは、最初に接続したときに見た証明書を何でも信頼します。最初の接続から検証させるには、**サーバー証明書の確認**の下に表示されるサムプリントを、インストーラーに渡してください。`install-node.ps1` と `install-proxy.ps1` では `-ServerCertThumbprint`、MSI では `SERVERCERTTHUMBPRINT=` です。セットアップページとメディアプロキシページのインストールコマンドには、すでに含まれています。リバースプロキシの背後では、代わりに、リバースプロキシが提示する証明書のサムプリントを使用してください。

サーバーが自身用に作成する自己署名証明書は、10 年間有効で、自動的には置き換えられません。**自己署名証明書を再生成**で置き換えられますが、そうすると、すべてのノードとプロキシを再登録する必要があり、ノードページには、それ以降チェックインしていないものが一覧表示されます。ノードを再登録するには、ノードインストーラーを再実行するか、ノードで `LarisVMS.Node.exe --reset-server-pin` を実行してサービスを再起動します（プロキシにも同じオプションがあります）。

## 1 回限りの登録コード

新しいノードとプロキシは、共有の**登録キー**、または 1 回限りのコードで登録します。1 回限りのコードで登録できるのは 1 つのノードまたはプロキシのみで、その後は使えなくなります。使用されなかった場合は、1 時間、24 時間、または 7 日後に期限切れになります。作成するには、**ノード → 更新と登録**で有効期間を選択し、**コードを作成**を選択します。コードは一度だけ表示されます。インストーラーが登録キーを求める場所で使用してください。**失効**は、まだ使用されていないコードを取り消します。

共有キーは、変更されるまで、すべてのインストールで機能します。1 回限りのコードを使うようになったら、**共有登録キーを受け付ける**のチェックを外してください。古いスクリプトやメールにあるキーのコピーでは、何も登録できなくなります。すでに登録済みのノードとプロキシには影響しません。どちらの場合でも、新しいノードは、カメラが割り当てられる前に、承認を待ちます。
