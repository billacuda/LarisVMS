# トラブルシューティング

よくある問題と、確認する場所について説明します。

## ログの場所

- **サーバー**: **ログ → システムログ**。レベルと保持期間は**設定 → ログ**で設定します。Debug と Trace は詳細が増えますが、ファイルが大きくなります。
- **カメライベントログ**: カメラが送信する生のイベントで、イベントタグのためにカメラのイベントトピックを一覧表示する目的でのみ使用されます。既定では 30 日間保持されます（**設定 → ログ**。0 で永久に保持）。消去しても、イベント、スナップショット、映像には影響しません。
- **データベースのメンテナンス**: 毎晩午前 3 時ごろに、サーバーがデータベースのインデックスと統計を整理し、実行内容を 1 行でログに記録します。データベースのログインに権限がない場合は、代わりに警告が記録されます。MariaDB ではスキップされます。MariaDB は独自に統計を管理します。
- **ノード**: 各ノードの `%ProgramData%\LarisVMS\logs\node-*.log`。
- **AI 検出**: 各ノードの `%ProgramData%\LarisVMS\logs\vision-*.log`。
- **自動更新**: 各ノードまたはプロキシの `%ProgramData%\LarisVMS\logs\updater-*.log`。

## カメラが録画していない

1. **ノードに割り当てられて**いて、そのノードは**オンライン**ですか？
2. ノードに**ストレージパス**がありますか？ ない場合は、ノード一覧でフラグが付きます。
3. カメラは**有効**で、ストリームは正しく見えますか？ カメラ自体で変更を行ったあとは、**再プローブ**してください。
4. モーション、スケジュール、イベントのモードでは、映像が破棄されていないか確認してください（[録画](/Help/recording#modes)をご覧ください）。

## ライブビューと再生が「接続中」のまま

ノードがブラウザーに直接ストリーミングしている場合（[ダイレクトストリーミング](/Help/nodes#direct-streaming)をご覧ください）、ブラウザーはノードのクライアントポート（既定は 4200）に接続します。ブラウザーのコンソールに、失敗した `wss://<node>:<port>/live/…` 接続が表示される場合は、ノードのファイアウォールがそのポートを許可しているか確認してください。インストーラーは、**LarisVMS Node Client Endpoint** という名前の受信ルールを作成します。0.215.1 より前のインストーラーは、ノードのアップグレード時や引き継ぎ時に、そのルールを失うことがありました。最新のノードインストーラーをもう一度実行するか、ルールを手動で追加してください。

## Active Directory のサインインまたは同期が失敗する

**設定 → Active Directory** の**接続をテスト**を使用してください。最後の同期のエラーは、同じページに表示されます。

- **ドメインコントローラーに接続できない:** ドメイン名がサーバーから解決できること、およびポート 636（LDAPS）または 389（LDAP）がドメインコントローラーに対して開いていることを確認してください。LDAPS では、ドメインコントローラーに、このサーバーが信頼する証明書が必要です。
- **サーバー自身の ID が拒否された:** 統合セキュリティは、LarisVMS Web サービスが、ドメインに参加したサーバー上で、LocalSystem またはドメインアカウントとして動作している場合にのみ機能します。そうでない場合は、サービスアカウントを使用してください。
- **「アクセス権のあるグループに属していません」:** ユーザーは正しくサインインしましたが、リンクされたグループに属していません。グループは、入れ子のものも含め、セキュリティグループとして照合されます。
- **ローカルサインインをオフにしたあと、管理ページに入れなくなった:** それをオンに戻すデータベースコマンドについては、[Active Directory](/Help/users#active-directory) をご覧ください。

## 背景のウィンドウでライブビューが一時停止する

Chrome は、表示されていないウィンドウを抑制するため、2 台目のモニターのライブウォールが固まり、その後追いつくことがあります。ライブビューは自動的に復旧します。防ぐには、Chrome のショートカットのリンク先に、次を追加してください。

```
--disable-backgrounding-occluded-windows --disable-background-timer-throttling
```

## すべてのタイルが固まり、そのあと一斉に再接続する

ブラウザーやネットワークではなく、ノードが停止しました。ノードのログで `Node process health: tick … ms late` を探してください。正常なノードは、これを 1 分に 1 回程度、1 桁ミリ秒の遅延で記録します。

- `gcPauseMs` が遅延に近い場合、原因はガベージコレクションです。
- `gcPauseMs` が小さいのに `pendingWorkItems` が数十の場合、スレッドがブロックされています。停止している間にダンプを取得してください: `dotnet-dump collect -p <LarisVMS.Node pid>`。

## AI 検出は止まるが、録画は続く

通常は、GPU ドライバーがリセットされています。Windows のシステムイベントログに、その時点で `nvlddmkm` のイベント 153 または `Display` のイベント 4101 が表示されます。ビジョンサービスは、結果が 60 秒間ない状態が続くと、自動的に再起動します。リセットが繰り返される場合は、GPU、ドライバー、冷却、または電源が原因です。

## 更新後にノードまたはプロキシが復帰しなかった

そのサービスを開始し（`sc start LarisVMSNode`、または `LarisVMSProxy`）、`updater-*.log` で再起動が失敗した理由を確認してください。ダウンロードされたものの適用されなかった更新は、ノードまたはプロキシが次に起動するときに、そのログにも記録され、後のチェックインで再び提供されます。

## ノードに「時計」と表示される

ノードの時計が、サーバーの時計と 1 分以上ずれています。時刻同期を修正してください。時計のずれは、スケジュールとタイムラインに影響します。

## ノードがチェックインに失敗し続ける

ノードの **⋯** メニューから**認証をリセット**を使用してください。ノードのチェックイントークンがクリアされ、次のハートビートでノードが再同期します。
