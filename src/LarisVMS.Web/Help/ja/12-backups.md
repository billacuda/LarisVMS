# バックアップ

データベースのバックアップと、そのほかにバックアップが必要なものについて説明します。

**設定 → バックアップ**では、LarisVMS データベースの SQL Server 完全バックアップを、日次スケジュールまたはオンデマンドで取得します。独自のバックアップをスケジュールできる SQL Agent がない、SQL Express 向けです。

- **バックアップディレクトリ**: *SQL Server サービス*が書き込めるフォルダーで、LarisVMS のインストールフォルダーの外にしてください。SQL Server が別のマシンにある場合、このパスはそのマシン上に存在する必要があり、古いバックアップは自動では削除されません。
- **保持する世代数**: 保持するバックアップの数です（ローカルの SQL Server のみ）。

復元は、LarisVMS の外で、SSMS または `sqlcmd` を使って行います。バックアップは完全バックアップのみです。SQL Express では、SIMPLE 復旧モデルを使用してください。

## MariaDB

MariaDB では、バックアップは `mariadb-dump` で作成され、圧縮された `.sql.gz` ファイルとして保存されます。`mariadb-dump` は LarisVMS サーバー上で実行されるため、MariaDB 自体が別のマシンで動作していても、そこに MariaDB クライアントツールをインストールしておく必要があります。LarisVMS は、`C:\Program Files\MariaDB …` からそれらを見つけます。または、Super Admin がバックアップページで `mariadb-dump.exe` のパスを設定できます。LarisVMS はサービス自身の権限でそれを実行するため、このパスは、このサーバー上の、管理者のみが変更できるフォルダー（Program Files 以下など）にある必要があります。

- **バックアップディレクトリ**: LarisVMS サーバー上のフォルダー（または共有）で、*LarisVMS サービス*が書き込めるもの。インストールフォルダーの外にしてください。MariaDB がどこで動作していても、古いバックアップは常に削除されます。
- バックアップには、データベース全体が、録画を止めずに取得された、1 つの一貫したスナップショットとして含まれます。

`.sql.gz` を（たとえば 7-Zip で）展開してから、`mariadb` クライアントで復元します。このファイルはデータベースがなければ作成し、テーブルを置き換えるため、先に LarisVMS Web サービスを停止してください。

```powershell
cmd /c "mariadb -u root -p < larisvms_20261026_030000.sql"
```

## そのほかのバックアップ対象

- `%ProgramData%\LarisVMS\keys` の**データ保護キー**。カメラのパスワード、メールのシークレット、ノードのキーは、これらで暗号化されています。これらのキーがないと、復元したデータベースでは、それらを復号できません。
- インストールフォルダー内の **`setup-generated.json`**。データベースの接続文字列が含まれています。そのパスワードは、保存したマシンでのみ機能します。新しいマシンでは、セットアップウィザードをもう一度実行し、復元したデータベースを指定してください。

録画は、データベースのバックアップには含まれません。アーカイブボリュームや、ご自身のストレージバックアップで保護してください。
