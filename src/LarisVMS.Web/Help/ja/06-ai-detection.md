# AI 検出

ノード上でのオブジェクト検出（モデル、ハードウェア、しきい値、スナップショット、外部バックエンド）について説明します。

各ノードは、カメラに対してリアルタイムのオブジェクト検出を実行できます。検出されたオブジェクトには、ライブのバウンディングボックス、タイムライン上の色付きの印、ライブタイルのバッジ、切り抜かれたスナップショットが付きます。検出は、モーションモードの録画では、モーションとしても数えられます。検出は別のプロセスで実行されるため、GPU やドライバーの問題で録画が止まることはありません。

カメラごとに、**このカメラでオブジェクトを監視**でオンにします。正確な検出に必要なのは、**カメラあたり 5～7 fps** だけです。GPU の負荷を抑えるため、[フレームレート](#thresholds)をその値に制限してください。グローバルな既定値は**設定 → AI 検出**にあります。ノードやカメラは、その大半を上書きできます。

## ハードウェア

1 つのノードパッケージで、すべてのマシンに対応します。起動時に、ビジョンサービスが、見つかったハードウェアに合わせてバックエンドを選択します。

| ハードウェア | バックエンド | ノードで必要なもの |
|---|---|---|
| NVIDIA GPU | CUDA（DirectML にフォールバック） | CUDA Toolkit 12.x と cuDNN 9.x |
| AMD / Intel GPU | DirectML | 最新の GPU ドライバー |
| GPU なし | CPU | なし |

ノードの編集ページには検出されたアクセラレーターが表示され、**アクセラレーター**の設定で 1 つを強制できます。モデルは同梱されていません。ノードは組み込みの YOLOX モデルをサーバーから取得し、それ以外のモデルは、ノードの `C:\ProgramData\LarisVMS\models` に置きます。

## 低速なバックエンド

NVIDIA のノードが CUDA を使用できない場合、AI 検出は DirectML にフォールバックしますが、数倍遅くなります。分析されるフレームが減り、GPU が高温になり、通過する車のような速いオブジェクトが検出されないことがあります。その場合、**ノード**ページのノードの横に、理由とともに**⚠️ DirectML 上の AI**と表示され、Super Admin に通知が届きます。

通常の原因は、cuDNN がないことです。ノードに CUDA Toolkit 12.x と、CUDA 12 用の cuDNN 9.x を、NVIDIA の cuDNN ダウンロードから、または `pip install nvidia-cudnn-cu12` でインストールしてください。ノードは 10 分以内にそれらを見つけ、AI バックエンドの隣にコピーし、CUDA で検出を再起動します。

## モデルファミリー

モデルはノードごとに 1 回実行され、そのノードのすべてのカメラに対応します。そのため、モデルの設定はカメラ単位ではなく、ノード単位です。

- **自動 / YOLOX**: 既定です。高速で、レターボックスが不要で、低電力の GPU や NVIDIA 以外の GPU でもよく動作します。**YOLOX サイズ**は、Nano（最速）から X（最高精度）まであります。低電力のマシンには Nano または Tiny、強力な GPU には L または X を使用してください。
- **D-FINE**: 試験的です。結果が予測できないことがあり、スライスモードで 2 つのタイルにまたがるオブジェクトは、見逃されたり重複したりすることがあります。**重み**: Obj2Coco は 80 種類のオブジェクト（小または中）を認識し、Obj365 は 365 種類を認識します。
- **カスタム**: ノードの models フォルダーに置いた任意の `.onnx` モデルです。[カスタムモデル](#custom-models)をご覧ください。

モデルを変更すると、各カメラの検出が再起動します。

## TensorRT

**D-FINE TensorRT** が機能するのは、ノードで TensorRT が有効になっていて（`Vision:EnableTensorRt`）、TensorRT 10.x SDK がインストールされている場合のみです。**FP32** は、安全な高速化をもたらします。**FP16** は最速です。カメラのエンジンが FP16 でオーバーフローした場合は、自動的に FP32 で再構築されます。各カメラ解像度での最初の起動では、エンジンの構築に数分かかります。

## カスタムモデル

`.onnx` ファイルを、ノードの `C:\ProgramData\LarisVMS\models` に置きます。モデル自身のメタデータにデコーダー、入力サイズ、ラベルが記述されていれば、そのまま動作します。そうでない場合は、不足している情報を補う、同じ名前の `.json` ファイルを追加してください。**更新**には、ノードが見つけたすべてのモデルが一覧表示され、メタデータが不完全なものにはフラグが付きます。警告のあるモデルは選択できますが、警告が解消されるまで実行されません。

## アスペクト比の調整

カメラのフレームを、モデルの正方形の入力に合わせる方法です。

- **レターボックス**（既定）: 縦横比を保ち、黒い帯で埋めます。
- **引き伸ばし**: フレームを押しつぶして正方形に合わせるため、形が歪みます。
- **スライス**: フレームを、重なり合うフル解像度の正方形に切り分けます。広角カメラ上の小さなオブジェクトや遠くのオブジェクトに最適ですが、16:9 のカメラでは約 2 倍の処理が必要です。GPU 前処理が必要で、自動的にオンになります。

**GPU フレーム前処理**は、色変換を CPU から GPU に移します。カメラの多いノードで効果があります。

## しきい値

- **信頼度**: 検出として数えられる最低スコアです。低くすると多くのオブジェクトを捉えますが、誤検出が増えます。何かを誤検出し続けるカメラでは、上げてください。
- **IoU**: 2 つのボックスが、どれだけ重なると 1 つのオブジェクトとして統合されるかです。
- **検出ストリーム**: サブは軽量で、メインはより詳細に捉えます。
- **向き**: 廊下に設置された一部のカメラは、横向きのストリームを報告しながら、縦向きの映像を送信します。それらのカメラでは**縦向き**を設定すると、検出とスナップショットが押しつぶされません。
- **最大検出フレームレート**: カメラごとに、モデルに届く 1 秒あたりのフレーム数です。**5～7 fps で、正確な検出と追跡には十分です。** それより高くしても、結果は良くならず、GPU の負荷が増すだけです。0 は上限なしです。

## スナップショット

追跡された各オブジェクトには、最も良いフレームから切り抜かれたスナップショットが付きます。

- **アイドルタイムアウト**: オブジェクトが見えなくなってから、スナップショットを閉じるまでの時間です。
- **静止オブジェクトを報告**: 駐車中の車のように、存在していても動いていないオブジェクトも報告します。
- **スナップショットのモーション精度**: オブジェクトが離れた少しあとにスナップショットを閉じ、同じ種類の後続のオブジェクトが統合されないようにします。**退出猶予**は、その待ち時間です。短すぎると、立ち止まったオブジェクトが 2 つのスナップショットに分かれます。
- **スナップショットのトリミング余白**: オブジェクトの周囲に確保する余白で、ボックスに対する割合で指定します。

同じ種類の複数のオブジェクトが 1 つのスナップショットに含まれる場合は、数（×2）で表示されます。それぞれ、独自の色と速度とともに、個別にも保存されます。

## オブジェクトの色

追跡された各オブジェクトの色は、最も鮮明なフレームから読み取られます。車両、動物、その他のオブジェクトは 1 色、人はシャツとズボンの色です。スナップショットには、それぞれの色で塗られたバッジが表示され、スナップショットのフィルターの**色**、**シャツ**、**ズボン**セクションで、チェックを入れた色に絞り込めます。検出アラートも、色で絞り込めます。

色はモデルではなく画像から取得されるため、どの検出器でも機能します。ボックスのすぐ外側の色もサンプリングされて除外されるため、犬の周りの芝生や、車の周りの道路の色が優先されることはありません。それでも最善の推測にすぎず、ごちゃごちゃしたシーン、重なり合ったオブジェクト、照明によって、誤った色になることがあります。最も影響が大きいのは照明です。日陰、ヘッドライト、ホワイトバランスで色が変わり、明るいグレーの車はシルバーや白と判定されることがあります。カメラが白黒の夜間（IR）モードの間は、色は記録されません。オフにするには、**設定 → AI 検出**の**オブジェクトの色**を使用します。

## 速度測定

速度測定は、道路を横切る 2 本の線の間で、オブジェクトの所要時間を計測します。カメラの**速度測定**ページ（**カメラ → 編集**から）で、**新しい速度測定**をクリックし、線 **A** の両端、次に線 **B** の両端をクリックして、道路に沿って測った線の間の実際の距離を入力します。両方の線を通過した追跡対象のオブジェクトには、速度が付き、ライブのボックスとスナップショットに表示されます。**方向**は、既定では両方向を計測します。双方向道路の 1 車線を計測するには、**A から B のみ**または **B から A のみ**を選択します。**速度の単位**（km/h または mph）は、**設定 → AI 検出**にあります。

速度測定で計測されたオブジェクトは、カメラに向かってまっすぐ走ってくる車両のように、それ以外では静止して見える場合でも、動いているものとして記録されます。計測には、オブジェクトが地面に接するボックスの下端中央が使われるため、線は路面上に描いてください。正確に計測するには:

- 線は、平らな地面で、進行方向と交差するように描き、オブジェクトがはっきり見える範囲でできるだけ離してください。
- 距離は慎重に測ってください。歩測するか、地図の測定ツールを使用します。
- 既知の速度で通過した車両で一度確認し、値がずれている場合は、距離を調整してください。

測定値は推定値です。カメラの検出フレームレートが、通過時刻をどれだけ正確に計測できるかを制限するため、短い測定区間と速い車両の精度が最も低くなります。速度測定を保存すると、カメラの AI 検出が再起動します。

速度測定には、**速度制限**（任意）を設定できます。それを超える速度は赤で表示され、速度ヒートマップで別にカウントされます。

測定された速度は、複数の場所に表示されます。

- **ライブビュー**: オブジェクトが映っている間、そのボックスに表示されます。
- **スナップショット**: カードの ⏱ バッジと、フィルター一覧の**速度**フィルター（「以上」）。
- **再生**: 各測定位置のタイムライン上の目盛り（制限を超えると赤。カーソルを合わせると詳細が表示されます）と、オブジェクトが画面に映っている間の映像上のバッジ。
- **ダッシュボード**: **速度ログ**ウィジェットに、最新の測定値が表示されます。タイトルをクリックすると、並べ替え、絞り込み、CSV ダウンロードが可能な完全なログが開きます。
- **アクティビティ**: **速度**に切り替えると、平均速度、最高速度、制限超過数、測定数のヒートマップが、日別・時間別に表示されます。履歴は、映像がなくなったあとも長く、アクティビティ履歴と同じ期間保持されます。
- **アラート**: 「制限を超える速度」ルール。

## 動き

スナップショット、アラート、ライブの**動いている**ボックスは、どこかへ向かっているオブジェクトだけを数えます。検出器のボックスは、駐車中の車でも、フレームごとに少し揺れるため、数ピクセルの変化では十分ではありません。これをどう判定するかは、**設定 → AI 検出**の**動体検出**、またはカメラごとに**カメラ → 編集**で決めます。

**標準**（既定）は、各オブジェクトの最近の経路の形を見ます。

- 一定の方向に着実に動くものは、数フレーム以内（7 fps でおよそ半秒）に動いていると数えられます。1 秒足らずで視界を横切る車でも、私道から出てくるトラックでも同様です。各オブジェクトの歩幅は、そのオブジェクト自身のボックスがどれだけ揺れるかと比較されるため、大きなオブジェクトが小さなオブジェクトより遠くまで移動する必要はありません。
- ボックスの揺れよりもゆっくり動くもの（歩く速さのごく一部）は、経路が数秒間、一定の線に沿って続いた時点で数えられます。揺れは前後に往復するため、線にはなりません。
- オブジェクトが移動しなければならない距離は、サイズとともに増えますが、サイズ自体よりも緩やかです。大きなトラックが、先に自分の長さの半分を横切る必要はありません。
- 画像の端から入ってくるオブジェクト、または柱や木の陰から出てくるオブジェクトは、見えている側のボックスの辺で判定されます。
- カメラに向かって、または離れる方向にまっすぐ走るオブジェクトは、大きくなる、または小さくなるにつれて数えられます。
- 駐車中の車の前を誰かが歩いてボックスが変化しても、数えられません。

**動体検出の感度**（標準のみ）は、既定で**標準**です。**高**は動きを早く検出し、**低**は揺れをより多く無視します。駐車中の車や揺れる茂みが動いていると報告されるカメラでは下げ、遅いオブジェクトが見逃されるカメラでは上げてください。

植木鉢の葉を検出器が含めたり含めなかったりして形が変わる場合や、駐車中の車の前を何かが通り過ぎて形が変わる場合のように、単にボックスの形が変わるだけでは、数えられません。動きは、1 回の急な変化ではなく、複数のフレームにわたって積み上がる必要があります。

**レガシー**は、以前のルールです。オブジェクトの中心が、2 秒以内にボックスのサイズの半分だけ動いたときに数えられます。標準がカメラで誤動作する場合に使用してください。

動いていたオブジェクトが、木、柱、駐車中の車の陰に入って見えなくなっても、同じ線上のさらに先で、分析された約 30 フレーム以内（6 fps でおよそ 5 秒）に出てくれば、同じオブジェクトのままになるため、1 回だけ数えられ、経路も 1 本のままです。さらに、同じ種類のオブジェクトでサイズが似ており、両方で判別できる場合は色も一致している必要があります。別の方向に出てきたもの、またはもっと時間が経ってから出てきたものは、新しいオブジェクトです。

## 動いているオブジェクト

動いている各オブジェクトの映像内での経路は、そのイベントとともに保存され、アクティビティページの**シーン**ヒートマップに使用されます。

**設定 → AI 検出**の**動いているオブジェクト**では、動いていると数えるオブジェクトの種類を選択します。既定では、**人**、**車両**、**動物**です。それ以外のものも検出され、**静止**をオンにすると静止ボックスとして表示されますが、動いていると数えられることはないため、スナップショットやアラートを開始できません。ほかのオブジェクトは、**その他のオブジェクト**の一覧で、1 つずつオプトインします。配達された荷物は、通常、スーツケース、バックパック、ハンドバッグとして認識されます。カスタムモデルの場合は、そのモデル自身のオブジェクト名をカンマで区切って入力します。

## 無視するオブジェクト

**設定 → AI 検出**の**無視するオブジェクト**では、オブジェクトの種類を完全にオフにします。モデルが報告した時点で破棄されるため、ボックス、スナップショット、イベント、アラートは一切作られません。デッキを飛行機と誤認するなど、お使いのカメラでモデルが誤認し続けるものに使用します。カテゴリ全体（**人**、**車両**、**動物**、**その他のオブジェクト**）または、一覧の個別のオブジェクトにチェックを入れます。どちらのモデルの表記でも一致するため、**airplane** を無視すると **aeroplane** も無視されます。カスタムモデルの場合は、そのモデル自身のオブジェクト名をカンマで区切って入力します。

カメラの**編集**ページでは、グローバルな一覧の代わりに、独自の一覧を選択できます。**無視するオブジェクト**で**このカメラ用に選択**を選びます。そこで何も選択しないと、グローバルな一覧で無視されるものも含め、そのカメラではすべてが検出されます。保存すると、そのカメラの検出が再起動しますが、リセットされるのは追跡だけです。

## ジッター

**ジッターのしきい値**は、オブジェクトのサイズに関係なく、動きとして数えられる最小のピクセル数です。レガシーモードでは、**静止オブジェクトのジッター除外**が、遠くに駐車した車両の揺れを平滑化します。本当にゆっくり動いているオブジェクトを静止として扱ってしまうこともあるため、既定ではオフです。標準には適用されません。標準は、揺れを自分で処理します。

## 外部バックエンド

**外部 HTTP サービス**は、ノード上でモデルを実行しません。各フレームを、ご自身で運用する推論サーバーに送信し、サーバーはボックスを JSON で返します。LarisVMS が同梱していないモデルや、GPU のないノードで使用します。追跡、スナップショット、タイムライン、ライブオーバーレイは、同じように機能します。

サービスは、`POST /v1/detect`、`GET /v1/models`、`GET /healthz` を公開する必要があります。**テスト**で接続を確認し、モデル一覧を読み込みます。**API キー**は、Bearer トークンとして送信されます。**トランスポート**: JPEG は、どのサービスでも動作します。raw の YUV と BGRA のモードは JPEG エンコードを省略しますが、4～10 倍の帯域幅を使用し、モデルがそれらを公開している場合にのみ動作します。
