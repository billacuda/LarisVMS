# AI 检测

节点上的对象检测：模型、硬件、阈值、快照和外部后端。

每个节点都可以对其摄像头运行实时对象检测。被检测到的对象会获得实时边界框、时间线上的彩色标记、实时磁贴上的徽章和裁剪后的快照。检测在移动侦测模式录制中也算作移动。检测在单独的进程中运行，因此 GPU 或驱动程序问题永远不会使录制停止。

通过**监视此摄像头中的对象**按摄像头开启它。准确检测只需要**每台摄像头 5–7 fps**，因此请将[帧率](#thresholds)限制在这个水平，以降低 GPU 负载。全局默认值在**设置 → AI 检测**下。节点和摄像头可以覆盖其中大部分。

## 硬件

一个节点包适用于所有计算机。启动时，视觉服务会根据发现的硬件选择后端：

| 硬件 | 后端 | 节点上需要 |
|---|---|---|
| NVIDIA GPU | CUDA（回退到 DirectML） | CUDA Toolkit 12.x 和 cuDNN 9.x |
| AMD / Intel GPU | DirectML | 最新的 GPU 驱动程序 |
| 无 GPU | CPU | 无 |

节点的编辑页面会显示检测到的加速器，其**加速器**设置可以强制指定一个。模型从不随附。节点会从服务器获取内置的 YOLOX 模型，其他模型放入节点上的 `C:\ProgramData\LarisVMS\models`。

## 慢速后端

如果 NVIDIA 节点无法使用 CUDA，AI 检测会回退到 DirectML，其运行速度要慢好几倍。分析的帧会变少，GPU 会发热，经过的汽车等快速移动的对象可能检测不到。此时**节点**页面会在该节点旁显示**⚠️ AI 运行于 DirectML**及原因，并通知超级管理员。

通常的原因是缺少 cuDNN。请在节点上安装 CUDA Toolkit 12.x 和适用于 CUDA 12 的 cuDNN 9.x，可从 NVIDIA 的 cuDNN 下载页面获取，或使用 `pip install nvidia-cudnn-cu12`。节点会在 10 分钟内发现它们，将其复制到其 AI 后端旁，并在 CUDA 上重启检测。

## 模型系列

模型每个节点运行一次，并为该节点的所有摄像头提供服务，因此模型设置是按节点而不是按摄像头的。

- **自动 / YOLOX**：默认选项。速度快，不需要加黑边，在低功耗和非 NVIDIA 的 GPU 上也表现良好。**YOLOX 规格**从 Nano（最快）到 X（最准确）。低功耗计算机使用 Nano 或 Tiny，强劲的 GPU 使用 L 或 X。
- **D-FINE**：实验性。结果可能难以预料，在切片模式下横跨两个磁贴的对象可能被遗漏或重复。**权重**：Obj2Coco 能识别 80 种对象类型（小或中），Obj365 能识别 365 种。
- **自定义**：放入节点 models 文件夹的任何 `.onnx` 模型。参见[自定义模型](#custom-models)。

更改模型会重启每台摄像头的检测。

## TensorRT

只有当节点启用了 TensorRT（`Vision:EnableTensorRt`）并安装了 TensorRT 10.x SDK 时，**D-FINE TensorRT** 才会起作用。**FP32** 能带来稳妥的加速。**FP16** 最快；如果摄像头的引擎在 FP16 下溢出，它会自动以 FP32 重新构建。在每个摄像头分辨率下首次启动时，构建引擎需要几分钟。

## 自定义模型

将 `.onnx` 文件放入节点上的 `C:\ProgramData\LarisVMS\models`。如果模型自身的元数据描述了其解码器、输入尺寸和标签，它就能直接使用。否则，请添加一个同名的 `.json` 文件，补充缺少的内容。**刷新**会列出节点发现的所有模型，并标出元数据不完整的模型。带有警告的模型可以选择，但在警告被修复之前不会运行。

## 宽高比适配

摄像头的画面如何适配模型的方形输入：

- **黑边填充**（默认）：保持比例，并用黑边填充。
- **拉伸**：将画面压缩以填满方形，这会使形状失真。
- **切片**：将画面切成相互重叠的全分辨率方块。最适合广角摄像头上小而远的对象，但在 16:9 的摄像头上要多做约 2 倍的工作。它需要 GPU 预处理，并会自动开启。

**GPU 画面预处理**把颜色转换从 CPU 转移到 GPU，这对摄像头较多的节点有帮助。

## 阈值

- **置信度**：检测被计入的最低分数。越低能捕获越多对象，但会增加误报。在不断误检的摄像头上请调高它。
- **IoU**：两个框必须重叠多少才会合并为一个对象。
- **检测码流**：子码流更轻量；主码流能看到更多细节。
- **方向**：一些安装在走廊的摄像头上报横向码流，却发送纵向视频。请在这些摄像头上设置**纵向**，以免检测和快照被压扁。
- **最大检测帧率**：每台摄像头每秒送达模型的帧数。**5–7 fps 足以实现准确的检测和跟踪。** 更高的帧率只会增加 GPU 负载，并不能改善结果。0 表示不设上限。

## 快照

每个被跟踪的对象都会获得一张快照，从其最佳画面中裁剪而来。

- **静止超时**：对象多久看不到之后，其快照才会关闭。
- **上报静止对象**：同时上报存在但未移动的对象，例如停着的汽车。
- **快照移动精度**：在对象离开后不久关闭快照，使稍后出现的同类对象不会被并入其中。**离开宽限时间**是等待多久。如果太短，停顿的对象会被拆分成两张快照。
- **快照裁剪边距**：对象周围额外保留的空间，以其框的百分比表示。

同一类型的多个对象出现在同一张快照中时，会显示为数量（×2）。每个对象也会连同各自的颜色和速度单独保留。

## 对象颜色

每个被跟踪对象的颜色取自其最清晰的画面：车辆、动物和其他对象为一种颜色，人则有上衣和裤子的颜色。快照会为每种颜色显示一个涂有该颜色的徽章，快照筛选器中的**颜色**、**上衣**和**裤子**部分会将结果缩小到您勾选的颜色。检测警报也可以按颜色筛选。

颜色来自画面而不是模型，因此适用于任何检测器。紧挨着框外侧的颜色也会被采样并剔除，所以狗周围的草坪或汽车周围的道路不会被误判为其颜色。它们仍然只是尽力而为的猜测：复杂的场景、重叠的对象和光线都可能给出错误的颜色。光线的影响最大：阴影、车灯和白平衡会使颜色偏移，浅灰色的汽车可能被识别为银色或白色。当摄像头处于黑白夜间（红外）模式时，不会记录颜色。可在**设置 → AI 检测**下用**对象颜色**将其关闭。

## 测速点

测速点会在道路上的两条线之间为对象计时。在摄像头的**测速点**页面（从**摄像头 → 编辑**进入）上，点击**新建测速点**，点击线 **A** 的两端，再点击线 **B** 的两端，并输入两线之间沿道路测量的实际距离。每个越过两条线的被跟踪对象都会得到一个速度，显示在其实时框和快照上。**方向**默认为双向计时；选择**仅 A 到 B**或**仅 B 到 A**可以为双向道路的一条车道计时。**速度单位**（km/h 或 mph）在**设置 → AI 检测**下。

被测速点计时的对象，即使看起来是静止的（例如径直驶向摄像头的车辆），也会被记录为在移动。计时使用每个框的底部中点，即对象接触地面处，因此请把线画在路面上。为了获得良好的读数：

- 将线画在平坦的地面上，横跨行驶方向，并在对象仍清晰可见的前提下尽量拉开距离。
- 仔细测量距离：可以步测，或使用地图的测距工具。
- 用一辆以已知速度驶过的车辆检查一次，如果读数有偏差，请调整距离。

读数是估计值。摄像头的检测帧率限制了通过时刻的计时精度，因此短的测速点和快速行驶的车辆精度最低。保存测速点会重启摄像头的 AI 检测。

测速点可以设置**速度限制**（可选）。超过它的速度会以红色显示，并在速度热力图中单独计数。

测得的速度会出现在多个位置：

- **实时查看**：对象在画面中时，显示在其框上。
- **快照**：卡片上的 ⏱ 徽章，以及筛选列表中的**速度**筛选（“达到或超过”）。
- **回放**：时间线上每次测量处的刻度（超过限制时为红色；悬停可查看详情），以及对象在屏幕上时视频上方的徽章。
- **仪表板：**“**速度日志**”小组件显示最新的测量结果。点击其标题可查看完整日志，支持排序、筛选和 CSV 下载。
- **活动**：切换到**速度**，可按天和小时查看平均速度、最高速度、超限数量或测量数量的热力图。历史记录的保存时间与活动历史相同，远长于录像本身。
- **警报：**“速度超过限制”规则。

## 移动

快照、警报和实时的**移动中**框只统计正在朝某处移动的对象。即使在停着的汽车周围，检测器的框也会逐帧轻微晃动，所以几个像素的变化是不够的。**设置 → AI 检测**下的**移动检测**，或每台摄像头在**摄像头 → 编辑**上的设置，决定如何判断这一点。

**标准**（默认）观察每个对象近期路径的形状：

- 任何朝一个方向稳定移动的对象，在几帧之内（7 fps 时大约半秒）就会被计为移动，无论它是不到一秒就穿过画面的汽车，还是正驶出车道的卡车。每个对象的步幅会与其自身的框晃动幅度比较，因此大对象不必比小对象走得更远。
- 比其框的晃动更缓慢地爬行的对象（只有步行速度的一小部分），在其路径保持稳定的直线数秒之后会被计入。晃动是来回的，因此永远不会形成一条线。
- 对象需要走多远随其大小而增长，但比大小本身增长得更慢。一辆大卡车不必先走过自身长度的一半。
- 从画面边缘进入，或从杆子或树后面出来的对象，按其框在画面中可见的那一侧来判断。
- 径直驶向或驶离摄像头的对象，会随着变大或变小而被计入。
- 有人从停着的汽车前面走过而使其框发生变化，不会被计入。

**移动灵敏度**（仅标准模式）默认为**普通**。**高**更早发现移动，**低**会忽略更多晃动。在停着的汽车或摇晃的灌木被报告为移动的摄像头上请调低它，在遗漏缓慢对象的地方请调高它。

仅仅是形状发生变化的框，例如盆栽的框在检测器一会儿包含叶子、一会儿不包含时发生变化，或停着的汽车的框在有东西从前面经过时发生变化，不会被计入。移动必须在多个帧中逐渐累积，而不是一次跳变。

**旧版**是更早的规则：对象的中心在 2 秒内移动了其框大小的一半时即被计入。如果标准模式在某台摄像头上表现异常，请使用它。

一个正在移动的对象如果消失在树、杆子或停着的汽车后面，并在大约 30 个已分析帧（6 fps 时约 5 秒）内从同一条线更远处出来，它仍是同一个对象，因此只会被计一次，并保持一条路径。它还必须是同类对象且大小相近，且在两者都能辨别时颜色也必须匹配。朝其他方向出来，或花了更长时间才出来的对象，则是新对象。

## 移动的对象

每个移动对象穿过画面的路径会随其事件一起保存，用于“活动”页面上的**场景**热力图。

**设置 → AI 检测**下的**移动中的对象**选择哪些类型的对象可以被计为移动。默认是**人**、**车辆**和**动物**。其他任何对象仍会被检测到，并在开启**静止**时显示为静止框，但永远不会被计为移动，因此不会触发快照或警报。请在**其他对象**列表中逐个选择加入其他对象：收到的包裹通常会被识别为手提箱、背包或手提包。对于自定义模型，请输入其自己的对象名称，以逗号分隔。

## 忽略的对象

**设置 → AI 检测**下的**忽略的对象**会完全关闭某些类型的对象。模型一上报它们就会被丢弃，因此它们永远不会获得框、快照、事件或警报。可用于模型在您的摄像头上总是识别错的东西，比如被它认成飞机的露台。可勾选整个类别（**人**、**车辆**、**动物**和**其他对象**）或列表中的单个对象。两种模型的拼写都能匹配，所以忽略 **airplane** 也会忽略 **aeroplane**。对于自定义模型，请输入其自己的对象名称，以逗号分隔。

摄像头的**编辑**页面可以选择自己的列表来代替全局列表：在**忽略的对象**下选择**为此摄像头选择**。在那里不选择任何内容，则该摄像头会检测所有内容，即使全局列表忽略了它们。保存会重启该摄像头的检测，这只会重置跟踪。

## 抖动

**抖动阈值**是无论对象大小，计入移动的最小像素移动量。在旧版模式下，**静止对象抖动抑制**会平滑远处停着的车辆的晃动；它也可能把真正缓慢移动的对象保持为静止，因此默认关闭。它不适用于标准模式，标准模式自己处理晃动。

## 外部后端

**外部 HTTP 服务**不在节点上运行任何模型。每一帧都会发送到您运行的推理服务器，由它以 JSON 返回框。可用于 LarisVMS 未捆绑的模型，或没有 GPU 的节点。跟踪、快照、时间线和实时叠加层的工作方式相同。

该服务必须提供 `POST /v1/detect`、`GET /v1/models` 和 `GET /healthz`。**测试**会检查连接并加载模型列表。**API 密钥**以 Bearer 令牌的形式发送。**传输**：JPEG 适用于任何服务。原始 YUV 和 BGRA 模式会跳过 JPEG 编码，但使用 4–10 倍的带宽，且只有在模型声明支持它们时才有效。
