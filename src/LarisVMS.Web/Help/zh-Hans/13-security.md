# 安全

IP 允许列表、独立的实时/回放端口、严格脚本策略、证书、主机名、更新、加密的密钥，以及面向企业的额外保护。

## 允许列表

**设置 → 安全**有两个 IP 允许列表。每行输入一个 IP 或 CIDR 块（例如 `10.0.0.5` 或 `10.0.0.0/24`）；以 `#` 开头的行是注释。空列表表示允许所有人。

- **管理 / API**：管理页面和 REST API。如果某个列表会拦截您正在保存它的地址，它会被拒绝，因此您不会把自己锁在外面。
- **实时查看 / 回放**：实时视频、回放、缩略图、导出下载和摄像头快照。

## 独立端口

**设置 → 实时查看 → 自定义端口**会将实时和回放流量移到它自己的 HTTPS 端口，使用同一个证书。这样您可以为它单独设置防火墙，或只将它暴露到局域网之外。它在 `Restart-Service LarisVMSWeb` 之后生效。此后，视频只在新端口上响应，其他所有内容只在主端口上响应。清空该字段即可恢复为单一端口。

## HTTP/3

服务器使用 HTTP/2，并在 Windows 11、Windows Server 2022 或更高版本上增加 HTTP/3。浏览器从 HTTP/2 开始，在能够连接时会自行切换到 HTTP/3。HTTP/3 在 HTTPS 端口（以及已设置的自定义端口）上使用 UDP。安装程序会同时开放 TCP 和 UDP；对于较旧的安装，请为该端口添加一条 UDP 规则，或再次运行当前的安装程序。在此之前，一切仍通过 HTTP/2 正常工作。要关闭 HTTP/3，请取消勾选**设置 → 安全 → HTTP/3**，然后运行 `Restart-Service LarisVMSWeb`。

## 严格脚本策略

开启**设置 → 安全 → 严格脚本策略**后，浏览器只运行此服务器发送的脚本，因此注入页面的脚本无法运行。它默认开启，升级也会将其开启。如果某些功能停止工作，请将其关闭：浏览器随后会上报严格策略原本会拦截的所有内容，最新的报告会显示在开关下方。当您使用过所依赖的页面后不再出现任何报告时，请再次开启它。更改在下次加载页面时生效。

## 证书

服务器的证书是在 `appsettings.Production.json` 中设置的 `.pfx` 文件。续期后的文件会在一分钟内被采用，无需重启。使用直连流媒体的节点在节点页面上有自己的证书设置。

## 摄像头证书

通过 HTTPS 访问的摄像头使用自签名证书，无法对照任何东西进行校验，因此默认接受任何证书。开启**设置 → 安全 → 固定摄像头证书**后，服务器会在首次连接时记住每个摄像头地址的证书，此后无论在服务器上还是节点上，都拒绝不同的证书。这样，网络上冒充摄像头的设备就无法获取其密码或发送虚假事件。

已记住的证书列在该设置下方。如果某台摄像头的证书确实发生了变化（固件更新、重置或新证书），请选择其地址旁边的**忘记**；它下次出示的证书会被记住。在此之前，服务器或节点上每次被拒绝的连接都会被记录到审计日志，并通知超级管理员（每个摄像头地址每小时最多一次），因为网络上可能有设备在冒充该摄像头。摄像头地址在服务器首次访问它时被记住，通常是在添加摄像头时；节点会接受服务器尚未访问过的地址。

## 主机名

默认情况下，服务器会响应浏览器使用的任何主机名，因此通过 IP 地址、短名称和完整名称都可以访问。若要只响应您使用的名称，请在 `appsettings.Production.json` 中将 `AllowedHosts` 设置为这些名称，以分号分隔（例如 `"AllowedHosts": "vms.example.com;vms;localhost"`），然后运行 `Restart-Service LarisVMSWeb`。请包含节点、代理和人员用来访问它的每个名称：其他任何名称都会出错。

在反向代理（IIS ARR、nginx 等）之后，请将其地址在 `appsettings.Production.json` 中列为 `"ReverseProxy": { "KnownProxies": [ "10.0.0.2" ] }`，然后重启。服务器随后会从该代理的 `X-Forwarded-For` 和 `X-Forwarded-Proto` 标头获取客户端的真实地址和协议方案，因此允许列表和审计日志看到的是本人，而不是代理。来自不在列表中的任何来源的这些标头会被忽略，而在列表为空时则完全忽略。

## 更新

这些检查介于下载和正在运行的安装之间：

- **发布版下载**附带 `SHA256SUMS.txt`。运行安装程序之前，用 `Get-FileHash <file> -Algorithm SHA256` 检查它并与该文件对应的行比较，或运行 `sha256sum -c SHA256SUMS.txt`。当安装程序经过代码签名时，Windows 还会显示发布者。
- **节点和代理的更新**由此服务器的签名密钥签名。节点或代理会保留其注册时的那个密钥，并且即使它与服务器的连接被篡改，也不会安装任何未用该密钥签名的内容。它还会拒绝不比正在运行的版本更新的版本。参见[安装](/Help/installation#updates)。
- **发布者签名**（可选）：使用发布者密钥（`-PublisherKeyPath`）构建的节点或代理，还要求每个更新都带有发布者签名；其他版本会跳过此检查。该密钥保存在离线环境，绝不会放在服务器上，因此即使服务器被入侵，也无法把它自己的代码推送到节点。
- 与服务器的**连接**按**节点 → 更新与注册 → 服务器证书检查**中的设置进行检查（参见[节点](/Help/nodes#server-certificate)）。

## 加密的密钥

摄像头凭据、SMB 凭据、节点密钥、电子邮件密钥、Entra 客户端密钥和 Active Directory 服务账户的密码，使用 `%ProgramData%\LarisVMS\keys` 中的数据保护密钥加密后存放在数据库中。只有 SYSTEM、Administrators 和 LarisVMS 服务的账户才能打开 `%ProgramData%\LarisVMS`：在那里发现的任何其他访问权限，例如本地用户在安装 LarisVMS 之前创建的文件夹，会在服务启动时被移除。请备份该文件夹，并且在部署期间绝不要删除它。

## 面向企业的额外保护

开箱即用时，LarisVMS 的设置能让家庭安装直接运行。下面的所有内容都是可选的，并且默认关闭；请开启适合企业或可从互联网访问的服务器的项目：

- **要求两步验证登录**：设置 → 安全（参见[两步验证登录](/Help/users#two-factor-sign-in)）。
- **管理页面需确认密码**：设置 → 安全（参见[会话](/Help/users#sessions)）。
- **管理员设置的临时密码**：设置 → 安全（参见[密码](/Help/users#passwords)）。
- **更短的会话和空闲超时**：设置 → 角色下的每个角色（参见[角色](/Help/users#roles)）。
- **固定摄像头证书**：设置 → 安全（参见[摄像头证书](#camera-certificates)）。
- **允许列表**：设置 → 安全（参见[允许列表](#allow-lists)）。
- **对所有其他计算机要求安装令牌**：在运行安装向导之前，在 `appsettings.Production.json` 中设置 `"Setup": { "AlwaysRequireToken": true }`（参见[安装](/Help/installation#web-server)）。
- **安装节点或代理时固定服务器证书：**`-ServerCertThumbprint`（参见[服务器证书](/Help/nodes#server-certificate)）。
- **一次性注册代码，并关闭共享密钥**：节点 → 更新与注册（参见[一次性注册代码](/Help/nodes#one-time-registration-codes)）。
- **从服务器到节点的加密连接**：在每个节点的页面上（参见[来自服务器的加密连接](/Help/nodes#encrypted-connections-from-the-server)）。
- **将审计日志转发到 syslog**：设置 → 日志（参见[审计日志](/Help/users#audit-log)）。
- **由发布者签名的更新**，适用于您自己构建的版本（参见[更新](#updates)）。
- **权限更低的服务账户。** LarisVMS 服务以 LocalSystem 运行。您可以使用其他账户来运行它们（`services.msc` 或 `sc.exe config`），但此后需要您自己为该账户提供服务所需的内容：安装文件夹、每个存储和归档文件夹或共享，以及证书文件。`%ProgramData%\LarisVMS` 由系统为您处理：每个 LarisVMS 服务在启动时都会将其限制为 SYSTEM、Administrators，以及 LarisVMS 服务运行所用的账户，并移除那里的任何其他访问权限。更改之后请检查服务的日志。
