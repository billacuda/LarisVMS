# 用户与访问

账户、角色、权限、摄像头访问、Active Directory 和 Microsoft 登录。

## 用户

自助注册已关闭。账户在**设置 → 用户**下创建，您还可以在那里分配角色、禁用账户和重置密码。本地账户使用其电子邮件地址登录。禁用账户会立即使其在所有地方退出登录，并关闭其实时视频。

## 密码

密码至少 12 个字符。常见的密码、类似 `123456789012` 的密码，以及包含本人姓名或电子邮件地址的密码都会被拒绝。若要拒绝更多密码，请将它们放入 Web 服务器上的 `%ProgramData%\LarisVMS\password-blocklist.txt`，每行一个（可以使用已公开的泄露密码列表）。无需重启即可生效。

拥有本地账户的人通过选择页面顶部的自己的姓名来更改自己的密码。需要输入当前密码，并且其他所有会话都会退出登录。管理员也以同样的方式更改自己的密码，而不是在**设置 → 用户**下。Active Directory 账户在 Windows 中更改密码。

在**设置 → 用户**下创建账户或重置密码时，您可以勾选**下次登录时必须更改**。此后，该用户必须先选择自己的密码，才能做其他任何事情。开启**设置 → 安全 → 管理员设置的临时密码**时，它默认已勾选。

同一个账户在 15 分钟内从同一个地址输错 5 次密码后，该地址必须等待这 15 分钟；本人仍然可以从其他任何地方登录。只有在来自任何地方的错误尝试达到 20 次后，账户才会被锁定 15 分钟，并且超级管理员永远不会因登录时输错密码而被锁定。超级管理员会收到重复失败和锁定的通知，以及分散在多个网络上的猜测通知：15 分钟内，一个账户从 3 个或更多网络失败 10 次，或整个服务器从 10 个或更多网络失败 50 次。

## 两步验证登录

任何使用密码（本地或 Active Directory）登录的人，还可以要求输入手机上验证器应用（Microsoft Authenticator、Google Authenticator、1Password 等）生成的六位数验证码。每个验证码只能使用一次，因此被人看到输入的验证码无法再次使用。要进行设置，请选择页面顶部的您的姓名，然后选择**两步验证登录**，扫描二维码，并输入应用显示的验证码。您会得到十个恢复码；请将它们保存在安全的地方，因为如果您丢失手机，每个恢复码可用于登录一次。之后更改任何内容，例如生成新的恢复码或将其关闭，都需要当前的验证码。

登录时，**在此浏览器上 14 天内不再询问**会在该浏览器上跳过验证码，直到密码或两步验证设置发生变化。

如果有人同时丢失了手机和恢复码，**设置 → 用户**下其旁边的**关闭两步验证**，可让他们仅用密码登录并重新设置。

**设置 → 安全 → 要求两步验证登录**会让每个使用密码登录的人必须先设置它才能做其他事情，并阻止他们将其关闭。Microsoft 登录交由 Entra 自己的检查处理。

## 会话

选择页面顶部的您的姓名，然后选择**会话**，即可查看您已登录的每个浏览器，以及其地址和上次使用时间。退出您不认识的会话，或除当前使用的会话之外的所有会话，然后更改您的密码。更改密码或开启两步验证登录会立即使您的其他会话退出登录。

开启**设置 → 安全 → 管理页面需确认密码**后，除非您在最近 15 分钟内登录或确认过，否则管理页面会再次要求输入您的密码（开启两步验证登录时还有验证码）；使用管理页面会使这一状态持续。这样，发现您的浏览器仍处于登录状态的人可以使用系统，但无法更改其设置、用户或密钥。Microsoft 登录则改为重新登录。默认关闭。

在**设置 → 用户**下，某人旁边的**退出登录**会使其在每个浏览器上退出。他们可以重新登录；若要阻止他们，请禁用账户。

## 角色

角色是一组命名的权限，在**设置 → 角色**下管理。每个角色还有：

- 一个**范围层级**；
- 用于限时访问的**有效期**（例如 8 小时班次为 480 分钟）；
- **会话有效期**：用户登录后，无论多活跃，需要重新登录之前的小时数（最长 30 天，或 0 表示永不过期）；
- **空闲超时**：用户在没有打开任何页面的情况下被退出登录之前的分钟数（0 表示关闭）。显示着实时视频的屏幕也算空闲，因此对于观看视频墙的角色请将其关闭；
- **云台优先级**，用于决定两个用户移动同一台摄像头时谁优先。

## 权限

**设置 → 权限矩阵**设置每个角色被允许执行的操作（查看摄像头、回放、导出、编辑设置等）。内置的**超级管理员**角色始终拥有全部权限。

**开始和停止手动录制**控制实时磁贴上的录制按钮。它还需要下面的**录制**摄像头访问权限。

## 摄像头访问

**设置 → 摄像头访问**决定每个角色可以使用哪些摄像头：所有摄像头、某个分组或单台摄像头，并针对查看、回放、导出、云台、通话（双向音频）、配置和录制（手动录制）分别设置。**没有授权的角色没有任何摄像头**；超级管理员始终拥有所有摄像头。导出的范围永远不会超过回放。从没有授权的角色也可以使用所有摄像头的版本升级时，会添加一个“所有摄像头”授权，以保持每个角色和用户的访问权限不变。

## API 密钥

**管理 → API 密钥**签发用于 [API](/Help/api) 的密钥。每个密钥以其绑定的角色运行，并且可以限制为该角色权限的一部分，因此多个密钥可以做不同的事情。密钥可以使用哪些摄像头由角色的摄像头访问权限决定。

## Entra

**设置 → 安全 → Entra ID 登录**会添加一个“使用 Microsoft 登录”按钮。它从不创建账户，也不按电子邮件匹配账户：在**设置 → 用户**中，使用某人所在行的 **Microsoft 登录**输入其 Entra **对象 ID**（来自 Microsoft Entra 管理中心中其用户页面）。他们首次通过 Microsoft 登录时即完成关联；留空则移除关联。请使用安全页面上显示的重定向 URI 在 Entra 中注册一个应用，然后输入其租户 ID（您目录的 GUID 或域，不是 `common`）、客户端 ID 和密钥。更改立即生效。已关联的账户继续可用。

## Active Directory

**设置 → Active Directory**允许域用户使用其 AD 用户名和密码登录，并根据其 AD 组赋予他们角色。只有超级管理员才能更改域、LarisVMS 连接到它的方式或本地登录，因为这些设置决定了谁可以以任何人的身份登录；其他管理员可以更改同步间隔和组关联。

- **域**：只需域名，例如 `corp.example.com`。
- **加密**：默认是端口 636 上的 LDAPS，需要域控制器上有此服务器信任的证书。端口 389 上的普通 LDAP 无需证书即可使用，但它不安全，不建议使用。
- **查询账户**：集成安全（默认）使用 LarisVMS Web 服务自己的账户。当服务在已加入域的服务器上以 LocalSystem 运行时，就是计算机账户。或者以 `DOMAIN\username` 的形式输入服务账户及其密码。
- **登录**：带有 `@` 的名称是本地账户。其他的都是 AD 用户名，输入时不带域。

**组 → 角色关联**：开始输入组名并从列表中选择（Tab 键选择第一个匹配项）。组的成员（包括嵌套组的成员）会获得该角色。账户在首次需要时创建，即组被关联后立即创建，或用户首次登录时创建。组和用户按 SID 跟踪，因此在 AD 中重命名任何一个，都会在下次同步时延续。AD 账户的角色只来自组关联，无法在“用户”页面上编辑。

**同步**默认每 30 分钟运行一次（5 分钟到 24 小时），或用**立即同步**马上运行。在 AD 中被禁用或已过期，或不再属于任何已关联组的 AD 账户，会在这里被禁用并退出登录。如果无法连接到 AD，同步不会更改任何内容，并在 5 分钟后重试。因同步而被禁用的账户在再次符合条件时会重新启用。在“用户”页面上手动禁用的账户则保持禁用。

当 AD 登录开启，并且至少有一个 AD 账户拥有超级管理员角色之后，可以关闭**本地登录**。请把安装时创建的超级管理员账户及其密码保存在安全的地方。如果 AD 变得不可用，请对 LarisVMS 数据库运行以下命令，并使用该账户登录。在 SQL Server 上：

```sql
UPDATE ActiveDirectorySettings SET LocalLoginsEnabled = 1
```

在 MariaDB 上：

```sql
UPDATE `ActiveDirectorySettings` SET `LocalLoginsEnabled` = 1;
```

## 审计日志

用户所做的一切都记录在**日志 → 审计日志**下：更改（含旧值和新值；密钥仅记录为“已更改”）、查看摄像头、开始回放和导出。

**防篡改。** 每个条目都与它前面的条目一起，使用仅靠数据库本身无法持有的密钥进行密封。每 6 小时（以及当您在审计日志页面上选择**立即检查**时），会检查整个日志。如果某个条目被更改、移除或直接添加到数据库中，页面会指出是哪一个，并通知超级管理员。因保留策略而被移除的条目属于预期情况，不计在内，并且每次移除本身也会被记录（**AuditLog.Pruned**）。此次更新之前的条目不在涵盖范围内。

服务器还在 `%ProgramData%\LarisVMS\audit-chain.dat` 中，于数据库之外保留一份小记录，记载了密封密钥以及日志的起点，这样日志就无法用另一个密钥重新密封，也无法被清空并重新开始而不被发现。如果您有意在同一服务器上以新的空数据库重新开始，请删除该文件一次；下一个条目会生成一个新文件。

**转发到 syslog。** 若要在服务器之外保留审计日志的副本，请在**设置 → 日志**下输入 syslog 服务器。每个新条目在写入时都会发送（RFC 5424，设施为 *log audit*，条目为 JSON）。可选择 UDP、TCP 或 TLS。TLS 要求 Web 服务器信任 syslog 服务器的证书。如果无法连接到 syslog 服务器，条目会被保留，并在其恢复后发送。转发从下一个条目开始，而不是现有历史记录。只有超级管理员才能更改日志的转发位置或关闭转发；该更改本身会先发送到旧的目的地。
