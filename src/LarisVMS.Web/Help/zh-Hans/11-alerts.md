# 警报、通知和电子邮件

警报规则、发送给用户的通知、团队渠道和电子邮件提供商设置。

## 警报规则

**设置 → 警报**中保存共享规则。每条规则监视一个条件：

- **摄像头未上报**：摄像头已停止发送健康报告。
- **节点离线**：节点已停止签到。
- **存储空间不足**：可用空间已降至某个百分比以下。
- **节点故障转移**：某个节点的摄像头已移到其备用节点。
- **检测到移动**：摄像头上或其某个移动侦测区域中的移动。
- **检测到对象**：AI 检测发现了匹配的对象。
- **速度超过限制**：对象以达到或超过设定速度的速度越过了[测速点](/Help/ai-detection#speed-traps)。
- **证据锁定即将结束**和**证据锁定已移除**：参见[证据锁定](/Help/live-and-playback#evidence-locks)。

健康规则每分钟检查一次。**冷却时间**是重复警报之间的最短间隔，因此持续成立的条件不会每分钟都发出警报。

### 检测警报

**检测到对象**和**速度超过限制**会在检测后数秒内触发。每个过滤器都是可选的，您设置的所有过滤器必须同时匹配：

- **摄像头**：一台摄像头、某个节点上的摄像头，或任意摄像头。
- **类别**和**标签**：例如车辆，或仅卡车。
- **颜色**：对象的颜色，或人的上衣或裤子的颜色。参见[对象颜色](/Help/ai-detection#object-colors)。
- **区域**：仅限站在摄像头某个区域内的对象（以框的底部判断）。
- **生效时间**：星期几和时间段，采用保存该规则的人所在的时区。像 22:00 到 06:00 这样的时间段会跨夜运行。

一次检测只会发出一次警报。在监视多台摄像头的规则上，冷却时间对每台摄像头分别计算，因此繁忙的摄像头不会拖延其他摄像头。

### 移动侦测警报

**检测到移动**会在移动后数秒内触发，来自服务器的移动检测或摄像头自身的移动事件。选择一台摄像头、某个节点上的摄像头，或任意摄像头。选择了一台摄像头时，**区域**可将其限制为该摄像头的某个**服务器移动侦测**区域；保持**（整个摄像头）** 则表示任何位置的移动。**生效**的日期和时间与检测警报的工作方式相同。一段持续的移动只会发出一次警报，并由冷却时间挡住下一次。

### 团队渠道

每条规则还可以发送到电子邮件列表、Webhook、ntfy、Pushover、Slack 和 Teams。开启一个渠道并填写其字段。

## 通知

通知会发送给个人，通过其浏览器或电子邮件，而不是发送到团队渠道。每个人在侧边栏的**通知**（也就是您姓名旁边的 🔔）下选择自己想要的内容。通知只会针对某人可以查看的摄像头送达。

- **共享通知**：在警报规则上，**允许用户订阅**会将其列在**我的通知 → 可用**下，任何人都可以开启。管理员也可以在规则的**订阅者**下添加某个用户，或某个角色中的所有人。
- **您自己的通知**：**我的通知 → 我的 → 新通知**可以仅为您自己创建一个，选项与警报规则相同。例如，晚上 10 点到早上 6 点之间后院摄像头里的动物。只有您能看到它。
- 可以将通知**静音**一小时、8 小时、一天，或直到您重新开启，而无需取消订阅。

**设置 → 通知**为用户开启或关闭每一类通知。关闭某一类并不会阻止警报规则上的团队渠道。

订阅需要**订阅共享通知**权限，创建自己的通知需要**创建个人通知**权限。每个角色默认都有这两项。

### 浏览器通知

在每个浏览器中，于**我的通知 → 此浏览器和设备**下开启它们，然后使用**发送测试**。**设置 → 通知**选择它们的发送方式：

| 发送方式 | 适用场景 | 需要 |
|---|---|---|
| **LarisVMS 打开期间** | 已打开 LarisVMS 标签页或已安装的应用 | 无。保持在您的网络内。 |
| **Web 推送** | 没有打开任何 LarisVMS 页面（Chrome、Edge、Firefox 和 Safari）。在计算机上，浏览器本身必须正在运行；见下文 | 一次**生成 Web 推送密钥**，以及从服务器到浏览器厂商推送服务的出站互联网访问。无需账户。 |
| **Firebase Cloud Messaging** | 没有打开任何 LarisVMS 页面，在计算机上有同样的限制 | 您自己的 Firebase 项目：其 Web 应用配置、Web 推送证书和服务账户密钥。仅在 Web 推送关闭时使用。 |

没有显示通知的权限时，通知会改为显示在打开的 LarisVMS 页面内。在手机上，请先将 LarisVMS 安装为应用（参见[概览](/Help/overview)）。

即使浏览器已关闭，手机也能收到推送通知。在计算机上，浏览器只有在运行时才能收到，而关闭其最后一个窗口通常会使其退出；这期间发送的内容会在它重新启动时显示。若要让它在后台保持运行，请开启**关闭 Google Chrome 后继续运行后台应用**（Chrome：设置 → 系统）或**关闭 Microsoft Edge 后继续运行后台扩展程序和应用**（Edge：设置 → 系统和性能）。对于需要在没有浏览器运行的情况下收到警报的人，请使用电子邮件。

### 电子邮件通知

人们也可以为通知选择电子邮件。它会通过下面设置的电子邮件，发送到其账户上的地址。**设置 → 通知**可以关闭电子邮件通知。

## 电子邮件

电子邮件警报和通知通过**设置 → 电子邮件**下设置的提供商发送。**保存并发送测试**会检查已保存的设置。

- **SMTP**：主机、端口、SSL/TLS 和凭据。
- **Microsoft Graph**：在 Entra ID 中注册一个应用，授予它 `Mail.Send` **应用程序**权限（不是委派权限）并获得管理员同意，然后输入其租户 ID、客户端 ID 和密钥。没有按用户的登录。
- **Gmail**：在 Google Cloud 中创建类型为 *Web 应用*的 OAuth 客户端。将 `https://<your-host>/Admin/OAuthCallback` 添加为已获授权的重定向 URI，并启用 `https://mail.google.com/` 范围。然后使用一次**保存并连接到 Google**来授予同意。

保存的密钥会被加密。如果服务器的数据保护密钥丢失，请重新输入它们，并重新连接 Gmail。
