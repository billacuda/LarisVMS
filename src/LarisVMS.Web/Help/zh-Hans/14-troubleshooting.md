# 故障排除

常见问题，以及该去哪里查看。

## 日志在哪里

- **服务器**：**日志 → 系统日志**。在**设置 → 日志**下设置级别和保留期。Debug 和 Trace 会增加细节，但会产生很大的文件。
- **摄像头事件日志**：摄像头发送的原始事件，仅用于列出摄像头的事件主题以设置事件标签。默认保留 30 天（**设置 → 日志**，0 表示永久保留）；清除它们不会影响事件、快照或录像。
- **数据库维护**：每晚大约凌晨 3 点，服务器会整理数据库的索引和统计信息，并记录一行说明它做了什么。如果其数据库登录没有权限，则改为记录一条警告。在 MariaDB 上会跳过此操作；MariaDB 自行维护统计信息。
- **节点**：每个节点上的 `%ProgramData%\LarisVMS\logs\node-*.log`。
- **AI 检测**：每个节点上的 `%ProgramData%\LarisVMS\logs\vision-*.log`。
- **自动更新**：每个节点或代理上的 `%ProgramData%\LarisVMS\logs\updater-*.log`。

## 摄像头没有在录制

1. 它是否已**分配到节点**，并且该节点是否**在线**？
2. 该节点是否有**存储路径**？节点列表会标出没有存储路径的节点。
3. 摄像头是否**已启用**，其码流看起来是否正常？在摄像头本身做了任何更改之后，请**重新探测**。
4. 在移动侦测、计划或事件模式下，检查录像是否被丢弃（参见[录制](/Help/recording#modes)）。

## 实时查看和回放一直停在“正在连接”

当节点直接向浏览器传输流媒体时（参见[直连流媒体](/Help/nodes#direct-streaming)），浏览器会连接到节点的客户端端口，默认为 4200。如果浏览器控制台显示 `wss://<node>:<port>/live/…` 连接失败，请检查节点的防火墙是否允许该端口：安装程序会创建一条名为 **LarisVMS Node Client Endpoint** 的入站规则。0.215.1 之前的安装程序在升级或接管节点时可能会丢失该规则；请再次运行当前的节点安装程序，或手动添加该规则。

## Active Directory 登录或同步失败

使用**设置 → Active Directory** 下的**测试连接**；上次同步的错误会显示在同一页面上。

- **无法连接到域控制器**：检查域名能否从服务器解析，以及端口 636（LDAPS）或 389（LDAP）是否对域控制器开放。使用 LDAPS 时，域控制器需要有此服务器信任的证书。
- **服务器自身的身份被拒绝**：只有当 LarisVMS Web 服务运行在已加入域的服务器上，并以 LocalSystem 或域账户运行时，集成安全才起作用。否则请使用服务账户。
- **“不在任何有访问权限的组中”**：用户登录正确，但不在任何已关联的组中。组是按安全组匹配的，包括嵌套的组。
- **关闭本地登录后被锁在管理页面之外**：参见 [Active Directory](/Help/users#active-directory)，其中有重新将其开启的数据库命令。

## 后台窗口中的实时查看暂停

Chrome 会限制不可见的窗口，因此第二个显示器上的实时墙可能会卡住，然后再追赶上来。实时查看会自行恢复。要避免这种情况，请把下面的内容添加到 Chrome 快捷方式的目标中：

```
--disable-backgrounding-occluded-windows --disable-background-timer-throttling
```

## 所有磁贴都卡住，然后一起重新连接

是节点停滞了，不是浏览器或网络。请在节点日志中查找 `Node process health: tick … ms late`。正常的节点大约每分钟记录一次，延迟只有个位数毫秒。

- 如果 `gcPauseMs` 接近延迟，原因是垃圾回收。
- 如果 `gcPauseMs` 很小但 `pendingWorkItems` 达到几十，则线程被阻塞。请在其停滞期间抓取转储：`dotnet-dump collect -p <LarisVMS.Node pid>`。

## AI 检测停止，但录制继续

通常是 GPU 驱动程序被重置了。Windows 系统事件日志会在那一刻显示 `nvlddmkm` 事件 153 或 `Display` 事件 4101。视觉服务在 60 秒没有结果后会自行重启。反复重置说明问题出在 GPU、其驱动程序、散热或电源上。

## 更新后节点或代理没有恢复

启动其服务（`sc start LarisVMSNode` 或 `LarisVMSProxy`），然后检查 `updater-*.log`，了解重启失败的原因。已下载但从未应用的更新，也会在节点或代理下次启动时记录到其自身的日志中，并在之后的签到中再次提供。

## 节点显示“时钟”

节点的时钟与服务器的时钟相差超过一分钟。请修复其时间同步。时钟偏差会影响计划和时间线。

## 节点一直签到失败

使用节点 **⋯** 菜单中的**重置认证**。它会清除节点的签到令牌，节点将在下次心跳时重新同步。
