# 노드

녹화 노드: 상태, 스트리밍 경로, 미디어 프록시, 장애 조치, 유지 관리, 업데이트를 설명합니다.

사이드바의 **노드**에는 모든 노드가 상태, 주소, 버전, 카메라 수, 디스크 사용량과 함께 나열됩니다. 노드를 클릭하면 설정을 편집할 수 있습니다. **⋯** 메뉴에는 다음 작업이 있습니다.

- **서비스 다시 시작**: 노드의 Windows 서비스를 다시 시작하며 컴퓨터는 다시 시작하지 않습니다. 녹화가 몇 초 동안 일시 중지됩니다.
- **인증 초기화**: 노드의 체크인 토큰을 지웁니다. 하트비트를 놓친 후 인증에 계속 실패하는 노드용입니다. 정상 노드에는 영향이 없습니다.
- **유지 관리**: 유지 관리를 끌 때까지 노드의 카메라를 백업 노드로 옮깁니다.
- **삭제**: 노드를 삭제합니다. 해당 카메라는 할당이 해제됩니다. 녹화는 삭제되지 않습니다.

노드는 최근 2분 이내에 체크인했으면 **온라인**입니다. ⚠️ **시계** 경고는 노드의 시계가 서버 시계와 1분 넘게 어긋나 있다는 뜻이므로 시간 동기화를 확인하십시오.

## 직접 스트리밍

기본적으로 모든 라이브 및 재생 영상은 웹 서버를 통해 중계됩니다(**프록시**). **직접**으로 하면 브라우저가 각 노드 자체의 HTTPS 엔드포인트에 바로 연결되어 서버의 부하가 줄어듭니다. 모드는 **설정 → 라이브 보기**에서 설정하며 노드별로 재정의할 수 있습니다.

직접 모드에는 브라우저가 접근할 수 있는 **클라이언트 엔드포인트 호스트**와 인증서(노드 페이지의 `.pfx` 경로)가 필요합니다. **자체 서명 허용**은 테스트 전용입니다. 보는 사람에게 브라우저 경고가 표시되기 때문입니다. 노드에 정상 엔드포인트가 없는 카메라는 자동으로 프록시로 대체됩니다.

## 서버에서의 암호화된 연결

서버와 미디어 프록시는 노드의 영상 및 제어 경로에 라이브 포트(8554)의 일반 HTTP로 접속하며, 신뢰할 수 있는 네트워크에서는 문제없습니다. 이 트래픽을 암호화하려면 노드 페이지에서 **서버에서의 연결 암호화**를 켠 다음 노드를 한 번 다시 시작하십시오(**다시 시작**). 노드가 HTTPS 엔드포인트를 시작하고(`.pfx`가 없으면 자체 서명 인증서 사용) 인증서를 보고하면, 서버가 그 인증서를 고정합니다. 서버와 프록시는 노드로부터 그 인증서만 수락하며, 미디어 토큰은 더 이상 주소의 일부가 아닙니다. 암호화되면 노드의 일반 포트는 `/health`에만 응답합니다.

노드 페이지의 **암호화됨** 열에는 암호화된 각 노드에 🔒가, 켜 놓았지만 아직 다시 시작이 필요한 노드에는 ⏳가 표시됩니다. 스위치 아래의 상태에는 사용 중인 인증서 또는 서버가 아직 인증서를 기다리고 있다는 내용이 표시됩니다(그때까지 서버는 일반 HTTP를 계속 사용하므로 작동이 멈추는 것은 없습니다). 기본값은 꺼짐입니다. 이를 위해 사용되는 자체 서명 인증서는 브라우저에 제공되지 않습니다. 직접 스트리밍에는 여전히 정식 인증서가 필요합니다.

## 프록시

**미디어 프록시**는 원격 사이트나 저대역폭 회선을 위해 브라우저와 노드 사이에 두는 별도의 중계(`LarisVMS.Proxy`)입니다. 프록시는 **설정 → 미디어 프록시**에서 등록한 다음 각 노드의 페이지에서 기본 프록시와 백업 프록시를 선택합니다. 브라우저는 정상인 첫 번째 것을 사용합니다.

## 장애 조치

노드에 **백업 녹화 노드**를 지정하면, 노드가 다운되었을 때 복구될 때까지 백업이 해당 카메라를 녹화합니다. "다운"은 노드의 파트너, 서버, 프록시의 투표로 결정됩니다. **유지 관리**는 의도적으로 카메라를 옮기고 그곳에 유지합니다.

백업의 AI 하드웨어가 다르거나 녹화 전용이면 노드 페이지에 경고가 표시됩니다. 이 경우 장애 조치 중에 감지가 느려지거나 일시 중지될 수 있습니다.

## 업데이트

노드와 프록시는 승인된 빌드에서 스스로 업데이트됩니다([설치](/Help/installation#updates) 참조). **노드 → 업데이트 및 등록 → 자동 업데이트**로 모든 노드에 대해 켜거나 끕니다.

노드 페이지의 **빌드** 섹션에는 각 종류의 노드가 목표로 하는 빌드와 승인을 기다리는 빌드가 **승인** 및 **거부**와 함께 표시됩니다. **빌드 기록**에는 승인됨, 대체됨, 거부됨을 포함한 모든 빌드가 나열됩니다.

## 서버 인증서

**노드 → 업데이트 및 등록 → 서버 인증서 확인**은 노드와 프록시가 이 서버의 HTTPS 인증서를 확인하는 방식을 결정합니다.

- **처음 사용 시 신뢰**(기본값): 신뢰할 수 있는 CA의 인증서는 갱신되거나 교체된 것을 포함하여 항상 작동합니다. 자체 서명 인증서는 노드가 처음 연결할 때 기억되며 같은 상태인 동안에는 만료일이 지나도 계속 작동합니다. 변경되면 노드와 프록시는 다시 등록될 때까지 이를 거부합니다.
- **신뢰할 수 있는 인증서만**: 서버의 이름과 일치하는 신뢰할 수 있는 CA의 인증서만 허용합니다. 이것을 선택하기 전에 설치하십시오.
- **확인 안 함**: 모든 인증서. 안전하지 않습니다. 네트워크 경로상의 누구든 서버를 사칭할 수 있습니다.

처음 사용 시 신뢰에서는 노드가 처음 연결할 때 본 인증서를 무엇이든 신뢰합니다. 첫 연결부터 확인하게 하려면 **서버 인증서 확인** 아래에 표시된 지문을 설치 프로그램에 전달하십시오. `install-node.ps1`과 `install-proxy.ps1`에는 `-ServerCertThumbprint`, MSI에는 `SERVERCERTTHUMBPRINT=`입니다. 설정 및 미디어 프록시 페이지의 설치 명령에는 이미 포함되어 있습니다. 리버스 프록시 뒤에서는 대신 리버스 프록시가 제시하는 인증서의 지문을 사용하십시오.

서버가 스스로 만드는 자체 서명 인증서는 10년간 유효하며 저절로 교체되지 않습니다. **자체 서명 인증서 다시 생성**으로 교체할 수 있지만, 그러면 모든 노드와 프록시를 다시 등록해야 하며 노드 페이지에는 그 이후 체크인하지 않은 항목이 나열됩니다. 노드를 다시 등록하려면 노드 설치 프로그램을 다시 실행하거나, 노드에서 `LarisVMS.Node.exe --reset-server-pin`을 실행하고 서비스를 다시 시작하십시오(프록시에도 같은 옵션이 있습니다).

## 일회용 등록 코드

새 노드와 프록시는 공유 **등록 키** 또는 일회용 코드로 등록합니다. 일회용 코드는 노드 또는 프록시 하나만 등록하고 사용할 수 없게 됩니다. 사용하지 않으면 1시간, 24시간 또는 7일 후 만료됩니다. 만들려면 **노드 → 업데이트 및 등록**에서 유효 기간을 선택하고 **코드 만들기**를 선택하십시오. 코드는 한 번만 표시됩니다. 설치 프로그램이 등록 키를 요구하는 곳에 사용하십시오. **해지**는 아직 사용되지 않은 코드를 취소합니다.

공유 키는 변경하기 전까지 모든 설치에 작동합니다. 일회용 코드를 쓰게 되면 **공유 등록 키 허용**을 해제하여 오래된 스크립트나 이메일에 있는 키 사본으로 아무것도 등록할 수 없게 하십시오. 이미 등록된 노드와 프록시는 영향을 받지 않습니다. 어느 쪽이든 새 노드는 카메라를 받기 전에 승인을 기다립니다.
