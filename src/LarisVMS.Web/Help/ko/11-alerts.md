# 알림, 알림 설정, 이메일

알림 규칙, 사용자에 대한 알림, 팀 채널, 이메일 공급자 설정을 설명합니다.

## 알림 규칙

**설정 → 알림**에는 공유 규칙이 있습니다. 각 규칙은 하나의 조건을 감시합니다.

- **카메라가 보고하지 않음**: 카메라가 상태 보고 전송을 멈췄습니다.
- **노드 오프라인**: 노드가 체크인을 멈췄습니다.
- **저장소 부족**: 여유 공간이 일정 비율 아래로 떨어졌습니다.
- **노드 장애 조치**: 노드의 카메라가 백업 노드로 옮겨졌습니다.
- **모션 감지됨**: 카메라 또는 그 모션 영역 중 하나에서의 모션.
- **객체 감지됨**: AI 감지가 일치하는 객체를 보았습니다.
- **제한 초과 속도**: 객체가 [속도 측정](/Help/ai-detection#speed-traps)을 설정한 속도 이상으로 통과했습니다.
- **증거 잠금 종료 임박**과 **증거 잠금 해제됨**: [증거 잠금](/Help/live-and-playback#evidence-locks)을 참조하십시오.

상태 규칙은 1분에 한 번 확인됩니다. **재알림 대기 시간**은 반복 알림 사이의 최소 시간으로, 조건이 계속 참이어도 매분 알리지 않게 합니다.

### 감지 알림

**객체 감지됨**과 **제한 초과 속도**는 감지 후 몇 초 이내에 발동합니다. 모든 필터는 선택 사항이며 설정한 것이 모두 일치해야 합니다.

- **카메라**: 카메라 하나, 노드 하나의 카메라, 또는 모든 카메라.
- **범주**와 **레이블**: 예를 들어 차량, 또는 트럭만.
- **색상**: 객체의 색상 또는 사람의 셔츠나 바지 색상. [객체 색상](/Help/ai-detection#object-colors)을 참조하십시오.
- **영역**: 카메라의 영역 중 하나 안에 서 있는 객체만(상자의 아래쪽으로 판단).
- **활성**: 요일과 시간대이며 규칙을 저장한 사람의 시간대로 판단합니다. 22:00부터 06:00 같은 시간대는 밤새 실행됩니다.

감지 하나당 알림은 한 번입니다. 여러 카메라를 감시하는 규칙에서는 재알림 대기 시간이 카메라별로 따로 계산되므로, 바쁜 카메라가 다른 카메라를 막지 않습니다.

### 모션 알림

**모션 감지됨**은 서버의 모션 감지 또는 카메라 자체 모션 이벤트에 의한 모션 후 몇 초 이내에 발동합니다. 카메라 하나, 노드 하나의 카메라, 또는 모든 카메라를 선택하십시오. 카메라 하나를 선택하면 **영역**으로 해당 카메라의 **서버 모션** 영역 중 하나로 제한할 수 있습니다. 어디서든 모션을 대상으로 하려면 **(카메라 전체)** 로 두십시오. **활성** 요일과 시간은 감지 알림과 같게 작동합니다. 한 번 이어진 모션은 한 번 알리고, 재알림 대기 시간이 다음 알림을 막습니다.

### 팀 채널

각 규칙은 이메일 목록, 웹훅, ntfy, Pushover, Slack, Teams로도 보낼 수 있습니다. 채널을 켜고 해당 항목을 입력하십시오.

## 알림 설정

알림은 팀 채널이 아니라 개인에게 브라우저나 이메일로 전달됩니다. 각 사람이 사이드바의 **알림**(이름 옆의 🔔도 동일)에서 원하는 것을 선택합니다. 알림은 그 사람이 볼 수 있는 카메라에 대해서만 도착합니다.

- **공유 알림**: 알림 규칙에서 **사용자 구독 허용**을 선택하면 **내 알림 → 사용 가능**에 나열되며 누구나 켤 수 있습니다. 관리자는 규칙의 **구독자**에서 사용자나 역할의 모든 사용자를 추가할 수도 있습니다.
- **나만의 알림**: **내 알림 → 내 것 → 새 알림**은 알림 규칙과 같은 선택지로 나만을 위한 알림을 만듭니다. 예를 들어 오후 10시부터 오전 6시 사이의 뒷마당 카메라 동물입니다. 본인에게만 표시됩니다.
- 알림은 구독을 취소하지 않고 1시간, 8시간, 하루, 또는 다시 켤 때까지 **음소거**할 수 있습니다.

**설정 → 알림**은 알림 종류별로 사용자에 대한 켜기/끄기를 설정합니다. 종류를 꺼도 알림 규칙의 팀 채널은 멈추지 않습니다.

구독에는 **공유 알림 구독** 권한이, 나만의 알림 생성에는 **개인 알림 생성** 권한이 필요합니다. 기본적으로 모든 역할이 둘 다 가지고 있습니다.

### 브라우저 알림

각 브라우저에서 **내 알림 → 이 브라우저 및 기기**에서 켠 다음 **테스트 보내기**를 사용하십시오. **설정 → 알림**에서 전달 방식을 선택합니다.

| 전달 | 작동 조건 | 필요한 것 |
|---|---|---|
| **LarisVMS가 열려 있는 동안** | LarisVMS 탭 또는 설치된 앱이 열려 있음 | 없음. 네트워크 안에 머뭅니다. |
| **웹 푸시** | LarisVMS 페이지가 열려 있지 않음(Chrome, Edge, Firefox, Safari). 컴퓨터에서는 브라우저 자체가 실행 중이어야 함(아래 참조) | **웹 푸시 키 생성**(한 번), 그리고 서버에서 브라우저 제조사의 푸시 서비스로 나가는 인터넷 접속. 계정 불필요. |
| **Firebase Cloud Messaging** | LarisVMS 페이지가 열려 있지 않음(컴퓨터에서는 같은 제한) | 자체 Firebase 프로젝트: 웹 앱 구성, 웹 푸시 인증서, 서비스 계정 키. 웹 푸시가 꺼져 있을 때만 사용됩니다. |

알림을 표시할 권한이 없으면 열려 있는 LarisVMS 페이지 안에 대신 표시됩니다. 휴대폰에서는 먼저 LarisVMS를 앱으로 설치하십시오([개요](/Help/overview) 참조).

휴대폰은 브라우저가 닫혀 있어도 푸시 알림을 받습니다. 컴퓨터에서는 브라우저가 실행 중일 때만 받으며, 마지막 창을 닫으면 보통 종료됩니다. 그동안 전송된 것은 다시 시작할 때 표시됩니다. 백그라운드에서 계속 실행하려면 **Google Chrome을 닫은 후에도 백그라운드 앱을 계속 실행**(Chrome: 설정 → 시스템) 또는 **Microsoft Edge가 닫혀 있을 때 백그라운드 확장 프로그램 및 앱 계속 실행**(Edge: 설정 → 시스템 및 성능)을 켜십시오. 브라우저를 실행하지 않고도 알림이 필요한 사람에게는 이메일을 사용하십시오.

### 이메일 알림

알림에 이메일을 선택할 수도 있습니다. 이메일은 계정의 주소로, 아래에서 설정한 이메일을 통해 전달됩니다. **설정 → 알림**에서 이메일 알림을 끌 수 있습니다.

## 이메일

이메일 알림은 **설정 → 이메일**에서 설정한 공급자를 통해 전송됩니다. **저장하고 테스트 보내기**는 저장된 설정을 확인합니다.

- **SMTP**: 호스트, 포트, SSL/TLS, 자격 증명.
- **Microsoft Graph**: Entra ID에 앱을 등록하고 관리자 동의와 함께 `Mail.Send` **애플리케이션** 권한(위임 아님)을 부여한 다음 테넌트 ID, 클라이언트 ID, 비밀을 입력합니다. 사용자별 로그인은 없습니다.
- **Gmail**: Google Cloud에서 유형이 *웹 애플리케이션*인 OAuth 클라이언트를 만듭니다. 승인된 리디렉션 URI로 `https://<your-host>/Admin/OAuthCallback`을 추가하고 `https://mail.google.com/` 범위를 사용 설정합니다. 그런 다음 **저장하고 Google에 연결**을 한 번 사용하여 동의를 부여합니다.

저장된 비밀은 암호화됩니다. 서버의 데이터 보호 키가 분실되면 다시 입력하고 Gmail을 다시 연결하십시오.
