# 문제 해결

흔한 문제와 확인할 곳을 설명합니다.

## 로그 위치

- **서버**: **로그 → 시스템 로그**. 수준과 보존 기간은 **설정 → 로그**에서 설정합니다. Debug와 Trace는 세부 정보를 더하지만 큰 파일을 만듭니다.
- **카메라 이벤트 로그**: 카메라가 보내는 원시 이벤트로, 이벤트 태그를 위해 카메라의 이벤트 주제를 나열하는 용도로만 사용됩니다. 기본적으로 30일간 보관됩니다(**설정 → 로그**, 0이면 영구 보관). 지워도 이벤트, 스냅샷, 영상에는 영향이 없습니다.
- **데이터베이스 유지 관리**: 매일 밤 새벽 3시경 서버가 데이터베이스의 인덱스와 통계를 정리하고 수행한 내용을 한 줄로 기록합니다. 데이터베이스 로그인에 권한이 없으면 대신 경고를 기록합니다. MariaDB에서는 건너뜁니다. MariaDB는 자체 통계를 관리합니다.
- **노드**: 각 노드의 `%ProgramData%\LarisVMS\logs\node-*.log`.
- **AI 감지**: 각 노드의 `%ProgramData%\LarisVMS\logs\vision-*.log`.
- **자동 업데이트**: 각 노드 또는 프록시의 `%ProgramData%\LarisVMS\logs\updater-*.log`.

## 카메라가 녹화하지 않음

1. **노드에 할당**되어 있고 그 노드가 **온라인**입니까?
2. 노드에 **저장 경로**가 있습니까? 없는 노드는 노드 목록에 표시됩니다.
3. 카메라가 **사용 설정**되어 있고 스트림이 올바르게 보입니까? 카메라 자체에서 무언가를 변경한 후에는 **다시 프로브**하십시오.
4. 모션, 일정, 이벤트 모드에서는 영상이 버려지고 있지 않은지 확인하십시오([녹화](/Help/recording#modes) 참조).

## 라이브 보기와 재생이 "연결 중"에서 멈춤

노드가 브라우저로 직접 스트리밍하는 경우([직접 스트리밍](/Help/nodes#direct-streaming) 참조) 브라우저는 노드의 클라이언트 포트(기본값 4200)에 연결합니다. 브라우저 콘솔에 실패한 `wss://<node>:<port>/live/…` 연결이 표시되면 노드의 방화벽이 해당 포트를 허용하는지 확인하십시오. 설치 프로그램은 **LarisVMS Node Client Endpoint**라는 인바운드 규칙을 만듭니다. 0.215.1 이전의 설치 프로그램은 노드를 업그레이드하거나 인수할 때 이 규칙을 잃을 수 있었습니다. 최신 노드 설치 프로그램을 다시 실행하거나 규칙을 직접 추가하십시오.

## Active Directory 로그인 또는 동기화 실패

**설정 → Active Directory**의 **연결 테스트**를 사용하십시오. 마지막 동기화의 오류는 같은 페이지에 표시됩니다.

- **도메인 컨트롤러에 연결할 수 없음:** 서버에서 도메인 이름이 확인되는지, 포트 636(LDAPS) 또는 389(LDAP)가 도메인 컨트롤러에 열려 있는지 확인하십시오. LDAPS에서는 도메인 컨트롤러에 이 서버가 신뢰하는 인증서가 필요합니다.
- **서버 자체의 ID가 거부됨:** 통합 보안은 LarisVMS Web 서비스가 도메인에 가입된 서버에서 LocalSystem 또는 도메인 계정으로 실행될 때만 작동합니다. 그렇지 않으면 서비스 계정을 사용하십시오.
- **"접근 권한이 있는 그룹에 속하지 않음":** 사용자는 올바르게 로그인했지만 연결된 그룹에 속하지 않습니다. 그룹은 중첩된 것을 포함하여 보안 그룹으로 일치시킵니다.
- **로컬 로그인을 끈 후 관리자 페이지에서 잠김:** 다시 켜는 데이터베이스 명령은 [Active Directory](/Help/users#active-directory)를 참조하십시오.

## 백그라운드 창에서 라이브 보기가 일시 중지됨

Chrome은 보이지 않는 창을 제한하므로 두 번째 모니터의 라이브 월이 멈췄다가 따라잡을 수 있습니다. 라이브 보기는 스스로 복구됩니다. 방지하려면 Chrome 바로 가기의 대상에 다음을 추가하십시오.

```
--disable-backgrounding-occluded-windows --disable-background-timer-throttling
```

## 모든 타일이 멈췄다가 한꺼번에 다시 연결됨

브라우저나 네트워크가 아니라 노드가 멈췄습니다. 노드 로그에서 `Node process health: tick … ms late`를 찾으십시오. 정상 노드는 이것을 1분에 한 번 정도, 한 자릿수 밀리초의 지연으로 기록합니다.

- `gcPauseMs`가 지연에 가까우면 원인은 가비지 수집입니다.
- `gcPauseMs`는 작은데 `pendingWorkItems`가 수십이면 스레드가 막혀 있습니다. 멈춰 있는 동안 덤프를 캡처하십시오: `dotnet-dump collect -p <LarisVMS.Node pid>`.

## AI 감지는 멈추지만 녹화는 계속됨

보통 GPU 드라이버가 초기화되었습니다. Windows 시스템 이벤트 로그에 그 시점의 `nvlddmkm` 이벤트 153 또는 `Display` 이벤트 4101이 표시됩니다. 비전 서비스는 결과 없이 60초가 지나면 스스로 다시 시작합니다. 초기화가 반복되면 GPU, 드라이버, 냉각 또는 전원을 의심하십시오.

## 업데이트 후 노드나 프록시가 돌아오지 않음

서비스를 시작한 다음(`sc start LarisVMSNode` 또는 `LarisVMSProxy`) `updater-*.log`에서 다시 시작이 실패한 이유를 확인하십시오. 다운로드되었지만 적용되지 않은 업데이트는 노드나 프록시가 다음에 시작할 때 자체 로그에도 기록되며 이후 체크인에서 다시 제공됩니다.

## 노드에 "시계"가 표시됨

노드의 시계가 서버의 시계와 1분 넘게 어긋나 있습니다. 시간 동기화를 수정하십시오. 시계 오차는 일정과 타임라인에 영향을 줍니다.

## 노드가 계속 체크인에 실패함

노드의 **⋯** 메뉴에서 **인증 초기화**를 사용하십시오. 노드의 체크인 토큰이 지워지고 다음 하트비트에서 노드가 다시 동기화됩니다.
