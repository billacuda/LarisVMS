# 사용자 및 접근

계정, 역할, 권한, 카메라 접근, Active Directory, Microsoft 로그인을 설명합니다.

## 사용자

자체 등록은 꺼져 있습니다. 계정은 **설정 → 사용자**에서 만들며, 거기서 역할 할당, 계정 사용 안 함, 비밀번호 초기화도 할 수 있습니다. 로컬 계정은 이메일 주소로 로그인합니다. 계정을 사용 안 함으로 하면 모든 곳에서 즉시 로그아웃되고 라이브 영상도 닫힙니다.

## 비밀번호

비밀번호는 12자 이상이어야 합니다. 흔한 비밀번호, `123456789012` 같은 비밀번호, 본인의 이름이나 이메일 주소가 들어간 비밀번호는 거부됩니다. 더 많은 것을 거부하려면 웹 서버의 `%ProgramData%\LarisVMS\password-blocklist.txt`에 한 줄에 하나씩 넣으십시오(공개된 유출 비밀번호 목록도 사용할 수 있습니다). 다시 시작하지 않아도 반영됩니다.

로컬 계정이 있는 사람은 페이지 상단의 이름을 선택하여 본인 비밀번호를 변경합니다. 현재 비밀번호가 필요하며 그 사람의 다른 모든 세션은 로그아웃됩니다. 관리자도 **설정 → 사용자**가 아니라 같은 방법으로 본인 비밀번호를 변경합니다. Active Directory 계정은 Windows에서 변경합니다.

**설정 → 사용자**에서 계정을 만들거나 비밀번호를 초기화할 때 **다음 로그인 시 변경해야 함**을 선택할 수 있습니다. 그러면 그 사람은 다른 작업을 하기 전에 본인의 비밀번호를 선택해야 합니다. **설정 → 보안 → 관리자가 설정하는 임시 비밀번호**가 켜져 있으면 기본으로 선택되어 있습니다.

한 계정에 대해 한 주소에서 15분 안에 비밀번호를 5번 틀리면 그 주소는 15분을 기다려야 하며, 본인은 다른 곳에서는 여전히 로그인할 수 있습니다. 계정은 모든 곳에서의 시도를 합쳐 20번 틀렸을 때만 15분 동안 잠기며, Super Admin은 로그인 시 비밀번호 오류로 잠기는 일이 없습니다. Super Admin에게는 반복되는 실패와 잠금, 여러 네트워크에 걸친 추측 시도가 알려집니다. 15분 안에 한 계정이 3개 이상의 네트워크에서 10번 실패하거나, 서버 전체에서 10개 이상의 네트워크에서 50번 실패한 경우입니다.

## 2단계 로그인

비밀번호(로컬 또는 Active Directory)로 로그인하는 사람은 휴대폰의 인증 앱(Microsoft Authenticator, Google Authenticator, 1Password 등)의 6자리 코드도 필수로 요구할 수 있습니다. 각 코드는 한 번만 유효하므로 입력하는 것을 누군가 보더라도 다시 사용할 수 없습니다. 설정하려면 페이지 상단의 이름을 선택하고 **2단계 로그인**을 선택한 다음 QR 코드를 스캔하고 앱에 표시되는 코드를 입력하십시오. 복구 코드 10개가 제공됩니다. 휴대폰을 분실하면 각 코드로 한 번씩 로그인할 수 있으므로 안전한 곳에 보관하십시오. 나중에 새 복구 코드를 만들거나 끄는 등의 변경을 하려면 현재 코드가 필요합니다.

로그인할 때 **이 브라우저에서 14일 동안 다시 묻지 않음**을 선택하면 비밀번호나 2단계 설정이 바뀔 때까지 그 브라우저에서는 코드를 생략합니다.

휴대폰과 복구 코드를 모두 분실한 경우 **설정 → 사용자**에서 해당 사용자 옆의 **2단계 인증 끄기**를 사용하면 비밀번호만으로 로그인하여 다시 설정할 수 있습니다.

**설정 → 보안 → 2단계 로그인 필수**는 비밀번호로 로그인하는 모든 사람이 다른 작업을 하기 전에 이를 설정하게 하고, 끄지 못하게 합니다. Microsoft 로그인은 Entra 자체의 확인에 맡깁니다.

## 세션

페이지 상단의 이름을 선택한 다음 **세션**을 선택하면 로그인되어 있는 모든 브라우저가 주소와 마지막 사용 시각과 함께 표시됩니다. 알아볼 수 없는 세션이나 사용 중인 것을 제외한 모든 세션을 로그아웃한 다음 비밀번호를 변경하십시오. 비밀번호를 변경하거나 2단계 로그인을 켜면 다른 세션은 즉시 로그아웃됩니다.

**설정 → 보안 → 관리자 페이지에서 비밀번호 확인**이 켜져 있으면, 최근 15분 이내에 로그인하거나 확인하지 않은 경우 관리자 페이지가 비밀번호를 다시 요청합니다(2단계 로그인이 켜져 있으면 코드도). 관리자 페이지를 사용하는 동안 그 기간이 연장됩니다. 로그인된 브라우저를 발견한 사람은 시스템을 사용할 수는 있어도 설정, 사용자, 키를 변경할 수는 없습니다. Microsoft 로그인은 대신 다시 로그인합니다. 기본값은 꺼짐입니다.

**설정 → 사용자**에서 사람 옆의 **로그아웃**을 선택하면 모든 브라우저에서 그 사람이 로그아웃됩니다. 다시 로그인할 수 있으며, 접근하지 못하게 하려면 계정을 사용 안 함으로 하십시오.

## 역할

역할은 이름이 있는 권한 집합으로, **설정 → 역할**에서 관리합니다. 각 역할에는 다음도 있습니다.

- **범위 단계**.
- 시간 제한 접근을 위한 **만료**(예: 8시간 근무는 480분).
- **세션 수명**: 로그인한 뒤 활동 여부와 관계없이 사용자가 다시 로그인해야 하기까지의 시간(최대 30일, 또는 0이면 만료되지 않음).
- **유휴 시간 제한**: 페이지를 열지 않은 채 사용자가 로그아웃되기까지의 분 수(0은 끔). 라이브 영상을 표시한 채 둔 화면은 유휴로 간주되므로, 비디오 월을 보는 역할에서는 꺼 두십시오.
- **PTZ 우선순위**: 두 사용자가 같은 카메라를 움직일 때 누가 우선하는지를 결정합니다.

## 권한

**설정 → 권한 매트릭스**는 각 역할에 허용되는 작업(카메라 보기, 재생, 내보내기, 설정 편집 등)을 설정합니다. 기본 제공 **Super Admin** 역할은 항상 모든 권한을 가집니다.

**수동 녹화 시작 및 중지**는 라이브 타일의 녹화 버튼을 제어합니다. 아래의 **녹화** 카메라 접근도 필요합니다.

## 카메라 접근

**설정 → 카메라 접근**은 각 역할이 사용할 수 있는 카메라를 모든 카메라, 그룹, 개별 카메라로, 보기, 재생, 내보내기, PTZ, 통화(양방향 오디오), 구성, 녹화(수동 녹화)별로 따로 결정합니다. **권한 부여가 없는 역할은 카메라가 없습니다.** Super Admin은 항상 모든 카메라를 가집니다. 내보내기는 재생보다 넓어지지 않습니다. 권한 부여가 없는 역할도 모든 카메라를 사용할 수 있었던 버전에서 업그레이드하면 각 역할과 사용자의 접근이 같게 유지되도록 "모든 카메라" 권한 부여가 추가됩니다.

## API 키

**관리 → API 키**는 [API](/Help/api)용 키를 발급합니다. 각 키는 연결된 역할로 동작하며 그 역할의 권한 중 일부로 제한할 수 있으므로, 여러 키가 서로 다른 일을 할 수 있습니다. 키가 사용할 수 있는 카메라는 역할의 카메라 접근이 결정합니다.

## Entra

**설정 → 보안 → Entra ID 로그인**은 "Microsoft로 로그인" 버튼을 추가합니다. 계정을 만들지 않으며 이메일로 계정을 일치시키지도 않습니다. **설정 → 사용자**에서 사람의 행에 있는 **Microsoft 로그인**을 사용하여 Entra **개체 ID**(Microsoft Entra 관리 센터의 사용자 페이지에서 가져옴)를 입력하십시오. 첫 Microsoft 로그인에서 연결이 완료되며, 비워 두면 연결이 제거됩니다. 보안 페이지에 표시된 리디렉션 URI로 Entra에 앱을 등록한 다음 테넌트 ID(디렉터리의 GUID 또는 도메인이며 `common`이 아님), 클라이언트 ID, 비밀을 입력하십시오. 변경 사항은 즉시 적용됩니다. 이미 연결된 계정은 계속 작동합니다.

## Active Directory

**설정 → Active Directory**를 사용하면 도메인 사용자가 AD 사용자 이름과 비밀번호로 로그인할 수 있고 AD 그룹에 따라 역할이 부여됩니다. 도메인, LarisVMS의 연결 방식, 로컬 로그인은 누가 누구로 로그인할 수 있는지를 결정하므로 Super Admin만 변경할 수 있습니다. 다른 관리자는 동기화 간격과 그룹 연결을 변경할 수 있습니다.

- **도메인:** `corp.example.com`과 같은 도메인 이름만.
- **암호화:** 포트 636의 LDAPS가 기본값이며, 이 서버가 신뢰하는 인증서가 도메인 컨트롤러에 있어야 합니다. 포트 389의 일반 LDAP는 인증서 없이 작동하지만 안전하지 않으며 권장되지 않습니다.
- **조회 계정:** 통합 보안(기본값)은 LarisVMS Web 서비스 자체의 계정을 사용합니다. 서비스가 도메인에 가입된 서버에서 LocalSystem으로 실행되면 컴퓨터 계정입니다. 또는 서비스 계정을 `DOMAIN\username`과 비밀번호로 입력합니다.
- **로그인:** `@`가 있는 이름은 로컬 계정입니다. 그 외에는 AD 사용자 이름이며 도메인 없이 입력합니다.

**그룹 → 역할 연결:** 그룹 이름을 입력하기 시작하고 목록에서 선택합니다(Tab으로 첫 번째 일치 항목 선택). 그룹의 구성원은 중첩된 그룹의 구성원을 포함하여 역할을 받습니다. 계정은 처음 필요해질 때, 즉 그룹이 연결되는 즉시 또는 사용자가 처음 로그인할 때 만들어집니다. 그룹과 사용자는 SID로 추적되므로 AD에서 이름을 바꿔도 다음 동기화에서 이어집니다. AD 계정의 역할은 그룹 연결로만 부여되며 사용자 페이지에서 편집할 수 없습니다.

**동기화**는 기본적으로 30분마다(5분~24시간) 실행되며, **지금 동기화**로 즉시 실행할 수도 있습니다. AD에서 사용 안 함이거나 만료되었거나 더 이상 연결된 그룹에 속하지 않는 AD 계정은 여기서도 사용 안 함이 되고 로그아웃됩니다. AD에 연결할 수 없으면 동기화는 아무것도 변경하지 않고 5분 후에 다시 시도합니다. 동기화로 사용 안 함이 된 계정은 다시 조건을 충족하면 다시 사용 설정됩니다. 사용자 페이지에서 직접 사용 안 함으로 한 계정은 계속 사용 안 함입니다.

**로컬 로그인**은 AD 로그인이 켜져 있고 하나 이상의 AD 계정이 Super Admin일 때 끌 수 있습니다. 설정 중에 만든 Super Admin 계정과 그 비밀번호를 안전한 곳에 보관하십시오. AD를 사용할 수 없게 되면 LarisVMS 데이터베이스에 대해 다음을 실행하고 그 계정으로 로그인하십시오. SQL Server의 경우:

```sql
UPDATE ActiveDirectorySettings SET LocalLoginsEnabled = 1
```

MariaDB의 경우:

```sql
UPDATE `ActiveDirectorySettings` SET `LocalLoginsEnabled` = 1;
```

## 감사 로그

사용자가 하는 모든 일이 **로그 → 감사 로그**에 기록됩니다. 변경 사항(이전 값과 새 값. 비밀은 "변경됨"으로만 기록), 카메라 보기, 재생 시작, 내보내기입니다.

**변조 감지.** 각 항목은 바로 앞의 항목과 함께, 데이터베이스만으로는 갖고 있지 않은 키로 봉인됩니다. 6시간마다(그리고 감사 로그 페이지에서 **지금 확인**을 선택할 때) 로그 전체를 확인합니다. 항목이 데이터베이스에서 직접 변경, 제거 또는 추가되었다면 페이지에 어떤 항목인지 표시되고 Super Admin에게 알림이 갑니다. 보존 기간에 의해 제거된 항목은 예상된 것이므로 집계되지 않으며, 각 제거 자체도 기록됩니다(**AuditLog.Pruned**). 이 업데이트 이전의 항목은 대상이 아닙니다.

서버는 또한 `%ProgramData%\LarisVMS\audit-chain.dat`에 봉인 키와 로그가 시작된 위치에 대한 작은 기록을 데이터베이스 밖에 보관합니다. 따라서 다른 키로 로그를 다시 봉인하거나 지우고 다시 시작하면 그 사실이 드러납니다. 같은 서버에서 새 빈 데이터베이스로 의도적으로 다시 시작하는 경우 그 파일을 한 번 삭제하십시오. 다음 항목에서 새 파일이 만들어집니다.

**syslog로 전달.** 감사 로그의 사본을 서버 밖에 보관하려면 **설정 → 로그**에서 syslog 서버를 입력하십시오. 새 항목은 기록될 때마다 전송됩니다(RFC 5424, 시설은 *log audit*, 항목은 JSON). UDP, TCP, TLS 중에서 선택합니다. TLS는 syslog 서버의 인증서를 웹 서버가 신뢰해야 합니다. syslog 서버에 연결할 수 없으면 항목은 보관되었다가 복구되면 전송됩니다. 전달은 기존 기록이 아니라 다음 항목부터 시작됩니다. 로그를 전달하는 위치를 변경하거나 전달을 끌 수 있는 사람은 Super Admin뿐이며, 그 변경 자체가 먼저 이전 대상으로 전송됩니다.
