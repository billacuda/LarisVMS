# 보안

IP 허용 목록, 별도의 라이브/재생 포트, 엄격한 스크립트 정책, 인증서, 호스트 이름, 업데이트, 암호화된 비밀, 기업을 위한 추가 보호를 설명합니다.

## 허용 목록

**설정 → 보안**에는 두 개의 IP 허용 목록이 있습니다. 한 줄에 IP 또는 CIDR 블록 하나를 입력합니다(예: `10.0.0.5` 또는 `10.0.0.0/24`). `#`으로 시작하는 줄은 주석입니다. 비어 있는 목록은 모두를 허용합니다.

- **관리 / API**: 관리자 페이지와 REST API. 저장하는 곳의 주소를 차단하게 되는 목록은 거부되므로 스스로를 잠글 수 없습니다.
- **라이브 보기 / 재생**: 라이브 영상, 재생, 썸네일, 내보내기 다운로드, 카메라 스냅샷.

## 별도 포트

**설정 → 라이브 보기 → 사용자 지정 포트**는 라이브 및 재생 트래픽을 같은 인증서를 사용하는 전용 HTTPS 포트로 옮깁니다. 이렇게 하면 방화벽을 따로 설정하거나 LAN 밖으로는 이 포트만 노출할 수 있습니다. `Restart-Service LarisVMSWeb` 후에 적용됩니다. 그 후에는 영상은 새 포트에서만, 그 외 모든 것은 기본 포트에서만 응답합니다. 필드를 비우면 포트 하나로 돌아갑니다.

## HTTP/3

서버는 HTTP/2를 사용하며 Windows 11, Windows Server 2022 이상에서는 HTTP/3를 추가합니다. 브라우저는 HTTP/2로 시작하여 도달할 수 있으면 스스로 HTTP/3로 전환합니다. HTTP/3는 HTTPS 포트(설정한 경우 사용자 지정 포트도)에서 UDP를 사용합니다. 설치 프로그램은 TCP와 UDP를 모두 엽니다. 이전 설치에서는 해당 포트에 UDP 규칙을 추가하거나 최신 설치 프로그램을 다시 실행하십시오. 그때까지는 모든 것이 HTTP/2로 계속 작동합니다. HTTP/3를 끄려면 **설정 → 보안 → HTTP/3**을 해제한 다음 `Restart-Service LarisVMSWeb`을 실행하십시오.

## 엄격한 스크립트 정책

**설정 → 보안 → 엄격한 스크립트 정책**을 켜면 브라우저는 이 서버가 보내는 스크립트만 실행하므로, 페이지에 삽입된 스크립트는 실행될 수 없습니다. 기본값은 켜짐이며 업그레이드하면 켜집니다. 무언가 작동하지 않으면 끄십시오. 그러면 브라우저가 엄격한 정책이 차단했을 모든 것을 보고하며, 최신 보고서가 스위치 아래에 표시됩니다. 의존하는 페이지를 사용한 뒤에도 보고서가 나타나지 않으면 다시 켜십시오. 변경 사항은 다음 페이지 로드 때 적용됩니다.

## 인증서

서버의 인증서는 `appsettings.Production.json`에 설정된 `.pfx` 파일입니다. 갱신된 파일은 다시 시작하지 않고 1분 안에 반영됩니다. 직접 스트리밍을 사용하는 노드에는 노드 페이지에 자체 인증서 설정이 있습니다.

## 카메라 인증서

HTTPS로 접속하는 카메라에는 무엇과도 대조할 수 없는 자체 서명 인증서가 있으므로 기본적으로 모든 인증서를 수락합니다. **설정 → 보안 → 카메라 인증서 고정**을 켜면 서버가 처음 연결할 때 각 카메라 주소의 인증서를 기억하고, 그 후에는 서버와 노드에서 다른 인증서를 거부합니다. 그러면 네트워크의 무언가가 카메라를 사칭하여 비밀번호를 수집하거나 거짓 이벤트를 보낼 수 없습니다.

기억된 인증서는 설정 아래에 나열됩니다. 카메라의 인증서가 실제로 바뀌면(펌웨어 업데이트, 초기화, 새 인증서) 해당 주소 옆의 **잊기**를 선택하십시오. 그 카메라가 다음에 제시하는 인증서가 기억됩니다. 그때까지 서버 또는 노드에서 거부된 연결은 각각 감사 로그에 기록되고 Super Admin에게 알려집니다(카메라 주소당 최대 한 시간에 한 번). 네트워크의 무언가가 카메라를 사칭하고 있을 수 있기 때문입니다. 카메라 주소는 서버가 처음 접속할 때, 보통 카메라를 추가할 때 기억됩니다. 노드는 서버가 아직 접속하지 않은 주소도 수락합니다.

## 호스트 이름

기본적으로 서버는 브라우저가 사용하는 모든 호스트 이름에 응답하므로 IP 주소, 짧은 이름, 전체 이름 모두로 작동합니다. 사용하는 이름에만 응답하게 하려면 `appsettings.Production.json`의 `AllowedHosts`에 세미콜론으로 구분하여 설정하고(예: `"AllowedHosts": "vms.example.com;vms;localhost"`) `Restart-Service LarisVMSWeb`을 실행하십시오. 노드, 프록시, 사람이 접속에 사용하는 모든 이름을 포함하십시오. 그 외의 것은 오류가 납니다.

리버스 프록시(IIS ARR, nginx 등) 뒤에서는 그 주소를 `appsettings.Production.json`에 `"ReverseProxy": { "KnownProxies": [ "10.0.0.2" ] }`로 나열하고 다시 시작하십시오. 그러면 서버는 해당 프록시의 `X-Forwarded-For` 및 `X-Forwarded-Proto` 헤더에서 클라이언트의 실제 주소와 스킴을 가져오므로, 허용 목록과 감사 로그에는 프록시가 아니라 사람이 보입니다. 이 헤더는 목록에 없는 곳에서 오면 무시되며, 목록이 비어 있는 동안에는 완전히 무시됩니다.

## 업데이트

이 확인들은 다운로드와 실행 중인 설치 사이에 있습니다.

- **릴리스 다운로드**에는 `SHA256SUMS.txt`가 함께 제공됩니다. 설치 프로그램을 실행하기 전에 `Get-FileHash <file> -Algorithm SHA256`으로 확인하여 해당 파일의 줄과 비교하거나, `sha256sum -c SHA256SUMS.txt`를 실행하십시오. 설치 프로그램이 코드 서명되어 있으면 Windows가 게시자도 표시합니다.
- **노드 및 프록시 업데이트**는 이 서버의 서명 키로 서명됩니다. 노드나 프록시는 등록할 때 그 키를 보관하며, 서버와의 연결이 변조되더라도 그 키로 서명되지 않은 것은 설치하지 않습니다. 또한 실행 중인 것보다 새롭지 않은 빌드는 거부합니다. [설치](/Help/installation#updates)를 참조하십시오.
- **게시자 서명**(선택 사항): 게시자의 키(`-PublisherKeyPath`)로 빌드된 노드나 프록시는 모든 업데이트에 게시자의 서명도 요구합니다. 다른 빌드는 이 확인을 건너뜁니다. 그 키는 오프라인으로 보관되며 서버에는 절대 두지 않으므로, 침입당한 서버조차 자체 코드를 노드에 밀어 넣을 수 없습니다.
- 서버에 대한 **연결**은 **노드 → 업데이트 및 등록 → 서버 인증서 확인**의 설정에 따라 확인됩니다([노드](/Help/nodes#server-certificate) 참조).

## 암호화된 비밀

카메라 자격 증명, SMB 자격 증명, 노드 키, 이메일 비밀, Entra 클라이언트 비밀, Active Directory 서비스 계정 비밀번호는 `%ProgramData%\LarisVMS\keys`의 데이터 보호 키를 사용하여 데이터베이스에서 암호화됩니다. `%ProgramData%\LarisVMS`를 열 수 있는 것은 SYSTEM, Administrators, LarisVMS 서비스 계정뿐입니다. LarisVMS를 설치하기 전에 로컬 사용자가 만든 폴더처럼 그곳에서 발견된 다른 접근은 서비스가 시작될 때 제거됩니다. 그 폴더를 백업하고 배포 중에는 절대 삭제하지 마십시오.

## 기업을 위한 추가 보호

기본 상태에서 LarisVMS는 가정용 설치가 그대로 작동하도록 설정되어 있습니다. 아래는 모두 선택 사항이며 기본값은 꺼짐입니다. 기업이나 인터넷에서 접근할 수 있는 서버에 맞는 것을 켜십시오.

- **2단계 로그인 필수**: 설정 → 보안([2단계 로그인](/Help/users#two-factor-sign-in) 참조).
- **관리자 페이지에서 비밀번호 확인**: 설정 → 보안([세션](/Help/users#sessions) 참조).
- **관리자가 설정하는 임시 비밀번호**: 설정 → 보안([비밀번호](/Help/users#passwords) 참조).
- **더 짧은 세션과 유휴 시간 제한**: 설정 → 역할의 각 역할([역할](/Help/users#roles) 참조).
- **카메라 인증서 고정**: 설정 → 보안([카메라 인증서](#camera-certificates) 참조).
- **허용 목록**: 설정 → 보안([허용 목록](#allow-lists) 참조).
- **다른 모든 컴퓨터에서의 설정 토큰**: 설정 마법사를 실행하기 전에 `appsettings.Production.json`에 `"Setup": { "AlwaysRequireToken": true }`를 설정합니다([설치](/Help/installation#web-server) 참조).
- **노드 또는 프록시를 설치할 때 서버 인증서 고정**: `-ServerCertThumbprint`([서버 인증서](/Help/nodes#server-certificate) 참조).
- **공유 키를 끈 일회용 등록 코드**: 노드 → 업데이트 및 등록([일회용 등록 코드](/Help/nodes#one-time-registration-codes) 참조).
- **서버에서 노드로의 암호화된 연결**: 각 노드의 페이지([서버에서의 암호화된 연결](/Help/nodes#encrypted-connections-from-the-server) 참조).
- **감사 로그를 syslog로 전달**: 설정 → 로그([감사 로그](/Help/users#audit-log) 참조).
- **게시자가 서명한 업데이트**: 직접 빌드하는 경우([업데이트](#updates) 참조).
- **권한이 더 낮은 서비스 계정.** LarisVMS 서비스는 LocalSystem으로 실행됩니다. 다른 계정(`services.msc` 또는 `sc.exe config`)으로 실행할 수도 있지만, 그 경우 서비스에 필요한 것, 즉 설치 폴더, 모든 저장소 및 보관 폴더나 공유, 인증서 파일을 그 계정에 부여하는 것은 사용자의 몫입니다. `%ProgramData%\LarisVMS`는 알아서 처리됩니다. 각 LarisVMS 서비스는 시작할 때 이를 SYSTEM, Administrators, LarisVMS 서비스가 실행되는 계정으로 제한하고 그곳의 다른 접근을 제거합니다. 변경 후 서비스의 로그를 확인하십시오.
