# 疑難排解

常見問題，以及該去哪裡查看。

## 記錄在哪裡

- **伺服器**：**記錄 → 系統記錄**。在**設定 → 記錄**下設定層級和保留期。Debug 和 Trace 會增加細節，但會產生很大的檔案。
- **攝影機事件記錄**：攝影機傳送的原始事件，僅用於列出攝影機的事件主題以設定事件標籤。預設保留 30 天（**設定 → 記錄**，0 表示永久保留）；清除它們不會影響事件、快照或錄影。
- **資料庫維護**：每晚大約凌晨 3 點，伺服器會整理資料庫的索引和統計資訊，並記錄一行說明它做了什麼。如果其資料庫登入沒有權限，則改為記錄一則警告。在 MariaDB 上會略過此操作；MariaDB 自行維護統計資訊。
- **節點**：每個節點上的 `%ProgramData%\LarisVMS\logs\node-*.log`。
- **AI 偵測**：每個節點上的 `%ProgramData%\LarisVMS\logs\vision-*.log`。
- **自動更新**：每個節點或代理上的 `%ProgramData%\LarisVMS\logs\updater-*.log`。

## 攝影機沒有在錄影

1. 它是否已**指派到節點**，並且該節點是否**線上**？
2. 該節點是否有**儲存路徑**？節點清單會標出沒有儲存路徑的節點。
3. 攝影機是否**已啟用**，其串流看起來是否正常？在攝影機本身做了任何變更之後，請**重新探測**。
4. 在移動偵測、排程或事件模式下，檢查錄影是否被丟棄（請參閱[錄影](/Help/recording#modes)）。

## 即時檢視和回放一直停在「正在連線」

當節點直接向瀏覽器串流時（請參閱[直連串流](/Help/nodes#direct-streaming)），瀏覽器會連線到節點的用戶端連接埠，預設為 4200。如果瀏覽器主控台顯示 `wss://<node>:<port>/live/…` 連線失敗，請檢查節點的防火牆是否允許該連接埠：安裝程式會建立一條名為 **LarisVMS Node Client Endpoint** 的輸入規則。0.215.1 之前的安裝程式在升級或接管節點時可能會遺失該規則；請再次執行目前的節點安裝程式，或手動新增該規則。

## Active Directory 登入或同步失敗

使用**設定 → Active Directory** 下的**測試連線**；上次同步的錯誤會顯示在同一頁面上。

- **無法連線到網域控制站**：檢查網域名稱能否從伺服器解析，以及連接埠 636（LDAPS）或 389（LDAP）是否對網域控制站開放。使用 LDAPS 時，網域控制站需要有此伺服器信任的憑證。
- **伺服器自身的身分識別被拒絕**：只有當 LarisVMS Web 服務執行在已加入網域的伺服器上，並以 LocalSystem 或網域帳戶執行時，整合式安全性才起作用。否則請使用服務帳戶。
- **「不在任何有存取權限的群組中」**：使用者登入正確，但不在任何已連結的群組中。群組是依安全性群組比對的，包括巢狀的群組。
- **關閉本機登入後被鎖在管理頁面之外**：請參閱 [Active Directory](/Help/users#active-directory)，其中有重新將其開啟的資料庫命令。

## 背景視窗中的即時檢視暫停

Chrome 會限制不可見的視窗，因此第二個螢幕上的即時牆可能會卡住，然後再追趕上來。即時檢視會自行恢復。要避免這種情況，請把下面的內容加入 Chrome 捷徑的目標中：

```
--disable-backgrounding-occluded-windows --disable-background-timer-throttling
```

## 所有圖塊都卡住，然後一起重新連線

是節點停滯了，不是瀏覽器或網路。請在節點記錄中尋找 `Node process health: tick … ms late`。正常的節點大約每分鐘記錄一次，延遲只有個位數毫秒。

- 如果 `gcPauseMs` 接近延遲，原因是記憶體回收。
- 如果 `gcPauseMs` 很小但 `pendingWorkItems` 達到幾十，則執行緒被封鎖。請在其停滯期間擷取傾印：`dotnet-dump collect -p <LarisVMS.Node pid>`。

## AI 偵測停止，但錄影繼續

通常是 GPU 驅動程式被重設了。Windows 系統事件記錄會在那一刻顯示 `nvlddmkm` 事件 153 或 `Display` 事件 4101。視覺服務在 60 秒沒有結果後會自行重新啟動。反覆重設說明問題出在 GPU、其驅動程式、散熱或電源上。

## 更新後節點或代理沒有恢復

啟動其服務（`sc start LarisVMSNode` 或 `LarisVMSProxy`），然後檢查 `updater-*.log`，瞭解重新啟動失敗的原因。已下載但從未套用的更新，也會在節點或代理下次啟動時記錄到其自身的記錄中，並在之後的簽到中再次提供。

## 節點顯示「時鐘」

節點的時鐘與伺服器的時鐘相差超過一分鐘。請修復其時間同步。時鐘偏差會影響排程和時間軸。

## 節點一直簽到失敗

使用節點 **⋯** 選單中的**重設驗證**。它會清除節點的簽到權杖，節點將在下次心跳時重新同步。
