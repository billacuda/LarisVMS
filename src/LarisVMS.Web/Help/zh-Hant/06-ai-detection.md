# AI 偵測

節點上的物件偵測：模型、硬體、閾值、快照和外部後端。

每個節點都可以對其攝影機執行即時物件偵測。被偵測到的物件會獲得即時邊界框、時間軸上的彩色標記、即時圖塊上的徽章和裁切後的快照。偵測在移動偵測模式錄影中也算作移動。偵測在獨立的程序中執行，因此 GPU 或驅動程式問題永遠不會使錄影停止。

透過**監看此攝影機中的物件**依攝影機開啟它。準確偵測只需要**每台攝影機 5–7 fps**，因此請將[畫面更新率](#thresholds)限制在這個水準，以降低 GPU 負載。全域預設值在**設定 → AI 偵測**下。節點和攝影機可以覆寫其中大部分。

## 硬體

一個節點套件適用於所有電腦。啟動時，視覺服務會根據發現的硬體選擇後端：

| 硬體 | 後端 | 節點上需要 |
|---|---|---|
| NVIDIA GPU | CUDA（回復為 DirectML） | CUDA Toolkit 12.x 和 cuDNN 9.x |
| AMD / Intel GPU | DirectML | 最新的 GPU 驅動程式 |
| 無 GPU | CPU | 無 |

節點的編輯頁面會顯示偵測到的加速器，其**加速器**設定可以強制指定一個。模型從不隨附。節點會從伺服器取得內建的 YOLOX 模型，其他模型放入節點上的 `C:\ProgramData\LarisVMS\models`。

## 慢速後端

如果 NVIDIA 節點無法使用 CUDA，AI 偵測會回復為 DirectML，其執行速度要慢好幾倍。分析的畫面會變少，GPU 會發熱，經過的汽車等快速移動的物件可能偵測不到。此時**節點**頁面會在該節點旁顯示**⚠️ AI 執行於 DirectML**及原因，並通知超級管理員。

通常的原因是缺少 cuDNN。請在節點上安裝 CUDA Toolkit 12.x 和適用於 CUDA 12 的 cuDNN 9.x，可從 NVIDIA 的 cuDNN 下載頁面取得，或使用 `pip install nvidia-cudnn-cu12`。節點會在 10 分鐘內發現它們，將其複製到其 AI 後端旁，並在 CUDA 上重新啟動偵測。

## 模型系列

模型每個節點執行一次，並為該節點的所有攝影機提供服務，因此模型設定是依節點而不是依攝影機的。

- **自動 / YOLOX**：預設選項。速度快，不需要加黑邊，在低功耗和非 NVIDIA 的 GPU 上也表現良好。**YOLOX 規格**從 Nano（最快）到 X（最準確）。低功耗電腦使用 Nano 或 Tiny，強勁的 GPU 使用 L 或 X。
- **D-FINE**：實驗性。結果可能難以預料，在切片模式下橫跨兩個圖塊的物件可能被遺漏或重複。**權重**：Obj2Coco 能辨識 80 種物件類型（小或中），Obj365 能辨識 365 種。
- **自訂**：放入節點 models 資料夾的任何 `.onnx` 模型。請參閱[自訂模型](#custom-models)。

變更模型會重新啟動每台攝影機的偵測。

## TensorRT

只有當節點啟用了 TensorRT（`Vision:EnableTensorRt`）並安裝了 TensorRT 10.x SDK 時，**D-FINE TensorRT** 才會起作用。**FP32** 能帶來穩妥的加速。**FP16** 最快；如果攝影機的引擎在 FP16 下溢位，它會自動以 FP32 重新建置。在每個攝影機解析度下首次啟動時，建置引擎需要幾分鐘。

## 自訂模型

將 `.onnx` 檔案放入節點上的 `C:\ProgramData\LarisVMS\models`。如果模型自身的中繼資料描述了其解碼器、輸入大小和標籤，它就能直接使用。否則，請新增一個同名的 `.json` 檔案，補充缺少的內容。**重新整理**會列出節點發現的所有模型，並標出中繼資料不完整的模型。帶有警告的模型可以選擇，但在警告被修復之前不會執行。

## 長寬比調整

攝影機的畫面如何適配模型的方形輸入：

- **黑邊填充**（預設）：保持比例，並用黑邊填充。
- **拉伸**：將畫面壓縮以填滿方形，這會使形狀失真。
- **切片**：將畫面切成相互重疊的完整解析度方塊。最適合廣角攝影機上小而遠的物件，但在 16:9 的攝影機上要多做約 2 倍的工作。它需要 GPU 預處理，並會自動開啟。

**GPU 畫面預處理**把顏色轉換從 CPU 轉移到 GPU，這對攝影機較多的節點有幫助。

## 閾值

- **信賴度**：偵測被計入的最低分數。越低能捕捉越多物件，但會增加誤判。在不斷誤判的攝影機上請調高它。
- **IoU**：兩個框必須重疊多少才會合併為一個物件。
- **偵測串流**：子串流較輕量；主串流能看到更多細節。
- **方向**：一些安裝在走廊的攝影機回報橫向串流，卻傳送直向影像。請在這些攝影機上設定**直向**，以免偵測和快照被壓扁。
- **最大偵測畫面更新率**：每台攝影機每秒送達模型的畫面數。**5–7 fps 足以實現準確的偵測和追蹤**。更高的畫面更新率只會增加 GPU 負載，並不能改善結果。0 表示不設上限。

## 快照

每個被追蹤的物件都會獲得一張快照，從其最佳畫面中裁切而來。

- **靜止逾時**：物件多久看不到之後，其快照才會關閉。
- **回報靜止物件**：同時回報存在但未移動的物件，例如停著的汽車。
- **快照移動精確度**：在物件離開後不久關閉快照，使稍後出現的同類物件不會被併入其中。**離開寬限時間**是等待多久。如果太短，停頓的物件會被拆分成兩張快照。
- **快照裁切邊界**：物件周圍額外保留的空間，以其框的百分比表示。

同一類型的多個物件出現在同一張快照中時，會顯示為數量（×2）。每個物件也會連同各自的顏色和速度單獨保留。

## 物件顏色

每個被追蹤物件的顏色取自其最清晰的畫面：車輛、動物和其他物件為一種顏色，人則有上衣和褲子的顏色。快照會為每種顏色顯示一個塗有該顏色的徽章，快照篩選器中的**顏色**、**上衣**和**褲子**區段會將結果縮小到您勾選的顏色。偵測警示也可以依顏色篩選。

顏色來自畫面而不是模型，因此適用於任何偵測器。緊鄰著框外側的顏色也會被取樣並剔除，所以狗周圍的草坪或汽車周圍的道路不會被誤判為其顏色。它們仍然只是盡力而為的猜測：複雜的場景、重疊的物件和光線都可能給出錯誤的顏色。光線的影響最大：陰影、車燈和白平衡會使顏色偏移，淺灰色的汽車可能被辨識為銀色或白色。當攝影機處於黑白夜間（紅外線）模式時，不會記錄顏色。可在**設定 → AI 偵測**下用**物件顏色**將其關閉。

## 測速點

測速點會在道路上的兩條線之間為物件計時。在攝影機的**測速點**頁面（從**攝影機 → 編輯**進入）上，按一下**新增測速點**，按一下線 **A** 的兩端，再按一下線 **B** 的兩端，並輸入兩線之間沿道路測量的實際距離。每個越過兩條線的被追蹤物件都會得到一個速度，顯示在其即時框和快照上。**方向**預設為雙向計時；選擇**僅 A 到 B**或**僅 B 到 A**可以為雙向道路的一條車道計時。**速度單位**（km/h 或 mph）在**設定 → AI 偵測**下。

被測速點計時的物件，即使看起來是靜止的（例如徑直駛向攝影機的車輛），也會被記錄為在移動。計時使用每個框的底部中點，即物件接觸地面處，因此請把線畫在路面上。為了獲得良好的讀數：

- 將線畫在平坦的地面上，橫跨行駛方向，並在物件仍清晰可見的前提下盡量拉開距離。
- 仔細測量距離：可以步測，或使用地圖的測距工具。
- 用一輛以已知速度駛過的車輛檢查一次，如果讀數有偏差，請調整距離。

讀數是估計值。攝影機的偵測畫面更新率限制了通過時刻的計時精確度，因此短的測速點和快速行駛的車輛精確度最低。儲存測速點會重新啟動攝影機的 AI 偵測。

測速點可以設定**速度限制**（選用）。超過它的速度會以紅色顯示，並在速度熱度圖中單獨計數。

測得的速度會出現在多個位置：

- **即時檢視**：物件在畫面中時，顯示在其框上。
- **快照**：卡片上的 ⏱ 徽章，以及篩選清單中的**速度**篩選（「達到或超過」）。
- **回放**：時間軸上每次測量處的刻度（超過限制時為紅色；暫留可查看詳細資料），以及物件在螢幕上時影像上方的徽章。
- **儀表板**：「**速度記錄**」小工具顯示最新的測量結果。按一下其標題可查看完整記錄，支援排序、篩選和 CSV 下載。
- **活動**：切換到**速度**，可依日期和小時查看平均速度、最高速度、超限數量或測量數量的熱度圖。歷程記錄的保存時間與活動歷程記錄相同，遠長於錄影本身。
- **警示**：「速度超過限制」規則。

## 移動

快照、警示和即時的**移動中**框只統計正在朝某處移動的物件。即使在停著的汽車周圍，偵測器的框也會逐畫面輕微晃動，所以幾個像素的變化是不夠的。**設定 → AI 偵測**下的**移動偵測**，或每台攝影機在**攝影機 → 編輯**上的設定，決定如何判斷這一點。

**標準**（預設）觀察每個物件近期路徑的形狀：

- 任何朝一個方向穩定移動的物件，在幾個畫面之內（7 fps 時大約半秒）就會被計為移動，無論它是不到一秒就穿過畫面的汽車，還是正駛出車道的卡車。每個物件的步幅會與其自身的框晃動幅度比較，因此大物件不必比小物件走得更遠。
- 比其框的晃動更緩慢地爬行的物件（只有步行速度的一小部分），在其路徑保持穩定的直線數秒之後會被計入。晃動是來回的，因此永遠不會形成一條線。
- 物件需要走多遠隨其大小而增長，但比大小本身增長得更慢。一輛大卡車不必先走過自身長度的一半。
- 從畫面邊緣進入，或從桿子或樹後面出來的物件，依其框在畫面中可見的那一側來判斷。
- 徑直駛向或駛離攝影機的物件，會隨著變大或變小而被計入。
- 有人從停著的汽車前面走過而使其框發生變化，不會被計入。

**移動靈敏度**（僅標準模式）預設為**一般**。**高**更早發現移動，**低**會忽略更多晃動。在停著的汽車或搖晃的灌木被回報為移動的攝影機上請調低它，在遺漏緩慢物件的地方請調高它。

僅僅是形狀發生變化的框，例如盆栽的框在偵測器一會兒包含葉子、一會兒不包含時發生變化，或停著的汽車的框在有東西從前面經過時發生變化，不會被計入。移動必須在多個畫面中逐漸累積，而不是一次跳變。

**舊版**是更早的規則：物件的中心在 2 秒內移動了其框大小的一半時即被計入。如果標準模式在某台攝影機上表現異常，請使用它。

一個正在移動的物件如果消失在樹、桿子或停著的汽車後面，並在大約 30 個已分析畫面（6 fps 時約 5 秒）內從同一條線更遠處出來，它仍是同一個物件，因此只會被計一次，並保持一條路徑。它還必須是同類物件且大小相近，且在兩者都能辨別時顏色也必須相符。朝其他方向出來，或花了更長時間才出來的物件，則是新物件。

## 移動的物件

每個移動物件穿過畫面的路徑會隨其事件一起儲存，用於「活動」頁面上的**場景**熱度圖。

**設定 → AI 偵測**下的**移動中的物件**選擇哪些類型的物件可以被計為移動。預設是**人**、**車輛**和**動物**。其他任何物件仍會被偵測到，並在開啟**靜止**時顯示為靜止框，但永遠不會被計為移動，因此不會觸發快照或警示。請在**其他物件**清單中逐個選擇加入其他物件：收到的包裹通常會被辨識為手提箱、背包或手提包。對於自訂模型，請輸入其自己的物件名稱，以逗號分隔。

## 忽略的物件

**設定 → AI 偵測**下的**忽略的物件**會完全關閉某些類型的物件。模型一回報它們就會被丟棄，因此它們永遠不會獲得框、快照、事件或警示。可用於模型在您的攝影機上總是辨識錯的東西，比如被它認成飛機的露台。可勾選整個類別（**人**、**車輛**、**動物**和**其他物件**）或清單中的單個物件。兩種模型的拼寫都能比對，所以忽略 **airplane** 也會忽略 **aeroplane**。對於自訂模型，請輸入其自己的物件名稱，以逗號分隔。

攝影機的**編輯**頁面可以選擇自己的清單來代替全域清單：在**忽略的物件**下選擇**為此攝影機選擇**。在那裡不選擇任何內容，則該攝影機會偵測所有內容，即使全域清單忽略了它們。儲存會重新啟動該攝影機的偵測，這只會重設追蹤。

## 抖動

**抖動閾值**是無論物件大小，計入移動的最小像素移動量。在舊版模式下，**靜止物件抖動抑制**會平滑遠處停著的車輛的晃動；它也可能把真正緩慢移動的物件保持為靜止，因此預設關閉。它不適用於標準模式，標準模式自己處理晃動。

## 外部後端

**外部 HTTP 服務**不在節點上執行任何模型。每一個畫面都會傳送到您執行的推論伺服器，由它以 JSON 傳回框。可用於 LarisVMS 未隨附的模型，或沒有 GPU 的節點。追蹤、快照、時間軸和即時疊加層的運作方式相同。

該服務必須提供 `POST /v1/detect`、`GET /v1/models` 和 `GET /healthz`。**測試**會檢查連線並載入模型清單。**API 金鑰**以 Bearer 權杖的形式傳送。**傳輸**：JPEG 適用於任何服務。原始 YUV 和 BGRA 模式會略過 JPEG 編碼，但使用 4–10 倍的頻寬，且只有在模型宣告支援它們時才有效。
