# 警示、通知和電子郵件

警示規則、傳送給使用者的通知、團隊管道和電子郵件提供者設定。

## 警示規則

**設定 → 警示**中保存共用規則。每條規則監看一個條件：

- **攝影機未回報**：攝影機已停止傳送健康報告。
- **節點離線**：節點已停止簽到。
- **儲存空間不足**：可用空間已降至某個百分比以下。
- **節點容錯移轉**：某個節點的攝影機已移到其備用節點。
- **偵測到移動**：攝影機上或其某個移動偵測區域中的移動。
- **偵測到物件**：AI 偵測發現了符合的物件。
- **速度超過限制**：物件以達到或超過設定速度的速度越過了[測速點](/Help/ai-detection#speed-traps)。
- **證據鎖定即將結束**和**證據鎖定已移除**：請參閱[證據鎖定](/Help/live-and-playback#evidence-locks)。

健康規則每分鐘檢查一次。**冷卻時間**是重複警示之間的最短間隔，因此持續成立的條件不會每分鐘都發出警示。

### 偵測警示

**偵測到物件**和**速度超過限制**會在偵測後數秒內觸發。每個篩選條件都是選用的，您設定的所有篩選條件必須同時符合：

- **攝影機**：一台攝影機、某個節點上的攝影機，或任意攝影機。
- **類別**和**標籤**：例如車輛，或僅卡車。
- **顏色**：物件的顏色，或人的上衣或褲子的顏色。請參閱[物件顏色](/Help/ai-detection#object-colors)。
- **區域**：僅限站在攝影機某個區域內的物件（以框的底部判斷）。
- **生效時間**：星期幾和時段，採用儲存該規則的人所在的時區。像 22:00 到 06:00 這樣的時段會跨夜執行。

一次偵測只會發出一次警示。在監看多台攝影機的規則上，冷卻時間對每台攝影機分別計算，因此繁忙的攝影機不會拖延其他攝影機。

### 移動偵測警示

**偵測到移動**會在移動後數秒內觸發，來自伺服器的移動偵測或攝影機自身的移動事件。選擇一台攝影機、某個節點上的攝影機，或任意攝影機。選擇了一台攝影機時，**區域**可將其限制為該攝影機的某個**伺服器移動偵測**區域；保持**（整個攝影機）** 則表示任何位置的移動。**生效**的日期和時間與偵測警示的運作方式相同。一段持續的移動只會發出一次警示，並由冷卻時間擋住下一次。

### 團隊管道

每條規則還可以傳送到電子郵件清單、Webhook、ntfy、Pushover、Slack 和 Teams。開啟一個管道並填寫其欄位。

## 通知

通知會傳送給個人，透過其瀏覽器或電子郵件，而不是傳送到團隊管道。每個人在側邊欄的**通知**（也就是您姓名旁邊的 🔔）下選擇自己想要的內容。通知只會針對某人可以檢視的攝影機送達。

- **共用通知**：在警示規則上，**允許使用者訂閱**會將其列在**我的通知 → 可用**下，任何人都可以開啟。管理員也可以在規則的**訂閱者**下新增某個使用者，或某個角色中的所有人。
- **您自己的通知**：**我的通知 → 我的 → 新通知**可以僅為您自己建立一個，選項與警示規則相同。例如，晚上 10 點到早上 6 點之間後院攝影機裡的動物。只有您能看到它。
- 可以將通知**靜音**一小時、8 小時、一天，或直到您重新開啟，而無需取消訂閱。

**設定 → 通知**為使用者開啟或關閉每一類通知。關閉某一類並不會阻止警示規則上的團隊管道。

訂閱需要**訂閱共用通知**權限，建立自己的通知需要**建立個人通知**權限。每個角色預設都有這兩項。

### 瀏覽器通知

在每個瀏覽器中，於**我的通知 → 此瀏覽器和裝置**下開啟它們，然後使用**傳送測試**。**設定 → 通知**選擇它們的傳送方式：

| 傳送方式 | 適用情境 | 需要 |
|---|---|---|
| **LarisVMS 開啟期間** | 已開啟 LarisVMS 分頁或已安裝的應用程式 | 無。保持在您的網路內。 |
| **Web 推播** | 沒有開啟任何 LarisVMS 頁面（Chrome、Edge、Firefox 和 Safari）。在電腦上，瀏覽器本身必須正在執行；見下文 | 一次**產生 Web 推播金鑰**，以及從伺服器到瀏覽器廠商推播服務的對外網際網路存取。無需帳戶。 |
| **Firebase Cloud Messaging** | 沒有開啟任何 LarisVMS 頁面，在電腦上有同樣的限制 | 您自己的 Firebase 專案：其 Web 應用程式設定、Web 推播憑證和服務帳戶金鑰。僅在 Web 推播關閉時使用。 |

沒有顯示通知的權限時，通知會改為顯示在開啟的 LarisVMS 頁面內。在手機上，請先將 LarisVMS 安裝為應用程式（請參閱[概觀](/Help/overview)）。

即使瀏覽器已關閉，手機也能收到推播通知。在電腦上，瀏覽器只有在執行時才能收到，而關閉其最後一個視窗通常會使其結束；這期間傳送的內容會在它重新啟動時顯示。若要讓它在背景保持執行，請開啟**關閉 Google Chrome 後繼續執行背景應用程式**（Chrome：設定 → 系統）或**關閉 Microsoft Edge 後繼續執行背景擴充功能和應用程式**（Edge：設定 → 系統與效能）。對於需要在沒有瀏覽器執行的情況下收到警示的人，請使用電子郵件。

### 電子郵件通知

人們也可以為通知選擇電子郵件。它會透過下面設定的電子郵件，傳送到其帳戶上的地址。**設定 → 通知**可以關閉電子郵件通知。

## 電子郵件

電子郵件警示和通知透過**設定 → 電子郵件**下設定的提供者傳送。**儲存並傳送測試**會檢查已儲存的設定。

- **SMTP**：主機、連接埠、SSL/TLS 和憑證。
- **Microsoft Graph**：在 Entra ID 中註冊一個應用程式，授予它 `Mail.Send` **應用程式**權限（不是委派權限）並獲得系統管理員同意，然後輸入其租用戶 ID、用戶端 ID 和密碼。沒有依使用者的登入。
- **Gmail**：在 Google Cloud 中建立類型為 *Web 應用程式*的 OAuth 用戶端。將 `https://<your-host>/Admin/OAuthCallback` 新增為已授權的重新導向 URI，並啟用 `https://mail.google.com/` 範圍。然後使用一次**儲存並連線到 Google**來授予同意。

儲存的密碼會被加密。如果伺服器的資料保護金鑰遺失，請重新輸入它們，並重新連線 Gmail。
