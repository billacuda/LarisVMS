# 使用者與存取

帳戶、角色、權限、攝影機存取、Active Directory 和 Microsoft 登入。

## 使用者

自助註冊已關閉。帳戶在**設定 → 使用者**下建立，您還可以在那裡指派角色、停用帳戶和重設密碼。本機帳戶使用其電子郵件地址登入。停用帳戶會立即使其在所有地方登出，並關閉其即時影像。

## 密碼

密碼至少 12 個字元。常見的密碼、類似 `123456789012` 的密碼，以及包含本人姓名或電子郵件地址的密碼都會被拒絕。若要拒絕更多密碼，請將它們放入 Web 伺服器上的 `%ProgramData%\LarisVMS\password-blocklist.txt`，每行一個（可以使用已公開的外洩密碼清單）。無需重新啟動即可生效。

擁有本機帳戶的人透過選擇頁面頂端的自己的姓名來變更自己的密碼。需要輸入目前的密碼，並且其他所有工作階段都會登出。管理員也以同樣的方式變更自己的密碼，而不是在**設定 → 使用者**下。Active Directory 帳戶在 Windows 中變更密碼。

在**設定 → 使用者**下建立帳戶或重設密碼時，您可以勾選**下次登入時必須變更**。此後，該使用者必須先選擇自己的密碼，才能做其他任何事情。開啟**設定 → 安全性 → 管理員設定的暫時密碼**時，它預設已勾選。

同一個帳戶在 15 分鐘內從同一個位址輸錯 5 次密碼後，該位址必須等待這 15 分鐘；本人仍然可以從其他任何地方登入。只有在來自任何地方的錯誤嘗試達到 20 次後，帳戶才會被鎖定 15 分鐘，並且超級管理員永遠不會因登入時輸錯密碼而被鎖定。超級管理員會收到重複失敗和鎖定的通知，以及分散在多個網路上的猜測通知：15 分鐘內，一個帳戶從 3 個或更多網路失敗 10 次，或整個伺服器從 10 個或更多網路失敗 50 次。

## 雙重驗證登入

任何使用密碼（本機或 Active Directory）登入的人，還可以要求輸入手機上驗證器應用程式（Microsoft Authenticator、Google Authenticator、1Password 等）產生的六位數驗證碼。每個驗證碼只能使用一次，因此被人看到輸入的驗證碼無法再次使用。要進行設定，請選擇頁面頂端的您的姓名，然後選擇**雙重驗證登入**，掃描 QR 碼，並輸入應用程式顯示的驗證碼。您會得到十個復原碼；請將它們保存在安全的地方，因為如果您遺失手機，每個復原碼可用於登入一次。之後變更任何內容，例如產生新的復原碼或將其關閉，都需要目前的驗證碼。

登入時，**在此瀏覽器上 14 天內不再詢問**會在該瀏覽器上略過驗證碼，直到密碼或雙重驗證設定發生變化。

如果有人同時遺失了手機和復原碼，**設定 → 使用者**下其旁邊的**關閉雙重驗證**，可讓他們僅用密碼登入並重新設定。

**設定 → 安全性 → 要求雙重驗證登入**會讓每個使用密碼登入的人必須先設定它才能做其他事情，並阻止他們將其關閉。Microsoft 登入交由 Entra 自己的檢查處理。

## 工作階段

選擇頁面頂端的您的姓名，然後選擇**工作階段**，即可查看您已登入的每個瀏覽器，以及其位址和上次使用時間。登出您不認識的工作階段，或除目前使用的工作階段之外的所有工作階段，然後變更您的密碼。變更密碼或開啟雙重驗證登入會立即使您的其他工作階段登出。

開啟**設定 → 安全性 → 管理頁面需確認密碼**後，除非您在最近 15 分鐘內登入或確認過，否則管理頁面會再次要求輸入您的密碼（開啟雙重驗證登入時還有驗證碼）；使用管理頁面會使這一狀態持續。這樣，發現您的瀏覽器仍處於登入狀態的人可以使用系統，但無法變更其設定、使用者或金鑰。Microsoft 登入則改為重新登入。預設關閉。

在**設定 → 使用者**下，某人旁邊的**登出**會使其在每個瀏覽器上登出。他們可以重新登入；若要阻止他們，請停用帳戶。

## 角色

角色是一組具名的權限，在**設定 → 角色**下管理。每個角色還有：

- 一個**範圍層級**；
- 用於限時存取的**有效期**（例如 8 小時班次為 480 分鐘）；
- **工作階段有效期**：使用者登入後，無論多活躍，需要重新登入之前的小時數（最長 30 天，或 0 表示永不過期）；
- **閒置逾時**：使用者在沒有開啟任何頁面的情況下被登出之前的分鐘數（0 表示關閉）。顯示著即時影像的螢幕也算閒置，因此對於觀看影像牆的角色請將其關閉；
- **PTZ 優先順序**，用於決定兩個使用者移動同一台攝影機時誰優先。

## 權限

**設定 → 權限矩陣**設定每個角色被允許執行的動作（檢視攝影機、回放、匯出、編輯設定等）。內建的**超級管理員**角色一律擁有全部權限。

**開始和停止手動錄影**控制即時圖塊上的錄影按鈕。它還需要下面的**錄影**攝影機存取權限。

## 攝影機存取

**設定 → 攝影機存取**決定每個角色可以使用哪些攝影機：所有攝影機、某個群組或單台攝影機，並針對檢視、回放、匯出、PTZ、通話（雙向音訊）、設定和錄影（手動錄影）分別設定。**沒有授權的角色沒有任何攝影機**；超級管理員一律擁有所有攝影機。匯出的範圍永遠不會超過回放。從沒有授權的角色也可以使用所有攝影機的版本升級時，會新增一個「所有攝影機」授權，以保持每個角色和使用者的存取權限不變。

## API 金鑰

**管理 → API 金鑰**簽發用於 [API](/Help/api) 的金鑰。每個金鑰以其綁定的角色運作，並且可以限制為該角色權限的一部分，因此多個金鑰可以做不同的事情。金鑰可以使用哪些攝影機由角色的攝影機存取權限決定。

## Entra

**設定 → 安全性 → Entra ID 登入**會新增一個「使用 Microsoft 登入」按鈕。它從不建立帳戶，也不依電子郵件比對帳戶：在**設定 → 使用者**中，使用某人所在列的 **Microsoft 登入**輸入其 Entra **物件 ID**（來自 Microsoft Entra 系統管理中心中其使用者頁面）。他們首次透過 Microsoft 登入時即完成連結；留空則移除連結。請使用安全性頁面上顯示的重新導向 URI 在 Entra 中註冊一個應用程式，然後輸入其租用戶 ID（您目錄的 GUID 或網域，不是 `common`）、用戶端 ID 和密碼。變更立即生效。已連結的帳戶繼續可用。

## Active Directory

**設定 → Active Directory**允許網域使用者使用其 AD 使用者名稱和密碼登入，並根據其 AD 群組賦予他們角色。只有超級管理員才能變更網域、LarisVMS 連線到它的方式或本機登入，因為這些設定決定了誰可以以任何人的身分登入；其他管理員可以變更同步間隔和群組連結。

- **網域**：只需網域名稱，例如 `corp.example.com`。
- **加密**：預設是連接埠 636 上的 LDAPS，需要網域控制站上有此伺服器信任的憑證。連接埠 389 上的一般 LDAP 無需憑證即可使用，但它不安全，不建議使用。
- **查詢帳戶**：整合式安全性（預設）使用 LarisVMS Web 服務自己的帳戶。當服務在已加入網域的伺服器上以 LocalSystem 執行時，就是電腦帳戶。或者以 `DOMAIN\username` 的形式輸入服務帳戶及其密碼。
- **登入**：帶有 `@` 的名稱是本機帳戶。其他的都是 AD 使用者名稱，輸入時不帶網域。

**群組 → 角色連結**：開始輸入群組名稱並從清單中選擇（Tab 鍵選取第一個符合項目）。群組的成員（包括巢狀群組的成員）會獲得該角色。帳戶在首次需要時建立，即群組被連結後立即建立，或使用者首次登入時建立。群組和使用者依 SID 追蹤，因此在 AD 中重新命名任何一個，都會在下次同步時延續。AD 帳戶的角色只來自群組連結，無法在「使用者」頁面上編輯。

**同步**預設每 30 分鐘執行一次（5 分鐘到 24 小時），或用**立即同步**馬上執行。在 AD 中被停用或已過期，或不再屬於任何已連結群組的 AD 帳戶，會在這裡被停用並登出。如果無法連線到 AD，同步不會變更任何內容，並在 5 分鐘後重試。因同步而被停用的帳戶在再次符合條件時會重新啟用。在「使用者」頁面上手動停用的帳戶則保持停用。

當 AD 登入開啟，並且至少有一個 AD 帳戶擁有超級管理員角色之後，可以關閉**本機登入**。請把安裝時建立的超級管理員帳戶及其密碼保存在安全的地方。如果 AD 變得無法使用，請對 LarisVMS 資料庫執行以下命令，並使用該帳戶登入。在 SQL Server 上：

```sql
UPDATE ActiveDirectorySettings SET LocalLoginsEnabled = 1
```

在 MariaDB 上：

```sql
UPDATE `ActiveDirectorySettings` SET `LocalLoginsEnabled` = 1;
```

## 稽核記錄

使用者所做的一切都記錄在**記錄 → 稽核記錄**下：變更（含舊值和新值；密碼僅記錄為「已變更」）、檢視攝影機、開始回放和匯出。

**防竄改**。每個項目都與它前面的項目一起，使用僅靠資料庫本身無法持有的金鑰進行密封。每 6 小時（以及當您在稽核記錄頁面上選擇**立即檢查**時），會檢查整個記錄。如果某個項目被變更、移除或直接新增到資料庫中，頁面會指出是哪一個，並通知超級管理員。因保留原則而被移除的項目屬於預期情況，不計在內，並且每次移除本身也會被記錄（**AuditLog.Pruned**）。此次更新之前的項目不在涵蓋範圍內。

伺服器還在 `%ProgramData%\LarisVMS\audit-chain.dat` 中，於資料庫之外保留一份小記錄，記載了密封金鑰以及記錄的起點，這樣記錄就無法用另一個金鑰重新密封，也無法被清空並重新開始而不被發現。如果您有意在同一伺服器上以新的空資料庫重新開始，請刪除該檔案一次；下一個項目會產生一個新檔案。

**轉送到 syslog**。若要在伺服器之外保留稽核記錄的副本，請在**設定 → 記錄**下輸入 syslog 伺服器。每個新項目在寫入時都會傳送（RFC 5424，設施為 *log audit*，項目為 JSON）。可選擇 UDP、TCP 或 TLS。TLS 要求 Web 伺服器信任 syslog 伺服器的憑證。如果無法連線到 syslog 伺服器，項目會被保留，並在其恢復後傳送。轉送從下一個項目開始，而不是現有歷程記錄。只有超級管理員才能變更記錄的轉送位置或關閉轉送；該變更本身會先傳送到舊的目的地。
