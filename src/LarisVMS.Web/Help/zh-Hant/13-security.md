# 安全性

IP 允許清單、獨立的即時/回放連接埠、嚴格指令碼原則、憑證、主機名稱、更新、加密的密碼，以及針對企業的額外保護。

## 允許清單

**設定 → 安全性**有兩個 IP 允許清單。每行輸入一個 IP 或 CIDR 區塊（例如 `10.0.0.5` 或 `10.0.0.0/24`）；以 `#` 開頭的行是註解。空清單表示允許所有人。

- **管理 / API**：管理頁面和 REST API。如果某個清單會封鎖您正在儲存它的位址，它會被拒絕，因此您不會把自己鎖在外面。
- **即時檢視 / 回放**：即時影像、回放、縮圖、匯出下載和攝影機快照。

## 獨立連接埠

**設定 → 即時檢視 → 自訂連接埠**會將即時和回放流量移到它自己的 HTTPS 連接埠，使用同一個憑證。這樣您可以為它單獨設定防火牆，或只將它暴露到區域網路之外。它在 `Restart-Service LarisVMSWeb` 之後生效。此後，影像只在新連接埠上回應，其他所有內容只在主連接埠上回應。清空該欄位即可恢復為單一連接埠。

## HTTP/3

伺服器使用 HTTP/2，並在 Windows 11、Windows Server 2022 或更新版本上增加 HTTP/3。瀏覽器從 HTTP/2 開始，在能夠連線時會自行切換到 HTTP/3。HTTP/3 在 HTTPS 連接埠（以及已設定的自訂連接埠）上使用 UDP。安裝程式會同時開放 TCP 和 UDP；對於較舊的安裝，請為該連接埠新增一條 UDP 規則，或再次執行目前的安裝程式。在此之前，一切仍透過 HTTP/2 正常運作。要關閉 HTTP/3，請取消勾選**設定 → 安全性 → HTTP/3**，然後執行 `Restart-Service LarisVMSWeb`。

## 嚴格指令碼原則

開啟**設定 → 安全性 → 嚴格指令碼原則**後，瀏覽器只執行此伺服器傳送的指令碼，因此注入頁面的指令碼無法執行。它預設開啟，升級也會將其開啟。如果某些功能停止運作，請將其關閉：瀏覽器隨後會回報嚴格原則原本會攔截的所有內容，最新的報告會顯示在開關下方。當您使用過所依賴的頁面後不再出現任何報告時，請再次開啟它。變更在下次載入頁面時生效。

## 憑證

伺服器的憑證是在 `appsettings.Production.json` 中設定的 `.pfx` 檔案。續期後的檔案會在一分鐘內被採用，無需重新啟動。使用直連串流的節點在節點頁面上有自己的憑證設定。

## 攝影機憑證

透過 HTTPS 存取的攝影機使用自我簽署憑證，無法對照任何東西進行驗證，因此預設接受任何憑證。開啟**設定 → 安全性 → 固定攝影機憑證**後，伺服器會在首次連線時記住每個攝影機位址的憑證，此後無論在伺服器上還是節點上，都拒絕不同的憑證。這樣，網路上冒充攝影機的裝置就無法取得其密碼或傳送虛假事件。

已記住的憑證列在該設定下方。如果某台攝影機的憑證確實發生了變化（韌體更新、重設或新憑證），請選擇其位址旁邊的**忘記**；它下次出示的憑證會被記住。在此之前，伺服器或節點上每次被拒絕的連線都會被記錄到稽核記錄，並通知超級管理員（每個攝影機位址每小時最多一次），因為網路上可能有裝置在冒充該攝影機。攝影機位址在伺服器首次存取它時被記住，通常是在新增攝影機時；節點會接受伺服器尚未存取過的位址。

## 主機名稱

預設情況下，伺服器會回應瀏覽器使用的任何主機名稱，因此透過 IP 位址、簡短名稱和完整名稱都可以存取。若要只回應您使用的名稱，請在 `appsettings.Production.json` 中將 `AllowedHosts` 設定為這些名稱，以分號分隔（例如 `"AllowedHosts": "vms.example.com;vms;localhost"`），然後執行 `Restart-Service LarisVMSWeb`。請包含節點、代理和人員用來存取它的每個名稱：其他任何名稱都會出錯。

在反向代理（IIS ARR、nginx 等）之後，請將其位址在 `appsettings.Production.json` 中列為 `"ReverseProxy": { "KnownProxies": [ "10.0.0.2" ] }`，然後重新啟動。伺服器隨後會從該代理的 `X-Forwarded-For` 和 `X-Forwarded-Proto` 標頭取得用戶端的真實位址和通訊協定方案，因此允許清單和稽核記錄看到的是本人，而不是代理。來自不在清單中的任何來源的這些標頭會被忽略，而在清單為空時則完全忽略。

## 更新

這些檢查介於下載和正在執行的安裝之間：

- **發行版下載**附帶 `SHA256SUMS.txt`。執行安裝程式之前，用 `Get-FileHash <file> -Algorithm SHA256` 檢查它並與該檔案對應的行比較，或執行 `sha256sum -c SHA256SUMS.txt`。當安裝程式經過程式碼簽署時，Windows 還會顯示發行者。
- **節點和代理的更新**由此伺服器的簽署金鑰簽署。節點或代理會保留其註冊時的那個金鑰，並且即使它與伺服器的連線被竄改，也不會安裝任何未用該金鑰簽署的內容。它還會拒絕不比正在執行的版本更新的版本。請參閱[安裝](/Help/installation#updates)。
- **發行者簽章**（選用）：使用發行者金鑰（`-PublisherKeyPath`）建置的節點或代理，還要求每個更新都帶有發行者簽章；其他版本會略過此檢查。該金鑰保存在離線環境，絕不會放在伺服器上，因此即使伺服器被入侵，也無法把它自己的程式碼推送到節點。
- 與伺服器的**連線**依**節點 → 更新與註冊 → 伺服器憑證檢查**中的設定進行檢查（請參閱[節點](/Help/nodes#server-certificate)）。

## 加密的密碼

攝影機憑證、SMB 憑證、節點金鑰、電子郵件密碼、Entra 用戶端密碼和 Active Directory 服務帳戶的密碼，使用 `%ProgramData%\LarisVMS\keys` 中的資料保護金鑰加密後存放在資料庫中。只有 SYSTEM、Administrators 和 LarisVMS 服務的帳戶才能開啟 `%ProgramData%\LarisVMS`：在那裡發現的任何其他存取權限，例如本機使用者在安裝 LarisVMS 之前建立的資料夾，會在服務啟動時被移除。請備份該資料夾，並且在部署期間絕不要刪除它。

## 針對企業的額外保護

開箱即用時，LarisVMS 的設定能讓家庭安裝直接運作。下面的所有內容都是選用的，並且預設關閉；請開啟適合企業或可從網際網路存取的伺服器的項目：

- **要求雙重驗證登入**：設定 → 安全性（請參閱[雙重驗證登入](/Help/users#two-factor-sign-in)）。
- **管理頁面需確認密碼**：設定 → 安全性（請參閱[工作階段](/Help/users#sessions)）。
- **管理員設定的暫時密碼**：設定 → 安全性（請參閱[密碼](/Help/users#passwords)）。
- **更短的工作階段和閒置逾時**：設定 → 角色下的每個角色（請參閱[角色](/Help/users#roles)）。
- **固定攝影機憑證**：設定 → 安全性（請參閱[攝影機憑證](#camera-certificates)）。
- **允許清單**：設定 → 安全性（請參閱[允許清單](#allow-lists)）。
- **對所有其他電腦要求安裝權杖**：在執行安裝精靈之前，在 `appsettings.Production.json` 中設定 `"Setup": { "AlwaysRequireToken": true }`（請參閱[安裝](/Help/installation#web-server)）。
- **安裝節點或代理時固定伺服器憑證**：`-ServerCertThumbprint`（請參閱[伺服器憑證](/Help/nodes#server-certificate)）。
- **一次性註冊代碼，並關閉共用金鑰**：節點 → 更新與註冊（請參閱[一次性註冊代碼](/Help/nodes#one-time-registration-codes)）。
- **從伺服器到節點的加密連線**：在每個節點的頁面上（請參閱[來自伺服器的加密連線](/Help/nodes#encrypted-connections-from-the-server)）。
- **將稽核記錄轉送到 syslog**：設定 → 記錄（請參閱[稽核記錄](/Help/users#audit-log)）。
- **由發行者簽署的更新**，適用於您自己建置的版本（請參閱[更新](#updates)）。
- **權限更低的服務帳戶**。LarisVMS 服務以 LocalSystem 執行。您可以使用其他帳戶來執行它們（`services.msc` 或 `sc.exe config`），但此後需要您自己為該帳戶提供服務所需的內容：安裝資料夾、每個儲存和封存資料夾或共用，以及憑證檔案。`%ProgramData%\LarisVMS` 由系統為您處理：每個 LarisVMS 服務在啟動時都會將其限制為 SYSTEM、Administrators，以及 LarisVMS 服務執行所用的帳戶，並移除那裡的任何其他存取權限。變更之後請檢查服務的記錄。
