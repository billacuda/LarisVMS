# Changelog Archive: v0.91.0 – v0.110.0

Archived entries from [CHANGELOG.md](../CHANGELOG.md), oldest read at the top or bottom the
same as the main file — nothing reordered, just moved. Format is unchanged: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/) / [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.110.0] - 2026-08-19

### Added

- Hardware-transcode capability probing foundation: nodes now probe which hardware encoders their
  ffmpeg build supports (NVENC/QSV/AMF) at startup, shown as badges on Admin → Nodes, plus a
  shared encode-pipeline argument builder for future transcode features to use. Not yet run
  against real hardware; no feature consumes it yet.

**install-node.ps1 re-run: not needed** — ordinary node auto-update covers it.

## [0.109.0] - 2026-08-18

### Added

- Viewing experience improvements: pinch-to-zoom in fullscreen, drag-select-to-zoom on a Playback
  grid cell, a playback speed selector from 1/32x to 32x (seek-driven "stepped" mode above 8x),
  and a per-user toggle to hide event-tag coloring on the Playback timeline (off by default).

## [0.108.0] - 2026-08-18

### Added

- Alerting: Admin → Alerts lets you create a rule watching one camera or node for a condition
  (not reporting, offline, low storage) and deliver it through email, webhook, ntfy, Pushover,
  Slack, or Teams. Evaluated on a 1-minute tick with a per-rule cooldown; fires only on trip, no
  resolved notification yet.

## [0.107.0] - 2026-08-18

### Added

- Gmail OAuth2 email provider, completing the email provider set alongside SMTP and Microsoft
  Graph. Admin → Settings → Email gained a Gmail card and a Google consent-redirect flow.

## [0.106.0] - 2026-08-18

### Added

- Microsoft Graph email provider (app-only client-credentials auth, no per-user consent). Admin →
  Settings → Email gained a provider selector and Graph config fields.

## [0.105.0] - 2026-08-18

### Added

- Outbound email foundation: Admin → Settings → Email configures an SMTP sender, with a "save and
  send test" action. Nothing in the app sends real alerts through it yet — that's separate,
  not-yet-built work.

## [0.104.0] - 2026-08-18

### Added

- Admin → Settings → Roles and → Users: create/rename/delete roles and edit their permission
  matrix, and create/disable users and reset passwords. Guards prevent removing the last
  Administrator's role or disabling the last enabled Administrator account. This is now the only
  way to provision a new account, since self-registration was disabled last release.

## [0.103.0] - 2026-08-18

### Security

- Self-registration is now disabled. The default ASP.NET Core Identity registration page was
  reachable with no invite or approval step; a self-registered account couldn't do anything since
  it held no role, but the open registration itself wasn't intentional. The route now redirects
  to Login.

## [0.102.0] - 2026-08-18

### Added

- Live view and playback can now run on a port of their own, separate from the management
  interface, for firewalling them differently. Requires a matching IIS site binding to actually
  take effect.

## [0.101.0] - 2026-08-18

### Added

- Per-camera access control is now enforced. The existing but previously-unused CameraAccess ACL
  now gates the camera list, live viewing, Playback, and export creation, with a new admin page to
  grant View/Playback/Export/PTZ/Talk/Configure per camera group or camera. A role with no grants
  stays unrestricted, so existing deployments are unaffected until an admin adds a grant. The
  playback data-proxy endpoints don't yet independently re-check access by camera id directly;
  tracked as a known gap.

## [0.100.0] - 2026-08-18

### Added

- A per-user column picker on Cameras and the Dashboard, letting you hide columns you don't need;
  saved as a preference that follows you across devices. Built as a reusable module any table can
  opt into.

## [0.99.0] - 2026-08-18

### Added

- User preferences (theme, last-watched Live view, dashboard thumbnail toggle, table page sizes,
  Playback scrub position and clock format) now persist server-side instead of only in
  localStorage, so they follow the signed-in user across devices.

## [0.98.0] - 2026-08-18

### Added

- Session lifetime is now configurable per role, replacing a fixed 60-minute timeout. Defaults to
  24 hours; 0 means never expires. A user with multiple roles is bound by the shortest.

## [0.97.0] - 2026-08-18

### Fixed

- The Viewer role has never had a single working permission, since it was first seeded — seeded
  rows stored the role's name as its RoleId instead of its actual database Id, so no permission
  check could ever match. Invisible in practice because Administrator bypasses the permission
  table entirely. Fixed by seeding the real Id, with a migration repairing already-seeded rows.
  Supersedes 0.94.0's fix, which addressed a shallower mismatch on top of this same bug.

## [0.96.0] - 2026-08-18

### Added

- A new HTTPS column on the Cameras list, read directly from each camera's stored URL scheme.

## [0.95.0] - 2026-08-18

### Changed

- Nodes moved out of the Admin dropdown into its own top-level nav button.
- The navbar is now permission-aware: every button is hidden unless the signed-in user actually
  holds the permission its page requires, instead of always showing the full menu.

### Added

- `IPermissionService.GetGrantedAsync`, resolving all of a user's granted permissions in one
  database round trip, making the permission-aware navbar affordable on every page.

### Known limitations

- The Viewer role's seeded permissions cover only a handful of resources; most nav buttons have
  no seeded Viewer permission yet, so a Viewer sees a much shorter navbar than an Administrator
  until the remaining RBAC gaps close.

## [0.94.0] - 2026-08-18

### Changed

- Logs moved out of the Admin dropdown into its own top-level nav button, with Audit Logs and
  System Logs as tabs of one page.
- Settings consolidated into one tabbed page (Backups, Branding, Cameras, Events, Logs, Nodes,
  Recording, Storage and Retention), replacing five separate Admin dropdown entries. Old routes
  redirect to their new home.

### Added

- Audit log retention setting, defaulting to forever (kept unbounded by default so an upgrade
  never silently starts deleting a compliance record).
- System log path is now shown (read-only) alongside its retention setting.

### Fixed

- The Viewer role's seeded audit-log permission never actually granted access, due to a
  resource-name mismatch. **Correction (see 0.97.0): this fix was real but incomplete** — a
  deeper bug underneath it meant no seeded permission for any resource actually worked; the full
  fix landed two releases later.

## [0.93.0] - 2026-08-17

### Added

- A camera's device service URL is now editable after creation, instead of requiring delete and
  re-add to change it. Saving triggers an automatic re-probe.

### Fixed

- The Dahua/Amcrest plugin's event connection validated the camera's TLS certificate, unlike
  every other camera-facing client in the app — so an HTTPS camera's event stream silently never
  connected on a typical self-signed LAN certificate. Brought in line with the rest.

**LarisVMS.Node change — `install-node.ps1` re-run needed on every recorder.**

## [0.92.0] - 2026-08-17

### Added

- Cameras are now re-probed automatically once a day at a configurable time, one at a time to
  avoid overwhelming inexpensive cameras. A failure on one camera doesn't stop the rest of the
  pass.

## [0.91.0] - 2026-08-17

### Added

- Plugins page (Admin → Plugins) listing every camera integration this build ships, its version,
  and which cameras use it.
- Each integration provider now carries its own independent version number.
- Event tag badge position (motion/detection badges on a live tile) is now configurable per
  corner.
