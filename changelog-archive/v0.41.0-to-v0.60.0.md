# Changelog Archive: v0.41.0 – v0.60.0

Archived entries from [CHANGELOG.md](../CHANGELOG.md), oldest read at the top or bottom the
same as the main file — nothing reordered, just moved. Format is unchanged: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/) / [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.60.0] - 2026-08-14

### 🛠️ Fixed

- Hover thumbnails sometimes rendered as a broken image, because the node wrote a newly-extracted
  thumbnail straight to its final path, letting a concurrent request read a truncated file mid-write.
  Now writes to a temp file and renames atomically. **LarisVMS.Node change — install-node.ps1
  re-run needed on every recorder.**

## [0.59.0] - 2026-08-14

### ➕ Added

- Timeline hover thumbnails: hovering the Playback page's per-camera timeline shows a small
  preview frame from that point in the recording. Thumbnails are generated per 5-minute bucket,
  cached on the node's disk, and deleted automatically with their source segment.

**LarisVMS.Node change — install-node.ps1 re-run needed on every recorder.**

## [0.58.0] - 2026-08-13

### 🛠️ Fixed

- Double-click-to-fullscreen didn't work on a saved view's own playback page, because that page's
  separate tile implementation was never wired up to the shared fullscreen module Live and
  Playback both use.

## [0.57.0] - 2026-08-13

### 🛠️ Fixed

- Playback's timeline/current-time readout never advanced during playback, because a typo threw
  an uncaught error partway through page init, before the update timer was ever started. Also
  broke the Export panel's button, fixed alongside it.

## [0.56.0] - 2026-08-13

### ⚙️ Changed

- Renamed the project from NidusVMS to LarisVMS project-wide, including the recorder node's
  Windows service, its data folder, and its environment variables.

**LarisVMS.Node change — install-node.ps1 re-run needed on every recorder**, and this one is not
a simple in-place update — the renamed Windows service must be stopped and removed manually
before installing fresh.

## [0.55.0] - 2026-08-13

### ➕ Added

- Schedule and Event recording modes, completing the original four-mode design (only
  Continuous/Motion existed before). Schedule mode keeps a segment only inside configured time
  windows; Event mode keeps a segment only when a specific "Drives recording" event tag rule
  fired nearby, ignoring ordinary motion entirely. Both fail open when nothing is configured yet.

**LarisVMS.Node change — install-node.ps1 re-run needed on every recorder.**

## [0.54.0] - 2026-08-13

### ➕ Added

- Admin dropdown in the main nav (Nodes, Node Builds, Settings), replacing two flat top-level
  links. Node Builds previously had no nav entry at all.

## [0.53.0] - 2026-08-13

### 🛠️ Fixed

- `install-node.ps1` had no UTF-8 BOM, breaking it under Windows PowerShell 5.1 with confusing
  parse errors, because that version falls back to the system codepage for BOM-less scripts and
  mangles this codebase's em dashes and curly apostrophes. All first-party scripts now carry a
  UTF-8 BOM.

## [0.52.0] - 2026-08-13

### 🛠️ Fixed

- Admin -> Nodes pointed at a stale page for the recorder registration key, left over from before
  that control moved to Admin -> Settings. Now links to the correct page.

## [0.51.0] - 2026-08-13

### 🛠️ Fixed

- `deploy.ps1`'s node-build-registration step (added last release) ran before EF migrations
  applied, so the very first deploy after the columns it needed were added silently failed to
  register the build. Registration now runs after migrations.

## [0.50.0] - 2026-08-13

### ⚙️ Changed

- Recorder-node build uploads on Admin -> Node Builds are gone, replaced by a `deploy.ps1`-driven
  approval queue, since uploading a several-hundred-MB build through the browser hit IIS's own
  request size limit. Every registered build now lands as Pending for admin approval.

### 🛠️ Fixed

- Dragging a zoomed Playback video tile could also kick off the browser's own native drag-out
  gesture at the same time as the tile's own pan-drag, since the handler never called
  `preventDefault()`. Same fix applied to the fullscreen-tile pan-drag.

## [0.49.0] - 2026-08-13

### 🛠️ Fixed

- Picking a saved view from Live's view picker left no way to switch to another view without
  going back and picking again; the view's own toolbar now carries the same picker.

## [0.48.0] - 2026-08-13

### ➕ Added

- Recorder node auto-update: upload a new node build once on Admin -> Node Builds, and every
  recorder node whose reported version is older downloads it, verifies it, and swaps its own
  binary on its next heartbeat — no more manually re-running install scripts on each machine.
  Gated by a global on-by-default setting.

## [0.47.0] - 2026-08-12

### ➕ Added

- Multi-camera video export: select several cameras and a timeframe from Playback's toolbar and
  get one MP4 per camera, delivered asynchronously through a new Exports page. Output is a pure
  remux, no transcode, and swept from disk after 7 days.
- Double-click focused/fullscreen view on Live and Playback camera tiles, using the real
  Fullscreen API on the tile's container so its own controls stay reachable.
- Live View: toggle a single camera into playback mode without leaving the page, reusing the same
  player Playback uses. Only one tile can be in playback mode at a time.
- Pagination for the Cameras and Nodes tables, with a remembered rows-per-page selector.
- Playback: exact-time seeking via the current-time readout and arrow keys, since a single pixel
  of timeline drag can cover 100+ seconds at wide zoom levels.

### 🛠️ Fixed

- Live View fullscreen now shows only mute and exit, instead of dropping every control out of the
  render tree.
- Playback's current-time readout is now centered under the timeline's playhead.

## [0.46.0] - 2026-08-12

### ➕ Added

- Day boundaries and date labels on the timeline, so scrolling across midnight or viewing a
  single day no longer leaves it unclear which day is on screen.

## [0.45.0] - 2026-08-12

### 🛠️ Fixed

- Corrected 0.44.0's stated cause: the cameras' clocks are fine — their ONVIF `UtcTime` field is
  not. The original per-camera measurement was confounded by recording gaps. Re-measured using a
  signal internal to the cameras themselves and found a consistent exactly-60-minute offset on
  affected units — the signature of a daylight-saving conversion bug in the camera's ONVIF layer,
  not clock drift. The 0.44.0 code fix was already correct; only its stated cause and the logged
  warning were wrong, both now corrected.

## [0.44.0] - 2026-08-12

### 🛠️ Fixed

- Untrustworthy ONVIF notification timestamps corrupted the timeline and defeated Motion-mode
  gating entirely, because motion events and recorded segments were stamped from two different
  time sources that could disagree by exactly one hour on some cameras. (**The cause originally
  stated here was wrong; see 0.45.0 for the corrected diagnosis.** The fix itself is unaffected.)
  Notification timestamps are now anchored to the node's own receive time whenever the reported
  time is more than 60 seconds off.
- The merged "all cameras" timeline on Playback now only covers the cameras in the selected view,
  instead of aggregating every camera in the system.

## [0.43.0] - 2026-08-11

### 🛠️ Fixed

- ONVIF-event Motion-mode recording never stopped, confirmed via live production data. The
  closing-edge debounce required a second qualifying call to actually close, which a continuously
  polled source supplies automatically but ONVIF PullPoint notifications don't — so motion stayed
  active for hours after it should have cleared. Fixed by removing the now-redundant debounce,
  since real ONVIF devices already debounce their own state.

## [0.42.0] - 2026-08-11

### 🛠️ Fixed

- The Event tags page added last release had no direct link to reach it from the Cameras list,
  the same gap Zones had since it shipped. Both are now linked directly from each camera's row.

## [0.41.0] - 2026-08-11

### ➕ Added

- User-configurable ONVIF event tag rules, with an admin editor: match incoming notifications by
  topic and tag the timeline with a chosen color, covering anything a camera's firmware pushes
  (object/person detection, tamper, digital inputs), not just motion.
- A rule can optionally gate Motion-mode recording's keep/discard decision the same way built-in
  motion and zones already do.

### ⚙️ Changed

- Node-side ONVIF event polling now restarts a camera's event session when its rule set changes,
  taking effect on the next reconcile instead of only after reassignment.
