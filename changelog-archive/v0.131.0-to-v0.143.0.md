# Changelog Archive: v0.131.0 – v0.143.0

Archived entries from [CHANGELOG.md](../CHANGELOG.md), oldest read at the top or bottom the
same as the main file — nothing reordered, just moved. Format is unchanged: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/) / [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.143.0] - 2026-08-23

### Added

- Roles & permissions overhaul, pass 1 of 5: new role metadata, an 8-role hierarchy with scope
  tiers, expiry defaults and PTZ priority, and a consolidated Permissions admin page (Matrix /
  Roles / Users tabs) replacing the old Roles/Users/Security split.

## [0.142.6] - 2026-08-23

### Added

- Admin > Nodes' stale-footage warning now lists which cameras and when their footage will age
  out of retention, instead of just a bare count.

## [0.142.5] - 2026-08-23

### Fixed

- A recorder node's binary-swap update could leave the Windows Service stopped with no log of
  why. The updater now logs to file and retries the final service-start step.

## [0.142.4] - 2026-08-22

### Security

- Export access is now enforced as a sub-permission of Playback access per camera.
- The Dashboard now hides cameras the viewer lacks View access to, instead of showing all of them.
- Snapshots' playback-thumbnail endpoint now enforces per-camera Playback access, closing a gap
  left over from the 0.142.3 fix.

## [0.142.3] - 2026-08-22

### Security

- A CameraAccess-restricted user could view and scrub any camera's live/recorded video by GUID,
  bypassing per-camera restrictions — several endpoints serving video bytes checked only the
  global permission, and a couple of endpoints leaked camera GUIDs a restricted user shouldn't
  see. All now enforce the per-camera check consistently.
- Media tokens now travel as an Authorization header in addition to the query string, so they
  stop appearing in plaintext access logs.
- The node registration key comparison now uses constant-time equality, matching the rest of the
  codebase.

## [0.142.2] - 2026-08-22

### Fixed

- Seeking backward within an already-loaded Playback segment could freeze the video with no
  error, because a fast path assumed the whole segment was buffered when only part of it was. A
  stall watchdog was also added as a backstop for future silent MSE stalls.
- The node's partial-fetch seek math used an absolute media timestamp instead of one relative to
  the segment, which could misalign or silently disable partial fetch for some files.

## [0.142.1] - 2026-08-22

### Fixed

- The timeline strip and time readout lagged behind the picture after jumping into the middle of
  a segment, because they used the fragment's own media time instead of the segment's true
  wall-clock start.

## [0.142.0] - 2026-08-22

### Added

- Snapshots shows a live "N of M ready" counter while on-demand thumbnails generate.

### Fixed

- Timeline events and playback position could read well behind the actual video content, because
  segment start time was taken from file-creation time instead of when real content appeared.
- Live view defaulted to serving cameras' Sub stream via Adaptive Streaming, reading as a quality
  regression; now off by default.
- Snapshots re-downloaded every thumbnail on each page load with no caching; historical
  thumbnails now carry a cache header.
- Jumping to an earlier point on the Playback timeline could hang forever with no timeout; a
  fetch timeout with automatic retry was added.

## [0.141.0] - 2026-08-21

### Fixed

- Recording could get permanently stuck after a storage outage, needing a manual node restart,
  because killing a process blocked on a dead network write could hang indefinitely. The kill
  wait is now bounded, letting the session move on to its normal reconnect/backoff cycle.

## [0.140.0] - 2026-08-21

### Added

- A node now retries transient storage I/O errors a few times before giving up, covering
  thumbnail backfill and playback partial-fetch reads that previously aborted or stalled on a
  brief storage blip.

## [0.139.0] - 2026-08-21

### Fixed

- Classified-detection snapshots regressed to wrong or empty thumbnails after 0.135.0 moved the
  sample point into the pre-roll buffer; classified detections are back to sampling just after
  the event start, while plain motion keeps the pre-roll-based sample point.

## [0.138.0] - 2026-08-21

### Added

- Playback can now jump straight to a scrub target inside a segment instead of downloading
  everything before it first, using a byte-offset index built from each segment's fragment
  headers.
- New admin-configurable recording segment length (default 60s, camera-overridable), which also
  bounds how far a scrub can ever need to skip.

## [0.137.1] - 2026-08-21

### Fixed

- Adaptive streaming (0.137.0) left switched tiles stuck reconnecting because a tile that
  switched to Sub still declared the Main stream's codec; a camera can record different codecs on
  Main and Sub. Each stream's codec is now sent separately and matched correctly.

## [0.137.0] - 2026-08-21

### Added

- Adaptive streaming: a live tile too small to benefit from a camera's full Main resolution is
  now shown its Sub stream instead, cutting bandwidth and decode cost. Nodes run an always-on Sub
  live session per camera; each tile picks Main or Sub based on its size, with a manual override
  and an automatic switch to Main in fullscreen.
- New admin toggle, Settings → Live View → "Adaptive streaming enabled" (default on).

## [0.136.0] - 2026-08-21

### Fixed

- The timeline could show gray instead of blue for genuinely recorded footage during continuous
  playback, because the playhead-follows-playback loop moved the visible window without ever
  requesting more bucket data once it scrolled past what was last fetched.

## [0.135.0] - 2026-08-21

### Changed

- Snapshot thumbnails now sample from the start of the pre-roll buffer for every span (not just
  classified detections), since the subject is typically already visible there rather than at the
  event's own start time.

## [0.134.0] - 2026-08-21

### Fixed

- Dragging the per-camera timeline triggered the browser's native drag-cancel cursor instead of
  panning, missing a `preventDefault()` fix already applied elsewhere.
- Playback could die mid-scrub with an append error and silently stop responding to Play; a
  listener now reloads the tile automatically when this happens.
- The per-camera Playback timeline could load showing only recorded coverage with no
  motion/event colors until a zoom triggered a redraw, due to a race between an early default
  reload and the real initial-position reload. A reload requested while one is in flight is now
  queued instead of dropped.

### Changed

- A Bookmark/Snapshot "Play" link now opens just that camera directly instead of searching for a
  saved View containing it.
- Live page gained a camera picker to view any single camera directly with no saved View needed.
- Snapshots and Audit Logs pagination no longer lists every page number; a windowed control shows
  first/last pages and a window around the current page.

## [0.133.0] - 2026-08-21

### Fixed

- Every camera's smart-event connection was reconnecting every few minutes regardless of health,
  because the assumed camera keep-alive doesn't actually get sent on this subscription; a real
  keep-alive event was added and the timeout backstop widened.

## [0.132.0] - 2026-08-21

### Fixed

- The Playback timeline's zoom level reset between page loads on two paths that didn't reapply
  the persisted zoom before rendering, and could overwrite the saved value with the default in
  the process.

## [0.131.0] - 2026-08-21

### Added

- Dahua/Amcrest detections now classify from the event's own object-type payload instead of just
  its event code, since one IVS code covers every configured object class. Falls back to the old
  code-based mapping when a payload carries no object detail.

**Install-node.ps1 re-run needed** on every recorder node for 0.142.5, 0.133.0 and 0.131.0 — the
NodeUpdater and Node binaries bumped in lockstep on those releases.
