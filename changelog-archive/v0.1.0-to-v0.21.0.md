# Changelog Archive: v0.1.0 – v0.21.0

Archived entries from [CHANGELOG.md](../CHANGELOG.md), oldest read at the top or bottom the
same as the main file — nothing reordered, just moved. Format is unchanged: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/) / [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.21.0] - 2026-08-09

### Fixed

- Playback tiles showed "Loading…" then went blank with nothing in the console, because a tile
  seeked to a raw offset assuming the recorded file's internal timeline started at zero, when it
  actually carried the timestamp it was written with. Seeks are now relative to the actual
  buffered start.
- Playback never auto-advanced to a camera's next segment, because the stream was never explicitly
  ended after appending a segment.
- Timeline drew recorded coverage in the future when sitting at "now", because the future-clamp
  capped the visible window's edge instead of the playhead itself.

### Changed

- Timeline now renders the stretch after "now" as unreachable future instead of looking like
  unrecorded time.
- Zooming a timeline no longer triggers a seek.

## [0.20.0] - 2026-08-09

### Fixed

- A Playback tile's status text had a blind spot while the segment lookup itself was in flight,
  looking identically blank whether it resolved quickly or never resolved. Now shows a "Looking
  for a recording…" status immediately, and a failed lookup now logs and shows an error instead of
  leaving the tile blank.

## [0.19.0] - 2026-08-09

### Fixed

- Chased a reported "timeline shows 12 hours in the future" through several dead ends before
  finding it was never a data bug — the default view is a 24-hour window centered on the playhead,
  so the right half is mathematically always future when the playhead starts at "now". Timelines
  now clamp so neither can scroll or zoom past the real current instant.

### Added

- Playback timelines now remember scrub position and zoom level between visits.
- A 24-hour clock toggle for both timelines.
- The two Playback timelines (per-camera and merged) now stay in sync on position and zoom.

## [0.17.0] - 2026-08-08

### Fixed

- Playback never loaded any video, root cause found: every timeline/segment range query was
  silently shifted by the server's UTC offset, because query-string date binding converts to the
  server's local zone before it reaches the database query. Every incoming range bound is now
  explicitly normalized to UTC before use.
- Console noise from aborted fetches during drag-scrubbing is gone, now handled inside the
  existing error guard instead of escaping as an unhandled rejection.

## [0.16.0] - 2026-08-08

### Fixed

- Found the real cause of Playback's "stuck on Loading…" symptom: the tape-scrubber redesign
  fired a scrub callback on every raw mouse-move event while dragging, flooding the browser's
  connection pool with abandoned requests across several cameras — not a slow storage read.
  Scrub firing is now throttled during a drag, and a superseded fetch is now actually cancelled
  instead of just having its stale result ignored.
- Playback tiles are now click-to-select-primary-camera on the whole cell, not just the small
  camera-name label.
- The playback-segment proxy now applies a 25s timeout instead of the 100s default, so a stuck
  storage read surfaces as a clear error instead of an indefinite spinner.

## [0.15.0] - 2026-08-08

### Fixed

- Playback's initial playhead defaulted to the current instant, which is almost never covered by
  an actual recording, so nothing ever loaded. Selecting a view now resolves the most recent
  actual recording and starts there instead.

### Changed

- Bootstrap and GridStack are now vendored locally instead of loaded from a CDN.
- Playback timeline redesigned as a tape scrubber: the playhead stays fixed at center and the
  strip slides underneath it, live-seeking every tile continuously while dragging.
- Playback tiles are now clickable to change which camera drives the per-camera timeline.

## [0.13.0] - 2026-08-08

### Fixed

- Playback's per-tile digital-zoom button group covered the entire video tile instead of sitting
  as a small corner overlay, the same Bootstrap ratio-box bug the Live page's mute button hit
  earlier.

### Changed

- Playback is now driven by saved Views instead of an ad-hoc camera picker, rendering the view's
  own saved cell layout with playback video.
- The Live page gained a view picker too, routing to the existing saved-view player instead of
  duplicating view-rendering logic.

### Added

- A second, merged timeline on Playback showing a bucket as recorded if any camera has footage
  there, useful for finding when something happened before knowing which camera caught it.

## [0.12.0] - 2026-08-08

### Added

- Playback & timeline: scrub a camera's recorded history and play it back, synchronized across
  multiple cameras. Each recorded segment file is fetched and appended to the browser's media
  source directly, trading a brief decode restart at each segment boundary for not needing any
  server-side stream rewriting.

### Known limitations

- Nothing in this pass has been exercised in a real browser yet.
- No hover thumbnails on the timeline.
- No frame-accurate synchronization across tiles during continuous playback.

## [0.11.0] - 2026-08-08

### Changed

- The Live page no longer shows an explainer paragraph that wasn't needed on every visit.

## [0.10.0] - 2026-08-08

### Added

- Recorder nodes now resume recording on their own after rebooting during a central-server/DB
  outage, using a cached copy of the last known-good camera config, instead of sitting idle until
  the server answers again.

### Known limitations

- Storage retention/quota cleanup doesn't get the same cache fallback yet.

## [0.9.0] - 2026-08-08

### Added

- Views & layout editor: save a camera-wall layout and open it later instead of rebuilding it
  every visit. Includes a drag-to-arrange editor, a read-only display page with a derived mobile
  layout, fullscreen kiosk mode, and a "start tour" feature cycling through shared views.

### Known limitations

- Adding a camera to the grid is click-to-add, not drag-and-drop.
- None of this milestone's UI has been visually confirmed in a real browser yet.
- Per-camera access control isn't wired into view visibility yet.

## [0.8.0] - 2026-08-08

### Added

- Dark mode toggle, defaulting to the system preference.
- Every table on Cameras and Admin/Nodes is now click-to-sort with a filter box, as a shared
  reusable pattern meant for every list page going forward.
- Quick enable/disable button on the Cameras list, without opening Edit.
- Bulk camera re-pointing: reassign multiple selected cameras to a different node in one action.
- Stale-segment warning badge, shown whenever a camera has recordings under a node it's no longer
  assigned to.

## [0.7.0] - 2026-08-08

### Added

- Live view now connects automatically for every camera as soon as the page loads, no manual
  "Watch" click needed.
- Live view auto-reconnects on its own after a dropped session, with backoff.
- Live view mute/unmute button on any camera whose stream has audio.
- `build-node.ps1` can mirror the built node package to a second location automatically.

### Fixed

- Live view confirmed working end-to-end in a real browser, both H.264 and HEVC, after five
  independent fixes found in sequence: a missing IIS WebSocket feature, no TLS cert for the
  node's own connection, wrong codec family selected before checking the camera's actual codec,
  the audio track undeclared in the browser's media source, and a late-joining viewer's playback
  position never landing inside the buffered range.
- A regression from the mute-button fix broke the video tile's aspect-ratio box entirely, from a
  Bootstrap utility class fighting the framework's own layout rule on the same element.
- Live view's mute/unmute button covered the entire video tile instead of sitting as a small
  corner overlay, the same Bootstrap ratio-box class issue.
- An append failure to the browser's media source was treated as non-fatal, causing every
  subsequent stream fragment to repeat the same error forever instead of ending the session.
- Live view returned a connection error for every camera on both nodes after the earlier signing
  upgrade, because a node that registered before that release had no signing key generated for
  it. The key is now backfilled automatically through the node's regular config poll instead of
  requiring re-registration.
- The node installer never opened a firewall rule for the live-view port, so WebSocket requests
  hung until timeout instead of failing fast.

## [0.6.0] - 2026-08-08

### Added

- Live view: watch a camera's live feed in the browser. Recording now tees the same ffmpeg
  session into both the segment recorder and a continuous live stream, instead of opening a
  second RTSP session. Nodes host a small LAN-only relay endpoint reachable only through the web
  tier's own proxy, authorized by a short-lived signed token — deliberately avoiding needing a
  TLS certificate on every node. Browser side is a vanilla-JS media-source player.

### Fixed

- The node's self-reported version included a build commit hash instead of just the version
  number.
- Two real bugs in the new tee'd ffmpeg command: a Windows path-escaping bug that corrupted drive
  letters, and a muxer flag name this ffmpeg build didn't accept, which aborted the entire tee.

### Known limitations

- Codec-support detection and hardware-transcode fallback are not implemented yet.
- A node that registered before this release has no signing key and returns an error for live
  view until re-registered.

## [0.5.0] - 2026-08-08

### Added

- Admin → Nodes shows each node's real IP address, captured server-side rather than self-reported.
- Real stream resolution/codec is now read from ffmpeg's own output, since ONVIF's advertised
  values are unreliable and were blank for some cameras.
- Per-stream enable/disable and a display-name override on the camera edit page.

### Changed

- The node installer's upgrade path no longer deletes and recreates the Windows Service, updating
  it in place instead.

### Fixed

- The node installer's service-stop step only waited for the node's own process to exit, leaving
  orphaned ffmpeg child processes that blocked a later upgrade from replacing files still in use.
- Nodes kept reporting a stale version in Admin → Nodes no matter how many times they were
  upgraded, from two compounding bugs: the heartbeat endpoint never actually read the reported
  version, and the node's own reported version was a hand-maintained literal instead of read from
  the build.
- A new migration would have defaulted every existing stream's enabled flag to false, which
  combined with a new filter would have silently stopped recording on every camera already in
  production. Caught before deploying and fixed to explicitly backfill true.

## [0.4.0] - 2026-08-08

### Added

- Storage manager: every node now enforces age-based retention, per-camera storage quotas, and a
  global watermark backstop that evicts the oldest segments once disk usage crosses a threshold,
  regardless of retention settings.
- Retention now resolves through a Camera → Node → Global override chain instead of a single
  global default.
- Nodes self-report free/total storage on every heartbeat; Admin → Nodes shows a usage bar and an
  estimated days of retention remaining.
- New Admin → Retention page for global retention/watermark defaults, plus per-node and
  per-camera override fields.

### Fixed

- The node's self-reported version had been hardcoded and drifted two releases behind the actual
  build.

### Changed

- Recording segments now write into nested date/hour folders instead of one flat directory, since
  a flat directory at realistic retention windows made every directory listing measurably slower.

## [0.3.1] - 2026-08-08

### Added

- Node management: edit a node's name and per-node storage root override, and delete a node
  outright (unassigning, not deleting, its cameras).
- `build-node.ps1` / `install-node.ps1`, replacing the earlier stub — publishes the recorder node
  as a self-contained Windows executable and installs it as a Windows Service.

### Fixed

- The installer's automatic ffmpeg bootstrap via winget went through several failure modes on
  real recorder machines; dropped the module layer entirely in favor of locating winget.exe
  directly.
- The resolved ffmpeg install location wasn't always accessible to the service account the node
  runs as; ffmpeg is now always copied into the node's own install directory before the service
  is registered.

## [0.3.0] - 2026-08-08

### Added

- 24/7 recording engine: a recorder node is a separate Windows Service process supervising one
  ffmpeg process per camera's Main stream, writing rolling segments with a stalled-stream
  watchdog that restarts a process that's alive but has stopped producing output.
- Node control plane: register/heartbeat/config/segment-report endpoints with bearer-token
  authentication.
- Admin → Nodes page and a camera-to-node assignment dropdown.

### Fixed

- An ONVIF camera's RTSP session commonly carries a metadata track the MP4 muxer can't handle,
  which aborted the entire recording; now maps only video and audio explicitly.
- A camera whose recording briefly failed to start left behind a 0-byte segment file that was
  being reported as a real segment; these are now skipped.
- Every ffmpeg restart re-created the in-memory de-duplication tracking from scratch, causing
  massive duplicate segment reports during a crash loop; segments now also have a unique
  constraint as a backstop.
- A single camera with an undecryptable stored credential crashed the entire Cameras list,
  because listing decrypted every row's credentials as a side effect even though the page never
  displays them.
- ONVIF calls to a camera's HTTPS device service failed outright, because certificate validation
  was applied to LAN cameras' self-signed certificates; disabled specifically for ONVIF calls.
- A camera's ONVIF port defaulted to 80 even for an HTTPS URI whose real default is 443.

## [0.2.0] - 2026-08-08

### Added

- Hand-rolled ONVIF SOAP client, since the WSDL-generated approach the original plan called for
  proved unworkable against ONVIF's schema.
- WS-Security digest authentication for ONVIF calls.
- WS-Discovery LAN auto-scan for finding cameras automatically.
- ONVIF Profile S/T/G/M capability probing, inferred from advertised services.
- Main/Sub/Third stream ranking that prefers stream naming over resolution, since some cameras
  report incomplete detail for their higher-quality profile.
- Camera entities and management pages: discovery, manual add/edit, listing, and group tree.

### Fixed

- SOAP response parsing only matched the SOAP 1.1 envelope namespace, but real camera firmware
  replies with SOAP 1.2 regardless of the request version; now matches by element name instead of
  namespace.

## [0.1.0] - 2026-08-08

### Added

- Solution skeleton with the project layering the plan called for.
- ASP.NET Core Identity with resource×action-based role permissions.
- Per-camera access control model, defined ahead of the Camera entity itself.
- Global settings with per-camera/group override resolution.
- Encryption at rest for stored secrets.
- UTC timestamp handling across the database layer.
- App version table and footer, so a half-applied deploy is visible on every page.
- Setup wizard covering database, admin account, storage, node, and branding.
- Security headers and a health-check endpoint.
- `deploy.ps1`, an IIS deploy script with a guard against ever mirroring over the recordings
  storage root.
