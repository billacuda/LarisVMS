# Changelog Archive: v0.111.0 – v0.130.0

Archived entries from [CHANGELOG.md](../CHANGELOG.md), oldest read at the top or bottom the
same as the main file — nothing reordered, just moved. Format is unchanged: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/) / [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.130.0] - 2026-08-21

### 🛠️ Fixed

- Snapshots and Audit Logs date filters were off by the UTC offset, cutting off the last hours of
  the selected day, because the picked date was treated as already-UTC instead of converted from
  local time.
- A Bookmark/Snapshot "Play" link could land at the start of the containing minute instead of the
  bookmarked instant, because the seek fired before the target time was actually buffered.

## [0.129.0] - 2026-08-21

### 🛠️ Fixed

- A vendor integration kept talking to a camera's old address after the address changed (e.g.
  HTTPS toggled off), because reconciliation compared only the integration key, not the URI.

### ➕ Added

- "Restart" button per node on Admin → Nodes, restarting just that node's Windows Service via a
  new restart-only mode on the NodeUpdater.

### ⚙️ Changed

- The Delete-node confirmation now fires on form submit instead of on any click inside the form.

## [0.128.0] - 2026-08-21

### ⚙️ Changed

- Object-detection snapshots now sample 1s after the event starts instead of at the span's
  midpoint, since span length is dominated by camera cooldown rather than how long the subject
  was in frame. Plain motion and custom-tag spans keep the midpoint.
- List pages now remember filter text and sort column, matching the page size/column memory they
  already had.

### ➕ Added

- Snapshots and Audit Logs now remember their filter selections across navigation and refresh.

## [0.127.0] - 2026-08-20

### ⚙️ Changed

- Navbar links are no longer dimmed; they read as full-brightness with a distinct hover color
  instead of Bootstrap's default muted style.

## [0.126.0] - 2026-08-20

### 🛠️ Fixed

- Landscape phones stacked every camera on top of each other, because the derived layout reused a
  portrait-oriented column setting. Landscape now derives its own column count from viewport
  height.

### ⚙️ Changed

- Snapshot thumbnails raised from 480 to 720 vertical resolution, with less aggressive JPEG
  compression at that size.

## [0.125.0] - 2026-08-20

### 🛠️ Fixed

- Landscape phones still squished some cameras, because the derived phone stack sized cells from
  a default 16:9 aspect ratio instead of each camera's real resolution. Now sizes from the probed
  resolution, and the view editor defaults new cells to the camera's own ratio.

## [0.124.0] - 2026-08-20

### 🛠️ Fixed

- A Bookmark/Snapshot "Play" deep link landed paused instead of playing immediately.

### ⚙️ Changed

- Snapshot card thumbnails are noticeably higher resolution — Snapshots' own cards now request a
  larger size than the shared hover-preview path uses.

## [0.123.0] - 2026-08-20

### 🛠️ Fixed

- Snapshots' "Play" links went nowhere, because they were built with a tag-helper form that
  resolved incorrectly; switched to the same plain-string link form Bookmarks already used
  successfully.

## [0.122.0] - 2026-08-20

### 🛠️ Fixed

- Snapshots pagination silently never advanced past page 1, because a handler parameter named
  `page` collided with a route value ASP.NET Core sets internally under the same name. Renamed to
  `pageNumber`.

## [0.121.0] - 2026-08-20

### 🛠️ Fixed

- Either Playback timeline could get stuck mid-drag unpredictably, when pointer capture silently
  failed to take; added a window-level fallback that always sees the release.
- A new bookmark didn't appear on the timeline until something unrelated triggered a reload; it
  now reloads immediately after a successful save.

### ➕ Added

- Snapshot cards now show the event's duration alongside its timestamp.

## [0.120.0] - 2026-08-20

### 🛠️ Fixed

- Playback still flashed a black cell at every segment boundary even with prefetching in place,
  because swapping the video element blanks it immediately regardless of how fast the next
  segment loads. Each tile now overlays its last frame until the new segment actually produces
  one.

### ➕ Added

- Play/Pause is now available while a Playback tile is fullscreen.

## [0.119.0] - 2026-08-20

### 🛠️ Fixed

- Every hover-thumbnail request started failing, because a new required parameter had no default
  and most callers didn't send it.
- Exact-instant Snapshots thumbnails routinely failed with 502 due to drift between a segment's
  recorded duration and its real encoded length; the proxy now retries once at a safe offset.
- A "Loading…" flash still showed on segment transitions that were already prefetched.
- The timeline's cursor could get stuck reading "grabbing" after a two-finger pinch cancelled a
  drag.
- Snapshots pagination could show a duplicate or skip a row between pages, from ties on the sort
  key; added a deterministic secondary sort.

### ➕ Added

- Per-visit event-type filter on the Snapshots page, on top of the existing admin-level setting.

## [0.118.0] - 2026-08-20

### 🛠️ Fixed

- Snapshots thumbnails were cropped and often missing; switched to a non-cropping fit and added
  an exact-instant thumbnail lookup instead of the coarser bucketed one used for hover previews.
- A Bookmark/Snapshot "Play" link could land at the covering segment's start instead of the
  bookmarked instant, from a race between two competing seeks.
- Faster-than-1x playback stalled with "Loading…" at every segment boundary; segments now
  prefetch one ahead in the background.
- Landscape phones lost their column stack, falling back to the desktop layout's column count;
  restored a scrollable landscape-specific stack.
- Fullscreen controls could sit unclickable underneath the fullscreen timeline on phones; the
  timeline now reserves space for them.

### ➕ Added

- Admin-configurable event-type visibility for the Snapshots browser.
- Snapshots now sample the midpoint of the event instead of its start.
- Bookmarks now render as markers on Playback's per-camera timeline.
- Refreshing Playback now restores the last-open View, not just scrub position and zoom.
- Pinch-to-zoom on both Playback timelines, for phone/tablet.

## [0.117.0] - 2026-08-19

### ➕ Added

- Snapshots browser: a new page listing every motion event — zone-triggered, camera-pushed,
  custom tags, and object detections — as a paged, filterable grid of thumbnails pulled live from
  the existing playback-thumbnail path. No new table or capture pipeline.

## [0.116.0] - 2026-08-19

### ➕ Added

- Bookmarks: mark a moment during Playback and jump straight back to it later. New Bookmark
  entity, a Bookmark button in Playback's toolbar, a Bookmarks list page with a deep link back
  into Playback, and a retention sweep that expires a bookmark once its footage ages out.

## [0.115.0] - 2026-08-19

### ➕ Added

- Basic PTZ: a directional pad and zoom control on each PTZ-capable camera's Live tile, using
  ONVIF PTZ called directly from the Web tier. Gated by a per-camera permission that existed in
  schema since M14 but was unenforced until now. Not yet verified against real PTZ hardware.

## [0.114.0] - 2026-08-19

### 🛠️ Fixed

- Fast-forward speed (8x) quietly reset to 1x after a few seconds, because every segment
  transition resets the video element's playback rate and nothing re-applied it. Now re-applied
  on every segment load.
- 16x and 32x dropped the video and got stuck on "Loading…", because the fast-forward loop fired
  a new seek on a fixed timer regardless of whether the previous one had finished, pre-empting
  itself forever. It now awaits each step before scheduling the next.

## [0.113.0] - 2026-08-19

### ⚙️ Changed

- Privacy-mask burn-in is switched off and deferred. The previous release's fix addressed one
  real bug but didn't resolve the reported symptom — a camera with a Privacy zone still gets
  stuck reconnecting — and the actual cause is still unknown. A Privacy zone is a safe no-op
  again until this is revisited.

**install-node.ps1 re-run: not needed** — ordinary node auto-update covers it.

## [0.112.0] - 2026-08-19

### 🛠️ Fixed

- Removed one confirmed bug in privacy-mask burn-in (pairing hardware decode with a CPU-only
  filter, which failed immediately). This did not resolve the reported symptom — a camera with a
  Privacy zone still gets stuck reconnecting with no footage. Root cause still unknown; privacy-
  mask burn-in remains deferred. Do not enable a Privacy zone on a production camera.

**install-node.ps1 re-run: not needed** — ordinary node auto-update covers it.

## [0.111.0] - 2026-08-19

### ➕ Added

- Static privacy-mask burn-in: a camera's enabled Privacy zones now burn in as black boxes over
  recordings and live feed, masking each zone's bounding box. Recording switches from stream copy
  to a real decode/filter/encode only for cameras with an enabled zone, preferring hardware
  encoding with a software fallback. Also fixes a latent hang in session cancellation found while
  building the per-camera restart this required. Not yet verified against real hardware encoders.

**install-node.ps1 re-run: not needed** — ordinary node auto-update covers it.

**Install-node.ps1 re-run needed** on every recorder node for 0.129.0, 0.126.0, and 0.124.0 — the
NodeUpdater and Node binaries bumped in lockstep on those releases.
