# Changelog Archive: v0.81.1 – v0.90.0

Archived entries from [CHANGELOG.md](../CHANGELOG.md), oldest read at the top or bottom the
same as the main file — nothing reordered, just moved. Format is unchanged: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/) / [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.90.0] - 2026-08-17

### Fixed

- Every deploy deleted the entire application log history, because the deploy script's mirror
  step excluded other data directories but not `logs`. `logs` is now excluded too.

### Added

- Application log retention is now configurable (0 keeps logs forever), replacing a hardcoded 14
  days.
- View pickers now show each view's camera count on Live and Playback.

## [0.89.2] - 2026-08-17

### Fixed

- Playback squeezed its video grid to a sliver on a phone in landscape, for a different reason
  than the similar 0.89.1 fix on Views/Play — the toolbar and timeline chrome claimed nearly the
  whole column at short viewport heights. Non-essential text is now hidden and padding tightened
  on short viewports.

## [0.89.1] - 2026-08-17

### Fixed

- A phone held sideways squeezed every camera into a thin horizontal band, because row height
  stayed pinned to the editor's fixed value while column width tracked the viewport. A short
  viewport now scales row height so the view fits the window.
- Hovering a View cell's mini-timeline showed no preview thumbnail, because the option that
  switches on hover-preview behavior was never passed for that timeline.

## [0.89.0] - 2026-08-16

### Added

- A volume slider on every tile that has audio, live and playback alike, alongside the existing
  mute button. Tiles still always start muted.
- Audio codec and sample rate now shown on the health dashboard, read from ffmpeg's stream
  summary on the node.

### Fixed

- Unmuting a live View cell was silently undone on the next reconnect, because the tile's mute
  state wasn't reapplied when its video element reloaded. Both live and playback tiles now share
  one implementation that reapplies mute/volume on every load.

**LarisVMS.Node change — `install-node.ps1` re-run needed on every recorder** (audio stream
summary parsing moved to the node).

## [0.88.1] - 2026-08-16

### Changed

- The recorder's live fan-out no longer allocates when nobody is watching. ffmpeg's stdout is now
  read through pooled pipe buffers instead of copying into a new array per read, cutting CPU and
  allocation substantially with no live viewer and modestly with one.
- Box-type parsing in the fragment scanner no longer allocates a string per box.

**Node change — `install-node.ps1` re-run needed on every recorder.**

## [0.88.0] - 2026-08-16

### Added

- Event colors are now admin-configurable (Admin → Event Colors) for motion, recorded coverage,
  and each detected object class.
- Three more object classes wired through both ONVIF and the Dahua/Amcrest integration: Animal,
  Object appeared, and Object missing. No camera tested so far is known to emit them yet.
- Several object classes detected at once are now all shown, instead of the badge strip
  overflowing or the timeline dropping all but the first.
- Detection badge text now picks black or white by the badge's own color, since badge colors
  became admin-configurable.

### Changed

- Dahua's left/taken-away events now map to Object appeared / Object missing instead of both
  collapsing into a generic Object class.
- Plain (unclassified) motion is now marked with a distinct swirl icon on live tiles.

## [0.87.5] - 2026-08-16

### Fixed

- Live tiles failed to decode right after a reconnect, because the node fanned out raw chunks of
  ffmpeg's pipe instead of complete fragments, so a joining viewer could receive a truncated box.
  Viewers are now fed whole fragments. **Node change — `install-node.ps1` re-run needed on every
  recorder.**
- Live-view sessions leaked their video-element event listeners on every reconnect, causing
  repeated duplicate error logging that obscured the real fault over a long-open page.

### Changed

- Several navbar/toolbar icon changes for clarity (vendor-integration marker, Playback, Exports).

## [0.87.4] - 2026-08-16

### Changed

- The "Other" detection class now shows a box icon instead of a magnifying glass on live-tile
  badges. Display only, no node change.

## [0.87.3] - 2026-08-16

### Fixed

- A dropped smart-event connection could leave a detection span open forever, since a stop event
  sent while the feed was down never arrives. Open spans are now closed at the point the feed
  died instead of extending indefinitely. **Node change — `install-node.ps1` re-run needed on
  every recorder.**

## [0.87.2] - 2026-08-16

### Added

- `probe-dahua-events.ps1 -UsePluginCodes`, subscribing with the plugin's actual filtered code
  list instead of requesting everything, to catch firmware that mishandles a narrow filter.

## [0.87.1] - 2026-08-16

### Fixed

- `probe-dahua-events.ps1` couldn't run at all, because its `-Host` parameter collided with a
  reserved PowerShell variable name. Renamed to `-CameraHost`. Script only, no application
  change.

## [0.87.0] - 2026-08-16

### Added

- Camera integration plugins: an extensibility point for vendor-specific behavior ONVIF can't
  express. Providers are compiled in and matched automatically from a camera's reported make and
  model.
- First provider: Dahua/Amcrest smart events, reading person/vehicle detections from the camera's
  onboard Smart Motion Detection over its CGI event API — these cameras publish nothing
  object-shaped over ONVIF, so this is what makes the 0.85.0 detection feature actually work on
  this camera family.

### Known limitations

- Vendor event codes are unverified against real hardware; an unrecognized code is ignored
  safely.

**LarisVMS.Node change — `install-node.ps1` re-run needed on every recorder.**

## [0.86.1] - 2026-08-16

### Fixed

- `probe-metadata-track.ps1` reported a false positive for bounding-box feasibility, matching on
  elements present in any ONVIF metadata stream rather than ones that actually carry object
  geometry.

### Research

- Bounding-box spike result: not achievable on the cameras tested. Their metadata track carries
  only a motion-cell grid, not object geometry — a hardware limitation, not a plumbing gap.

## [0.86.0] - 2026-08-16

### Fixed

- The Playback page's timelines disappeared while a tile was fullscreened, since they're
  page-level elements outside what the Fullscreen API renders. The timeline element is now moved
  into the tile while fullscreen is active and moved back on exit.

### Added

- `probe-metadata-track.ps1`, a read-only research script checking whether a camera exposes an
  ONVIF metadata track ffmpeg can demux, ahead of any bounding-box design work.

## [0.85.0] - 2026-08-16

### Added

- Object-detection events: cameras whose onboard analytics classify what they see (person /
  vehicle / face) now surface a labelled badge on the live tile and a distinctly colored span on
  the Playback timeline, instead of only generic motion. Runs on the existing ONVIF PullPoint
  channel with no new wire format.

### Changed

- A detection now counts toward Motion-mode recording, as one more OR term alongside existing
  motion triggers — it can only keep a segment that would otherwise be discarded, never discard
  one that would have been kept.

### Known limitations

- These are not bounding boxes — ONVIF's rule-engine topics report that an object class was seen,
  not where it was in frame. Unverified against a camera that actually emits these topics.

**LarisVMS.Node change — `install-node.ps1` re-run needed on every recorder.**

## [0.84.0] - 2026-08-16

### Added

- Branding page (Admin → Branding): application name, primary/navbar color, logo, and font,
  applied across every page including sign-in. Anything left blank falls back to the built-in
  default.
- Emoji added to main action buttons, matching the existing navbar convention.

### Changed

- Branding moved from the one-time Setup wizard into ordinary editable settings.

### Security

- Branding values are allowlist-validated before storage, since they're interpolated directly
  into page styles and image tags — colors must be hex literals, fonts chosen from a fixed table,
  and a logo must be a data URI that actually decodes as an image (SVG rejected, since it can
  carry script).

## [0.83.0] - 2026-08-16

### Added

- Multi-sensor camera support: a quad-lens (or other multi-sensor) device can now be split into
  one independent camera per lens, each recordable and placeable in a view on its own.

### Fixed

- On a multi-lens device, a camera could end up recording the wrong lens, because profile
  selection didn't account for which sensor a profile belonged to. A camera pinned to a channel
  now only considers that channel's own profiles.

## [0.82.0] - 2026-08-16

### Added

- Comprehensive audit logging: new entries for every live stream opened, every view/playback
  session watched (naming every camera involved), every export download, and node-build
  approve/reject actions — several of these had no audit coverage at all before.

### Changed

- Change entries now record what actually changed as old → new values, instead of only that a
  save happened, for global settings, camera edits, node edits, and backup settings. Secrets are
  never written to the log — only that they changed.

## [0.81.2] - 2026-08-16

### Fixed

- A View cell in playback mode lost its mini-timeline when fullscreened and didn't get it back
  after exiting, from a CSS rule that no longer applied correctly plus a canvas that was measured
  at zero size while hidden and never re-measured. Timelines now self-heal on any size change via
  a ResizeObserver.

## [0.81.1] - 2026-08-15

### Fixed

- The hard-resync fallback added in 0.81.0 made the stutter/reconnect loop worse instead of fixing
  it, seeking backward into a position that was still far behind and re-triggering forever. A
  session that far behind now just ends and lets the existing retry path build a fresh session at
  the live edge, rather than attempting another seek-based correction.
- Leaked live-view drift timers could seek a video element that had since been reassigned to
  playback mode, causing several different playback positions to interleave on what should have
  been a single tile.
- A View cell's playback mini-timeline was cut off at the bottom and showed no coverage colors,
  from being too short and never wired to the coverage data source.
