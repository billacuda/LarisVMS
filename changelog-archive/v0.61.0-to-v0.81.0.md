# Changelog Archive: v0.61.0 – v0.81.0

Archived entries from [CHANGELOG.md](../CHANGELOG.md), oldest read at the top or bottom the
same as the main file — nothing reordered, just moved. Format is unchanged: [Keep a
Changelog](https://keepachangelog.com/en/1.1.0/) / [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.81.0] - 2026-08-15

### 🛠️ Fixed

- Live tiles could repeatedly stutter and reconnect, because 0.78.0's drift-correction seek could
  land off a keyframe when drift grew unusually large (e.g. from a backgrounded/throttled tab) and
  throw a real decode error. Catch-up now speeds up playback instead of seeking, falling back to a
  hard seek only when drift is too large for that to close in reasonable time.
- A View cell's playback-mode mini-timeline never actually painted anything, since its draw call
  was only triggered by a code path the mini-timeline doesn't use.

## [0.80.0] - 2026-08-15

### ⚙️ Changed

- Saved Views are now the only live-viewing surface — the flat all-cameras Live grid is gone.
  Create a View containing every camera to get the old layout.
- The per-tile playback toggle (scrub the last few minutes of a live tile without leaving the
  grid) moved to View cells, where it previously didn't exist at all.

### ➕ Added

- Dashboard now auto-refreshes every 60 seconds instead of needing a manual reload.
- Optional per-camera thumbnail column on the Dashboard, off by default.
- Every dashboard column is now sortable, with pagination added; sort/page state survives each
  refresh.

## [0.78.0] - 2026-08-15

### 🛠️ Fixed

- Regression from 0.76.0's live-tile drift resync: a lagging tile would repeat a few seconds of
  already-played video every couple of minutes, and cameras in the same grid could drift apart,
  because the periodic check reused a recovery function that targets the start of the newest
  buffered range rather than nudging toward the true live edge. Fixed to converge without a hard
  rewind.

## [0.77.0] - 2026-08-15

### 🛠️ Fixed

- Dashboard per-camera fps/bitrate/last-report/reconnect-count stayed blank forever, because this
  app's tee-based ffmpeg pipeline never reports a real bitrate on its progress line, and the
  parser required one for the whole line to match — silently dropping fps too. Fps now parses
  independently; bitrate is derived from each completed segment's actual size and duration
  instead. **Node change — install-node.ps1 re-run needed on every recorder.**

## [0.76.0] - 2026-08-15

### ⚙️ Changed

- Live now opens the saved view you watched last instead of always showing the flat all-cameras
  grid, falling back to the first view or a "create one" prompt.
- Navbar links carry emoji icons, matching the app's existing emoji-as-icon convention.
- Accessibility labels added on icon-only controls across the Live grid, view cells, and editor.
- Toggling a Live tile into playback now starts 30 seconds back instead of at the start of the
  camera's most recent segment, which could be minutes stale.

### 🛠️ Fixed

- Changing a view cell's aspect ratio never resized the cell, because the dropdown wasn't wired
  for the `change` event.
- Motion badges never appeared on a saved view's cells, only on the flat Live grid, since
  Views/Play never built the badge element or started the poll.
- The export camera picker only offered the cameras in the currently selected view instead of
  every camera.
- An intermittent stuck drag could hijack later mouse gestures, most visibly breaking timeline
  scrubbing after zooming or fullscreening a tile, because a `mouseup` released outside the window
  never reached the drag handler. Switched to pointer capture with cancel handling.
- A Live tile that fell behind its own live edge was never pulled forward again outside of a
  stall; each tile now checks periodically and re-seeks to its own live edge when too far behind.

## [0.75.0] - 2026-08-14

### 🛠️ Fixed

- Exporting a range that spans a camera reassignment always failed on its first dispatch attempt,
  because the per-node split added in 0.68.0 didn't actually narrow each split item's segment
  query to its own node. Pinned items now filter to their own node before dispatching.

## [0.74.0] - 2026-08-14

### ➕ Added

- Health dashboard: per-camera real-time fps, bitrate, and cumulative reconnect count, plus each
  node's online/offline status and summary counts.
- Real-time stream health reporting, parsed from ffmpeg's own progress line and reported every
  ~15s per active camera. **Node change — install-node.ps1 re-run needed on every recorder.**

## [0.73.0] - 2026-08-14

### ➕ Added

- Application log capture on both tiers, writing daily-rolling files to disk since neither IIS
  in-process hosting nor a Windows Service has a visible console.
- System Logs viewer (Admin > System Logs), tailing the Web tier's own log file with a date picker
  and text filter.

**LarisVMS.Node change — install-node.ps1 re-run needed on every recorder.**

## [0.72.0] - 2026-08-14

### ➕ Added

- Database backups (Admin > Backups): scheduled daily or on-demand, with retention-by-count
  cleanup and history. Built for SQL Express installs with no SQL Agent of their own. Restoring is
  deliberately not part of this page.

## [0.71.0] - 2026-08-14

### 🛠️ Fixed

- Several admin pages displayed raw UTC timestamps as if they were local time with no indicator,
  since formatting never converted timezone regardless of the underlying value being UTC. Seven
  pages now convert to the server's local time before display.

### ➕ Added

- Recorder nodes now report their own clock skew each heartbeat; Admin > Nodes shows a warning
  badge when a node's clock disagrees with the server's by more than 60 seconds.

**LarisVMS.Node change — install-node.ps1 re-run needed on every recorder** (older nodes keep
working; the skew measurement is simply skipped until updated).

## [0.70.0] - 2026-08-14

### ➕ Added

- Audit log viewer (Admin > Audit Log): filter by action/details, actor, and date range,
  paginated.
- New audit log entries for camera and node create/update/delete, global settings changes, and
  export creation — previously only login/logout were logged.

## [0.69.0] - 2026-08-14

### ⚙️ Changed

- Live view no longer blanks a tile to "Reconnecting…" text on a routine decode-error reconnect
  (typically from a slow client, e.g. WiFi roaming). Once a tile has shown a frame, a reconnect
  now freezes that last frame with a small spinner until the new session has one to show.

## [0.68.0] - 2026-08-14

### ➕ Added

- Exporting a range that spans a camera reassignment now produces multiple downloadable files
  instead of failing outright, split into one export per node actually involved.

## [0.67.0] - 2026-08-14

### ➕ Added

- Exports page now auto-refreshes while any job is queued or running.
- Trash button to delete a finished export.
- Retry button on a failed export item.

**LarisVMS.Node change — install-node.ps1 re-run needed on every recorder** (new route for the
trash button).

## [0.66.0] - 2026-08-14

### 🛠️ Fixed

- Exporting a camera whose footage range crossed a node reassignment failed with an opaque HTTP
  400, because the dispatcher sent every segment path to the camera's current node even though
  some segments still lived on the old node's disk. Now caught before dispatch with a specific,
  actionable error message.

## [0.65.0] - 2026-08-14

### 🛠️ Fixed

- Hover thumbnails were blocked by the app's own Content-Security-Policy regardless of earlier
  fixes, because `img-src` allowed `data:`/`https:` but not `blob:`, which is how thumbnails are
  actually loaded.

## [0.64.0] - 2026-08-14

### 🛠️ Fixed

- The previous release's broken-image backstop was itself a regression — nearly every hover
  started showing "No preview available" regardless of whether the fetch actually succeeded,
  because a superseded in-flight load's async error could fire after a newer successful one. Now
  gated on a token so a stale error can't override a current image.

## [0.63.0] - 2026-08-14

### 🛠️ Fixed

- Hover thumbnails could still render as a broken image, because the in-memory cache's eviction
  picked the first-inserted key as "oldest" without accounting for re-hits, so a frequently-viewed
  bucket could be evicted while still on screen. Cache hits now bump the entry to
  most-recently-used. Added a generic broken-image fallback as a backstop.

## [0.62.0] - 2026-08-14

### 🛠️ Fixed

- The "footage exists on another node" stale-segment warning could never clear on its own,
  because retention sweeps only walked cameras still assigned to that node — a reassigned or
  deleted camera's leftover segments became permanently invisible to cleanup. Now swept using the
  camera's own retention policy even after it moves away. **LarisVMS.Node change —
  install-node.ps1 re-run needed on every recorder.**

## [0.61.0] - 2026-08-14

### ➕ Added

- Concurrency limits and a low-priority background backfill service for hover thumbnails, since
  nothing previously capped how many ffmpeg extractions could run at once. On-demand requests are
  now capped and a background service fills in the cache gradually. Superseded hover requests now
  actually cancel their ffmpeg process on the node, not just the local fetch.

**LarisVMS.Node change — install-node.ps1 re-run needed on every recorder.**
