THIRD PARTY NOTICES
===================

This file covers the third-party components that came in with native AI object detection
(LarisVMS.Vision / LarisVMS.Vision.Service). LarisVMS is MIT licensed; this is not yet a complete
notice for every dependency the wider application uses (ASP.NET Core, EF Core, Bootstrap, GridStack,
etc. — each carries its own standard OSS license via NuGet/npm, not separately re-stated here).


RUNTIME DEPENDENCIES
--------------------

YoloDotNet 4.2.0
    MIT
    https://github.com/NickSwardh/YoloDotNet
    Copyright (c) Niklas Swärd

    NOTE: the NuGet package declares MIT, and 96 of its 100 source files carry
    an SPDX MIT header. Four files are marked GPL-3.0-or-later:
        YoloDotNet/Video/FrameRate.cs
        YoloDotNet/Video/VideoOptions.cs
        YoloDotNet/Video/Services/Processor.cs
        YoloDotNet/Video/Services/FrameSaveService.cs
    All four belong to the library's built-in video pipeline, which LarisVMS.Vision does not use —
    Capture/VisionSession.cs replaces it entirely, the same way aitest's own FrameReader did (this
    project's own capture pipeline was ported from that reference implementation — see below). The
    package-level MIT declaration is what is relied upon here. This inconsistency has been noted
    upstream.

    STILL A RUNTIME DEPENDENCY, EVEN THOUGH ITS OWN DECODERS AREN'T USED ANY MORE: the D-FINE and
    YOLOX engines run Microsoft.ML.OnnxRuntime directly and no longer touch YoloDotNet's
    model-specific decoding or its execution-provider wrappers. This package remains referenced for
    (1) its ObjectDetection/LabelModel/IDetection types, which the decoders construct directly so
    ByteTracker/MovementClassifier/CameraDetectionPipeline never needed to change, and (2) its public
    LAPJV.Solve, which the ByteTrack port below calls directly.

Microsoft.ML.OnnxRuntime + Microsoft.ML.OnnxRuntime.Gpu.Windows + Microsoft.ML.OnnxRuntime.DirectML
    MIT
    https://github.com/microsoft/onnxruntime
    Copyright (c) Microsoft Corporation
    LarisVMS.Vision references the managed assembly and the CPU native; LarisVMS.Vision.Service also
    stages the CUDA(+TensorRT) and DirectML native builds into onnxruntime-backends/<name>/ so one
    node package runs on any hardware (VisionBackendResolver picks one at runtime). The ~320 MB
    onnxruntime_providers_cuda.dll is not shipped in the node package — deploy.ps1 seeds it onto the
    LarisVMS server and an NVIDIA node downloads it from there once. Used directly from
    Inference/OrtSessionFactory.cs, DFineEngine.cs, YoloXEngine.cs.

Microsoft.AI.DirectML
    MIT
    https://github.com/microsoft/DirectML
    Copyright (c) Microsoft Corporation
    Provides DirectML.dll, staged alongside the DirectML ONNX Runtime build.

SkiaSharp
    MIT
    https://github.com/mono/SkiaSharp
    Copyright (c) Microsoft Corporation
    Pulled in transitively by YoloDotNet; used directly in LarisVMS.Vision for detection box geometry
    and, since the D-FINE integration, for DFineEngine's own frame preprocessing (resize/pixel pack).

MODEL WEIGHTS
-------------

Not distributed in this repository; downloaded by tools/export-models/fetch_dfine.py. Licenses are
carried alongside each fetched model in models/ (gitignored — see fetch_dfine.py's own
write_license).

D-FINE (small — obj2coco and obj365 variants; medium — obj2coco variant)
    Apache-2.0 — https://github.com/Peterande/D-FINE (Yansong Peng et al.)
    ONNX weights redistributed via onnx-community on Hugging Face
    (onnx-community/dfine_s_obj2coco-ONNX, onnx-community/dfine_s_obj365-ONNX,
    onnx-community/dfine_m_obj2coco-ONNX), themselves derived from ustc-community/dfine-small-obj2coco,
    ustc-community/dfine-small-obj365 and ustc-community/dfine-medium-obj2coco — all Apache-2.0, same
    upstream project. Replaced YOLOv9/LibreYOLO (see git history) as the default
    detection model: license-clean (Apache-2.0 end to end, unlike YOLOv9's non-permissive weight
    lineage) and DETR-style (no per-frame NMS, and — per user-reported CPU/GPU utilization —
    noticeably lighter on the CPU than YoloDotNet's own YOLO-family decode+NMS path).

    Objects365 dataset note (obj365 variant only): the Objects365 annotations are CC BY 4.0, but
    the underlying source images are distributed under the Flickr Terms of Use and are NOT
    redistributable. This project ships only the derived D-FINE model weights (a trained neural
    network, not the training images or annotations themselves) — no Objects365 image or
    annotation data is included anywhere in this repository or its release artifacts.
    See https://www.objects365.org/download.html.

    RF-DETR and YOLOX are reserved model-family options (DetectionModelFamily enum, rendered
    disabled in the admin picker) with no weights fetched or shipped yet — see the model-swap
    plan's deferred scope for why.
